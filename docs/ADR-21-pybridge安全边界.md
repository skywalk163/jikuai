# ADR-21 · pybridge 安全边界（v0.5.0 · M4）

- 状态：Accepted
- 日期：2026-08-08
- 决策者：架构师（承接交付总监安全审计要求）
- 落地环节：v0.5.0 · M4 · 文档级 ADR（不含代码沙箱实现）
- 相关：ADR-14（诊断内核，`JK-E6001`/`JK-W6001`）、基线校正说明-v0.5.0

---

## 1. 背景

极快通过 `蟒:` 前缀提供 Python 互操作桥接（pybridge）。当前安全机制为黑名单（`pybridge.DENY_LIST`），拦截以下已知危险调用：

- `os.system`
- `subprocess.Popen`
- `builtins.eval`
- `builtins.exec`

**已知不足**：`importlib` 等间接路径可绕过黑名单；`ctypes`、`code.interact`、`os.popen` 等未列入；动态属性访问（`getattr`）可构造绕过链。黑名单机制本质上无法穷举所有危险路径。

引用 Summary 裁决 D-01：本周期不实现代码沙箱，仅做文档级安全声明。

---

## 2. 决议

### 2.1 安全定位声明

**pybridge 不提供完整沙箱隔离，仅基于黑名单做安全缓解。**

pybridge 的安全模型是「可信代码 + 最佳努力拦截」，不是「不可信代码 + 强隔离」。

### 2.2 适用场景

- 运行你自己编写的 Python 代码
- 运行来源可信的第三方 Python 库（如 PyPI 上的知名库）
- 教学与原型验证场景
- 团队内部工具链中 `.jk` 调用内部 `.py` 模块

### 2.3 禁用场景

- **执行不受信任的第三方代码**
- **多租户环境**（不同用户的代码共享同一进程）
- **面向公网的代码执行服务**（如在线 playground 无额外隔离）
- **处理不可信输入可能触发代码执行的场景**

### 2.4 强隔离需求的建议方案

若必须承载不可信输入，须叠加以下措施：

- 进程级隔离（独立子进程 + seccomp/AppArmor）
- 容器级隔离（Docker/OCI 容器 + 资源限制）
- 虚拟机级隔离（用于最高安全要求场景）

pybridge 在上述方案中**不作为安全边界**，仅作为防误触的便利层。

### 2.5 黑名单维护策略

- `DENY_LIST` 以「已知高危 + 低误报」为准则维护
- 新增条目须经安全审计确认不会阻塞正常 stdlib 用法
- 命中黑名单时产出 `JK-E6001` 错误
- 首次加载外部 Python 模块时产出 `JK-W6001` 警告提示

## 3. 声明落点

本 ADR 的安全声明须在以下三处同步体现：

- **`docs/ADR-21-pybridge安全边界.md`**（本文件）：完整决议与分析
- **`src/jikuai/pybridge.py` 模块 docstring**：模块级文档字符串中声明安全定位与禁用场景（一段话）
- **`README.md` 安全声明段**：面向用户的简要安全提示，引导至本 ADR 获取详情

## 4. AOT 产物与调试器的信任前提

### AOT 产物

- AOT 编译产物（M6 规划）继承源码的信任等级
- AOT 不引入额外的安全边界或沙箱
- 编译后的产物与解释执行具有相同的权限范围

### 调试器

- 调试器（M6 规划）允许检视运行时状态，包括变量值与调用栈
- 调试器的使用前提是用户对被调试代码具有完全信任
- 不得在生产环境向非授权用户暴露调试端口

## 5. 验证方式

- **G7 安全审计**：逐条核对本 ADR 中声明的三处落点是否一致
- **文档要点核对**（非行为测试）：
  - `pybridge.py` docstring 包含「不提供完整沙箱隔离」关键表述
  - `README.md` 包含安全声明段并引用本 ADR
  - `DENY_LIST` 中至少包含 `os.system`/`subprocess.Popen`/`builtins.eval`/`builtins.exec`
- **`JK-E6001` 行为测试**：调用被拒绝的函数时产出包含 `JK-E6001` 的 `Diagnostic`
- **`JK-W6001` 行为测试**：首次加载外部模块时产出包含 `JK-W6001` 的 `Diagnostic`

## 6. 已知限制

- 黑名单无法防御所有绕过路径（`importlib`、`ctypes`、动态 `getattr` 链等）
- 本周期不实现进程隔离、seccomp profile 或容器化方案
- pybridge 的 `DENY_LIST` 检查发生在调用时（运行期），不能在静态分析阶段拦截
- 如用户通过 `蟒:importlib` 动态加载模块后调用危险函数，黑名单不生效——这是已知的设计局限，非 bug
- 未来若引入 LSP 代码动作（code action），可考虑在编辑器端提示安全风险，但不阻断执行
