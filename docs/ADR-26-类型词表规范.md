# ADR-26 · 块类型词表规范（v0.14.0 W1）

- 状态：Accepted
- 日期：2026-08-10
- 决策者：项目维护者
- 落地环节：v0.14.0 M1（W1-W2 类型系统细化）
- 相关：ADR-15（块生态架构）、ADR-25（语义选块）

---

## 1. 背景

v0.13.0 及之前，`块.json` 的 `输入[].类型` 与 `输出.类型` 是**无约束自由文本**。
`_validate` 仅校验"是非空字符串"，实测出现 `数 / 字符串 / 布尔 / 列表 / 字典 /
字典或列表` 等写法。这导致：

1. 类型对齐粘合器（W3-W4 glue）无法做类型推断——自由文本没有可靠语义
2. 联合类型靠 `"字典或列表"` 手写，无结构化表达
3. CLI/Agent 无法验证块组合时的传参兼容性

## 2. 目标

为 `块.json` 的 `类型` 字段定义结构化词表，向后兼容旧格式，为 W3-W4 类型图
粘合器提供可靠基础。

## 3. 决议：类型词表

### 3.1 单类型（标量）

以下字符串为合法的标量类型值：

- `数` — 数值（整数或浮点）
- `字符串` — 文本
- `布尔` — 真/假
- `函数` — 回调/高阶函数参数
- `任意` — 不约束类型（通配）

### 3.2 同质容器

结构化对象表达：

```json
{"类型": "列表", "元素类型": "数"}
{"类型": "字典", "键类型": "字符串", "值类型": "任意"}
```

- `列表` 必须带 `元素类型`（标量类型字符串或嵌套容器）
- `字典` 必须带 `键类型` + `值类型`

### 3.3 异质元组

```json
{"类型": "元组", "元数": ["数", "数", "数", "字符串"]}
```

- `元组` 必须带 `元数`：非空数组，每项为合法类型值
- 用途：`批量统计` / `税单` 这类固定形状返回值

### 3.4 联合类型

```json
{"类型": "联合", "候选": ["字典", "列表"]}
```

- `联合` 必须带 `候选`：至少 2 项的数组，每项为合法类型值
- 裸字符串 `联合` **不合法**——无候选的联合等同 `任意`，应直接写 `任意`
- 用途：替代旧格式的自由文本联合写法 `"字典或列表"`（`记法解析` / `记法织串`）

### 3.5 子类型规则

- `列表<T>` <: `列表`（裸 `列表` 视为 `列表<任意>`）
- `元组[T1..Tn]` <: `列表`（长度已知的特化列表）
- `T` <: `任意`（任何类型都是 `任意` 的子类型）

### 3.6 向后兼容

- 旧格式裸字符串 `"列表"` / `"字典"` / `"元组"` 继续合法，视为 `列表<任意>` /
  `字典<字符串,任意>` / 长度未知元组
- `_validate` 对裸容器不报错（W2 G14 门禁才引入精度强制）
- 非法自由文本（如 `"字典或列表"`）不再合法：W1 已把 `记法解析` / `记法织串`
  两块改写为 §3.4 的 `联合` 形态

## 4. 实现

### 4.1 `_validate` 扩容

在 `blocks.py` 的 `_validate` 中增加 `_validate_type_annotation(value, context, path)` 辅助函数：

- 如果值是字符串 → 必须属于 `SCALAR_TYPES ∪ CONTAINER_TYPE_NAMES`
- 如果值是 dict → 按 `类型` 字段路由到对应容器校验
- 无 `类型` 字段的 dict → 报错
- 嵌套递归校验（`元素类型` / `值类型` / `元数` 的每项）

### 4.2 合法类型常量

```python
SCALAR_TYPES = frozenset({'数', '字符串', '布尔', '函数', '任意'})
CONTAINER_TYPE_NAMES = frozenset({'列表', '字典', '元组'})
UNION_TYPE_NAME = '联合'
```

### 4.3 校验策略

输入项的 `类型` 字段和输出的 `类型` 字段**都**过 `_validate_type_annotation`。

## 5. 影响

- `索引.json` 的 `输入`/`输出` 字段格式可能从纯字符串变为结构化对象
- G11 索引一致性门禁、G12 向量索引哈希都会因格式变化而需要重生成
- W2 回填后全量重生成索引

## 6. 决策记录

| 备选 | 理由 |
|-------|------|
| TypeScript 风格 `list<number>` | 中文项目，不引入英文语法 |
| 纯枚举字符串 | 无法表达容器元素类型 |
| 当前方案：字符串+结构化对象混合 | 简单标量用字符串省心，复杂容器用对象精确 |
