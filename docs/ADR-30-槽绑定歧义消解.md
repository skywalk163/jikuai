# ADR-30 · 槽绑定歧义消解（v0.17.0 W43）

- 状态：Accepted
- 日期：2026-08-11
- 决策者：项目维护者
- 落地环节：v0.17.0 M11 W43（ADR + 实现）
- 相关：ADR-26（类型词表）、ADR-28（L3 聚合块规范）

---

## 1. 问题定义（W42 归因数据支撑）

v0.16.0 W30 实测 L3 粘合率：**末步整体 0/3 = 0.0%、槽级 7/20 = 35.0%**。

W42 `bench_glue_l3.py` 对 3 个 L3 块（报销单/工资册/客户对账）的 20 个入参槽
逐一做 A/B/C/D 归因，结果：

| 类别 | 含义 | 槽数 | 占总 | 占失配 |
|------|------|------|------|--------|
| A | 同型不同义（类型图无从区分） | 14 | 70% | 100% |
| B | 上游无产出 | 0 | 0% | 0% |
| C | 类型词表标注不够细 | 0 | 0% | 0% |
| D | 粘合器实现缺陷 | 0 | 0% | 0% |
| (可填) | 类型图可正确填充 | 6 | 30% | — |

**结论**：问题 100% 是 A 类——同型不同义。典型表现：

- `报销单` 8 个入参中，年×2(单据年/生年)、月×2、日×2 —— 全是 `数`
- `工资册` 7 个入参中，年×2(生年/今年)、月×2、日×2 —— 全是 `数`
- `客户对账` 5 个入参中，计数×2(期数/每组) —— 全是 `数`

扩 ADR-26 类型词表（把 `数` 细分为 `金额/年/月/日/比率/计数`）**也无法消解**：
「生年」和「今年」即使细化到子类型「年」，仍是同子类型冲突。

**因此走路线 2：引入槽名语义匹配。**

---

## 2. 决议：槽名语义匹配绑定

### 2.1 核心思路

在 `TypeGraph.plan` 的候选变量选择阶段做两件事：

1. **同型槽不复用同一变量**（修 W42 暴露的实现缺陷）：一个步骤内，某变量被前面的槽
   消费后，从后续槽的候选池里剔除。旧实现会把唯一一个 `数` 常量塞进报销单全部 7 个
   `数` 槽，生成「月薪 = 生年 = 生月 = 同一个数」的荒谬代码且**不报警**。
2. **多候选时先做槽名字面匹配**：类型兼容候选 >1 时，用形参名与变量名的字面关系
   消解歧义；匹配不上再落回既有的「最近产出优先」。

```
候选 = [v for v in reversed(池) if v not in 本步已用 and type_feeds(v.类型, 形参类型)]
if len(候选) == 0:   留空 + 记未匹配原因（区分「同变量已用」与「无类型兼容」）
elif len(候选) == 1: 用它（线性链路，行为与 v0.14 一致）
else:                字面匹配命中且置信度 >= 0.6 → 用命中项；否则用 候选[0]（最近产出）
```

### 2.2 字面匹配策略

三级递进，**首个非空级即定胜负**（`match_slot_name`）：

1. **精确匹配**：变量名剥百家姓前缀后 == 形参名（置信度 1.0）
   - 形参「生年」→ 变量「赵生年」（剥前缀得「生年」）
2. **后缀匹配**：剥前缀后以形参名结尾（置信度 0.8）
3. **包含匹配**：形参名是剥前缀后的子串（置信度 0.6）

**同一级有多项命中即视为歧义未消解，返回留空**——不在同级里再挑一个。
例：形参「年」对候选 `赵生年/赵今年`，两者都后缀命中 → 返回 `(None, 0.0)`，
交由上层落回兜底而不是乱猜。

**不做**：embedding 相似度、需求文本 NLP 解析。理由：
- 零运行时第三方依赖是硬守原则
- 字面匹配已能覆盖 L3 槽的主要冲突模式（年/生年/今年 的命名规范使然）
- v0.16.0 教训：先验假设被证伪（神经 > TF-IDF），先跑最简单的看数字

### 2.3 留空原则与兜底的边界

**不可让步的部分**：同型槽不复用同一变量。凑不齐就留空 + `未匹配` 点名，
理由文本明确写「同变量已喂前一槽，避免同型静默复用」。

**保留兜底的部分**：多候选且字面匹配不出结果时，仍取「最近产出」而非直接留空。
这是刻意的——评测集 L01-L13 十三条 `应链` 用例全都依赖这条兜底
（`共享` 常量是 `任意` 型，对任何槽都类型兼容，若「匹配不上就留空」会把
既有 100% 链式命中率打到 0）。**为一个假想场景砸掉十三条已验证用例是错的交易。**

留空后的用户体验：生成代码里该参数位置写 `?` + 注释说明，沿用 `synthesize`
的既有占位机制。

### 2.4 对既有行为的影响

| 场景 | 现行行为 | 改后行为 |
|------|----------|----------|
| 池中只有一个类型兼容变量 | 取唯一候选 | **不变** |
| 多候选 + 槽名字面命中 | 取最近产出（可能填错） | **取字面命中项** |
| 多候选 + 字面匹配不出 | 取最近产出 | **不变**（见 §2.3） |
| 同一步骤内同变量喂多个槽 | 静默复用 | **剔除并留空 + 明确理由** |
| 池中无类型兼容变量 | 留空 | **不变** |

`bench_glue.py` 30 条用例实测**零回归**：命中率 100%、荒谬率 0%、拒绝质量 100%、
边界通过率 100%。

### 2.5 实现边界

- 改动只在 `tools/ai-bridge/glue.py`：新增 `strip_surname` / `match_slot_name`
  两个纯函数 + `TypeGraph.plan` 内部逻辑
- 不动 `type_feeds`、`normalize_type`、`synthesize` 的接口
- 不新增 pip 依赖；**不 import `jikuai.surnames`**——`strip_surname` 只需
  「跳过 1 个前缀字」的粗略近似，跨包依赖不值当
- 测试：`tests/test_glue_slot_binding.py` 20 条（含 3 条 L3 端到端 + 3 条留空守护）

## 3. 已知局限

1. **字面匹配只覆盖命名规范良好的场景**。若形参叫「月薪」而变量叫「赵甲」，
   字面匹配失败，落回最近产出兜底——可能填错。这是 §2.3 讲的刻意取舍。
2. **不处理跨步骤的全局最优分配**。仍按槽顺序逐个匹配，不做二部图最优匹配。
   理由：L3 入参通常来自不同上游，交叉冲突罕见；二部图引入 O(n³) 且难解释。
3. **置信度阈值硬编码 0.6**。不做用户可配——块命名规范统一（ADR-15 §3.7 原子性），
   阈值不会因项目而异。
4. **`strip_surname` 只剥 1 字**，复姓变量名（`欧阳月薪`）剥不干净。影响是
   降低命中率而非误匹配（第 2/3 级的子串关系仍能兜住），故不引入姓氏表。

## 4. 度量与验收（实测数字）

`bench_glue_l3.py --验证` 双场景实测（W30 基线：槽级 7/20 = 35.0%）：

- **场景甲「槽名规范命名」**（共享常量取名 `赵<槽名>`，选块器/用户按块签名命名时的常态）：
  **20/20 = 100.0%**。报销单 8/8、工资册 7/7、客户对账 5/5，
  `生年` 与 `今年`、`生月` 与 `今月`、`期数` 与 `每组` 三对同型槽全部各归各位。
- **场景乙「无字面线索」**（常量取名 `赵甲/赵乙/…`）：**同变量硬塞 0 次**，
  达到「宁可留空不硬塞」门槛。

`bench_glue.py` 原有 30 条：**零回归**（见 §2.4）。

**如实标注**：场景甲的 100% 是**字面匹配的上限**，前提是共享常量按槽名命名。
真实用户随手起名时落在甲乙之间，本轮不虚报一个「平均值」——两个端点都摆出来。

## 5. 决策记录

| 备选 | 结论与理由 |
|------|-----------|
| 扩 ADR-26 类型词表（路线 1） | **拒**。W42 数据证伪——即使细分子类型，生年/今年 仍同为「年」而冲突 |
| Embedding 语义相似度 | **拒**。引入运行时 AI 依赖，违反零第三方原则；且收益不确定 |
| 需求文本 NLP 解析 | **拒**。同上，且需求文本是人写的自由文本，不可靠 |
| 二部图全局最优匹配 | **拒**。O(n³) + 难解释；逐槽顺序匹配 + 留空已足够 |
| 多候选匹配不上即留空 | **拒**。会打掉 L01-L13 十三条已验证 `应链` 用例（见 §2.3） |
| 共享常量改按声明顺序扫描 | **拒**。实测打掉 L13（`文本合成` 的分隔符要取最近的 `赵分`），为假想场景砸真用例 |
| 当前方案：字面匹配三级递进 + 同型槽不复用 | **接受**。零依赖、可解释、零回归，L3 上限从 35% 抬到 100% |
