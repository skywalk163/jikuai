# ADR-32 · 块包格式与安装器块发现接线（v0.19.0 W63）

- 状态：Accepted
- 日期：2026-08-11
- 决策者：项目维护者
- 落地环节：v0.19.0 W63（设计）/ W64（桩验证）/ W65-W66（实现）
- 相关：ADR-27（第三方块注册表 —— 本 ADR 兑现其 §4 末条伏笔）、ADR-15（块生态架构）、ADR-28（L3 聚合块规范）

---

## 1. 背景

包管理与块生态是**两套互不相通的体系**：

- **包**：`jk 包 装` 把依赖物化到 `项目根/极快_包/<名称>/`（`installer.py` 的 `PACKAGES_DIR`、`_install_one`），记账进 `包.锁`。
- **块**：`scan_blocks()` 只扫内置 `blocks_root()` 加上 `extra_roots()`，后者仅读环境变量 `JIKUAI_PKG_ROOTS`（`blocks.py` 的 `PKG_ROOTS_ENV`）。

代码层面的断裂是可验证的：`installer.py` / `resolver.py` / `pkg/cli.py` **没有任何一处 import `blocks` 模块**；`extra_roots()` 的唯一调用者是 `scan_blocks()`，`JIKUAI_PKG_ROOTS` 的唯一读取点是 `blocks.py`。`blocks.py` 自述「块不会被安装进 `极快_包/`」正是这个现实的注脚。

后果是第三方块只能靠用户手配环境变量接入——ADR-27 §4 末条已埋下伏笔：

> 未来若需包管理器自动安装，只需让安装器把块放到约定目录并追加环境变量。

v0.19.0 兑现这条，但**对「追加环境变量」这半句作出修正**（见 §5）。

## 2. 决议：最小桥接

核心原则：**包只是块的运输壳**。块元数据格式不动、命名空间规则不动、合并规则不动；只新增两件事——包如何声明自己携带块，安装器如何让这些块被发现。

### 2.1 携带块声明进 `包.json`，不进 `包.锁`

`包.json` 新增**可选顶层字段 `块`**，值为「包内块根的相对路径」字符串列表：

```json
{
  "名称": "社区块集",
  "版本": "1.0.0",
  "块": ["blocks"]
}
```

- 字段缺失或为空列表 = 普通包，不携带块（存量包全部落在这一档，**零破坏**）。
- 每条路径相对**包根**解析，语义与 `extra_roots()` 的每条路径一致：**直接指向 `blocks/` 那一级**，其下第一级子目录即命名空间（ADR-27 §2.1/§2.2 不变）。
- 允许多条，用于一个包携带多组块根的场景；不推荐但不禁止。

**为什么进 manifest 而不是 lockfile**：携带块是**作者的静态声明意图**，不是依赖解析的产物。`包.锁` 的职责被 `lockfile.py` 明令限定为「让同一份清单在任何机器上装出完全一样的依赖树」，刻意不写派生与易变字段；把作者声明塞进锁文件属于职责错配。且 `Manifest` 对未识别字段是**宽松保留**（`_validate` 只查必填与几个类型，`to_dict` 原样透传 `_data`），新字段不需要改动任何读写路径。

### 2.2 安装落点不变

块随包一起物化到 `极快_包/<包名>/`（沿用 `_install_one` 的落点与 `.tmp-` → `os.replace` → `.old-` 时序）。块根就是其下 `块` 字段声明的子目录，例如 `极快_包/社区块集/blocks/`。

**不给块单独开落点**。理由：包已经是原子安装/卸载单位，块跟着包走能免费继承 `_prune` 的裁剪语义与 `os.replace` 的原子替换；给块另开目录等于要自己重造这两件事。

### 2.3 发现接线：安装器维护块根索引文件

安装器在 `极快_包/` 下维护一份**已装块根索引** `极快_包/.块根.json`：

```json
{
  "索引版本": 1,
  "块根": [
    {"包": "社区块集", "路径": "社区块集/blocks"}
  ]
}
```

- 路径相对 `极快_包/` 存放（**不写绝对路径**——`包.锁` 已确立「不写机器相关字段」的纪律，绝对路径会让这个文件不可提交、换机即废）。
- `install()` 收尾时按本次解析出的节点重建整份索引（复用 `_prune` 的 `keep` 集合作真相源，保证索引与磁盘一致）；`uninstall()` 同步剔除对应条目。**重建而非增量改**，避免增量维护出现残留。
- `extra_roots()` 扩成两路来源合并：环境变量 `JIKUAI_PKG_ROOTS`（**优先**，保留原语义）+ 从当前目录上溯找到的项目根下的 `.块根.json`。仍然过滤不存在目录、去重保序。

### 2.4 命名空间：推荐取包名，不强制

块包的块根下**应当**套一层命名空间目录：

```
极快_包/社区块集/blocks/社区块集/数据/方差/块.json
                       └─ 命名空间（推荐 = 包名）
```

`_infer_namespace()` 逻辑不改——相对块根的第一段目录名即命名空间。若作者没套这层目录（块直接躺在块根下），该函数返回空命名空间，块会与内置块争同一命名空间，撞名时按 ADR-27 §2.3 **内置优先、第三方静默跳过**。

**为什么推荐而不强制**：强制要靠新校验，而 ADR-27 §2.2 已定「命名空间从目录结构推断、不写进 `块.json`」——把它变成硬约束等于在包侧再造一套元数据校验，与「最小桥接」相悖。不套命名空间的后果（可能被内置块遮蔽）由作者自己承担，且这个后果是既定规则的自然延伸，不是新增陷阱。

### 2.5 不变的部分（明确列出，防止实现期跑偏）

- `块.json` schema 一个字段都不加。
- ADR-27 §2.2 命名空间推断、§2.3 合并规则与内置优先、§2.4 索引格式全部照旧。
- 块的 sha256 完整性走包的 `compute_checksum`（包内 `.jk`/`.py`/`.json` 全覆盖，块文件天然在内），**不给块另开校验路径**。
- 七门（G10-G17）对块的校验口径不变——第三方块包里的块该过什么门，与手配 `JIKUAI_PKG_ROOTS` 接入的块完全一致。

## 3. 实现要点（W65-W66 对着做）

| 位置 | 改动 |
|------|------|
| `manifest.py` | `Manifest` 加 `块根声明` 只读属性读 `块` 字段；`_validate` 校验它是「字符串列表」且每条不含 `..`/绝对路径（沿用 `入口` 字段的逃逸防护口径） |
| `installer.py` | 新增 `_写块根索引(base, nodes)`；`install()` 在 `save_lockfile` 附近调用；`uninstall()` 后重写索引 |
| `blocks.py` | `extra_roots()` 加读 `.块根.json` 一路；新增 `_找项目根()`（向上找含 `包.json` 的目录，与 `module_loader` 的项目根口径一致） |
| 常量 | `installer.BLOCK_ROOTS_INDEX = '.块根.json'`、索引版本 `1`（不匹配拒读，同 `包.锁` 纪律） |

**安全边界**：`块` 字段的每条路径必须落在包目录内——`_ensure_within` 已有现成实现，直接复用。这是新增的外部输入面（第三方包 `包.json` 里的路径），不校验等于开一个目录穿越口子。

## 4. 后果

- 存量包与存量块**行为完全不变**：不声明 `块` 的包走老路；手配 `JIKUAI_PKG_ROOTS` 的块继续优先生效。
- `.块根.json` 是新的可提交产物，落在 `极快_包/` 内——该目录已在 `.gitignore`（`jk 包 初始化` 会追加），因此实际不进版本库，每次 `jk 包 装` 重建。
- `extra_roots()` 从「纯环境变量读取」变成「环境变量 + 项目根索引」，多了一次向上找项目根的文件系统探测。纯脚本用户（无 `包.json`）找不到项目根即跳过，不受影响。
- 块生态首次有了「装一个包就多一批块」的路径，为 W67 生态冷启动与 W68 端到端钉板铺路。

## 5. 决策记录

| 备选 | 理由 |
|------|------|
| 安装器追加用户环境变量 `JIKUAI_PKG_ROOTS`（ADR-27 §4 原设想） | **否决**。跨平台不可靠（PowerShell/bash/图形会话各写各处、各自生效范围不同）；卸载时无法精确回收自己写进去的那几段；污染用户全局环境，一个项目的安装影响另一个项目。ADR-27 写这条时还没有 installer，属未经实现检验的设想 |
| 块另开安装落点（如 `极快_块/`） | 否决。要自己重造 `_prune` 裁剪与 `os.replace` 原子替换；且包与块的生命周期本就一致（块跟着包装、跟着包卸），拆开只多一套记账 |
| 携带块声明进 `包.锁` | 否决。锁文件职责是确定性重现依赖树，明令不写派生字段；且信息源头在 manifest，进锁文件要多穿一层 `to_locked` |
| 把块与包模型统一（块也是一种包） | 否决。块有层级/领域/输入输出/导出/依赖块/稳定性等一整套语义，包只有名称版本依赖——强行统一会做出四不像，且要动 `块.json` schema 与七门口径。**这是本 ADR 最重要的一条否决** |
| 强制块包必须套命名空间目录 | 否决。要新增校验，与 ADR-27「命名空间由目录推断、不进元数据」的既定路线冲突；改为推荐 + 后果自负（见 §2.4） |
| 当前方案：manifest 声明 + 索引文件接线 | 块格式零改动、安装卸载对称、不碰用户环境、复用现成的落点与校验和机制 |

## 6. 重开条件

若出现下列情形，本 ADR 的 §2.3 需重审：

- 需要「不依赖项目根」的全局块包安装（当前索引挂在项目根下，天然是项目级）。这与 BACKLOG §3「全局缓存共享」是同一件事，届时一并设计。
- `.块根.json` 在真实使用中出现与磁盘不一致的情形（说明重建时机选错了）。W64 桩验证与 W65-W66 的卸载对称测试就是拦这个的。
