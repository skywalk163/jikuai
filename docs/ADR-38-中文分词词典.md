# ADR-38 · 中文分词词典扩容（565 → 约 2.9 万）

- 状态：Accepted
- 日期：2026-08-15
- 决策者：项目维护者
- 落地环节：v0.23.0（见 `docs/路线图-v0.23.md`）
- 相关：ADR-16（标准库契约 §3.3 混合模块）、BACKLOG §9（本 ADR 兑现其立项）、
  v0.13.0「人工同义词表 = 过拟合」教训（见 §6 边界澄清）

---

## 1. 背景：现状不是空白，是词典太小

`stdlib/分词.jk`（门面）+ `stdlib/分词.py`（实现，235 行）已在跑正向最大匹配
（FMM）。**算法那部分是完整的**：

- `segment()` 是纯函数，只读模块级 `WORDS`（`frozenset`）与 `MAX_WORD_LEN`
  （`分词.py:164-211`）
- 兜底三分支 B1 空白 / B2 半角字母数字整体成词 / B3 其余单字成词，口径与
  `docs/标准库.md` 对齐
- 幂等三条 AC（AC-M5-07-01/02/03）由 `tests/test_v0_6_0_segmenter_idempotent.py`
  把守，含「源码里不得出现 `global`、`WORDS` 必须是 `frozenset`」的静态防回归

缺的只有词典：**565 条**，7 段空白分隔的字符串字面量硬编码在 `分词.py:49-119`，
`_build_dictionary()` 过滤「长度 ≥2 且全汉字」后去重成 `frozenset`。
`docs/标准库.md` 自己写明「词典是常用词子集（565 条），未收录词按单字兜底切」。

`MAX_WORD_LEN` 不是常数，是从词典推导的（`分词.py:143`），当前值 **5**。
这一点在扩容时会咬人，见 §4。

## 2. 立项理由与非目标

**理由是「中文」域本身**——它是六域之一，是 `极简·极速·极中国` 价值主张里
「极中国」的直接承载物。565 条的分词对外称不上一个能力。

**非目标（写在最前面，否则会本末倒置）**：

本 ADR **不以「改善检索拒答」为验收标准**。拒答专题第五轮已实测：即使给一个完美
分词，`评测集.json` 的正例仍会产出库外词——建集原则就是刻意用口语改写避开块名，
`帮我把这堆数字加起来` 切成 `帮我 / 把 / 这堆 / 数字 / 加起来`，其中 `帮我`、
`这堆`、`加起来` 在块语料 df 同样为 0。分词只把粒度切对，**不解决「虚词/口语 vs
内容词」的区分**。

同理，**不在本轮动 `src/jikuai/ai/retrieval.py` 的 `_tokenize_chinese`**。它是检索侧
独立的 uni/bi/tri-gram 穷举，与 stdlib 分词无 import 关系；v0.16.0 实测链式任务
TF-IDF 反超神经 38pp 正是靠这套 ngram 字面匹配。换成词级切分**很可能是负收益**，
属另一条待定项（BACKLOG §9 第二行），要动必须按纪律双集报数。

## 3. 决议：两源合并 + 现有词表作必留种子

### 3.1 三个组成部分

| 来源 | 授权 | 取法 | 净增词数 |
| --- | --- | --- | --- |
| **种子集**：现有 565 条 | 本项目自有 | **全部必留，无条件合并** | 565 |
| **通用底座**：jieba `dict.txt` | MIT（Sun Junyi, 2013） | 过滤后按词频降序取 top 20000 | 20000 |
| **域内增强**：THUOCL `caijing` / `law` | MIT（THUNLP, 2018） | 全量过滤后取 | 约 9200 |

合并去重后 **29331 条 / 289 KB / 加载 8.2 ms**（实测，见 §5）。

### 3.2 必留种子集不可被频率截断（本 ADR 最容易被误删的一条）

实测：jieba 按词频取 top 20000，会**漏掉现有 565 条里的 91 条**，包括

> 人工智能 分词 简体 繁体 简繁 排版 成语 语料 语料库 标点 标点符号 程序员
> 线程 队列 组件 文档 调试 加密 解密 解码 源代码 二进制 字节 用户体验
> 局域网 广域网 路由器 交换机 防火墙 虚拟机 解释器 显卡 公历 端午 中秋 ……

原因是 jieba 的词频来自**通用语料**，不是极快业务域的频率分布。极快最需要的技术词
恰好在通用语料里是低频词。

因此：**现有 565 条是必留集，合并顺序为「种子 ∪ 底座 ∪ 增强」，任何后续调整
`top N` 的动作都不得导致种子集出现缺失**。生成脚本必须断言 `seed - merged == ∅`。

### 3.3 明确不收的词表

THUOCL 共 11 个词表，只收 `caijing`（财经）与 `law`（法律）。逐条理由：

- `IT`：12854 条可用，净增 12834 条 / +165 KB，但绝大多数是产品名与公司名。
  种子集的 `_RAW_TECH` 段已覆盖技术通用词。**列为可选扩展，本轮不收**——
  要收须先给出「哪个真实需求被切错了」的具名证据。
- `diming`（地名，640 KB）/ `animal` / `medical` / `poem` / `car` /
  `chengyu` / `food` / `lishimingren`：与六域无关，纯体积。`chengyu` 另有
  `stdlib/成语.jk` 模块承载，不重复。

## 4. 词长上限截断到 8 字（性能决策，不是洁癖）

`MAX_WORD_LEN` 是 FMM 内层递减循环的上界，直接决定单字符成本。

实测（同一段 1880 字中文财务文本，jieba top20000 词典）：

- `cap=5`（现状词长）→ 4.02 ms
- `cap=6` → 4.46 ms
- `cap=8` → 4.91 ms
- `cap=14`（不截断）→ **6.81 ms**，比 cap=5 慢 70%

而超过 8 字的词条只有 30 个，占 0.15%。

**决议：入库过滤条件从「长度 ≥2」改为「2 ≤ 长度 ≤ 8」。**花 0.15% 的词条换回
28% 的切分速度。8 字以上的长串本来也不该由 FMM 一口吞掉——那是短语，不是词。

副作用：`MAX_WORD_LEN` 从 5 变 8，`test_最长词长度与词典一致` 仍成立（它断言的是
与词典一致，不是等于某个字面值）。

## 5. 存储形态：明文外部文件，不压缩

### 5.1 决议

- 词典落 `stdlib/分词词典.txt`：**UTF-8、一行一词、按码点升序、无注释、
  结尾单个换行**。排序固定是为了让 git diff 可读、让 sha256 可复现。
- `分词.py` 在导入期读同目录的该文件，构建 `frozenset` 后即只读。
- 授权链条落 `stdlib/分词词典来源.md`（人读）；机读的来源与校验和落
  `stdlib/分词词典.元信息.json`（含每个上游源的 URL、license、取用规则、
  条数，以及合并结果的 `词条数` 与 `sha256`）。

### 5.2 为什么不压缩（原方案是压缩内联，实测后推翻）

实测 2 万词规模：

| 形态 | 体积 | 加载耗时 |
| --- | --- | --- |
| 明文 | 152 KB | 5.5 ms |
| gzip -9 | 69 KB | — |
| gzip + base64 嵌 .py | 92 KB | 7.1 ms |

压缩省下约 84 KB，代价是：

1. **git diff 完全不可读**，词典改了什么看不见——评审无法进行；
2. gzip 必须固定 `mtime=0` 才字节可复现，否则每次重打包都产生假变更；
3. 加载路径多一层解压，反而更慢。

84 KB 换不掉「词典改了什么能看见」。仓库里 `向量索引.bin` 量级远大于此，
289 KB 明文不构成体积问题。**故改为明文 + sha256 记账**——后者比压缩更能防篡改。

### 5.3 这打破了「词典内联在 .py 里」的现状，但不打破品牌主张

「零依赖」指的是**不引第三方运行时依赖**，不是「不许有数据文件」。
`分词词典.txt` 随包分发，不需要网络、不需要 pip 安装任何东西。
打包清单要相应把 `stdlib/*.txt` 纳入（见路线图验收项）。

## 6. 边界澄清：这与 v0.13.0「同义词表 = 过拟合」不冲突

v0.13.0 那条教训针对的是**为检索指标手搓的同义词映射**——对着评测集调的旋钮，
涨的是调优集、留出集不涨。本 ADR 引入的是**通用语言资源**：词表来自公开的通用
语料词频与第三方领域词库，**与任何评测集无关**，也不以任何检索指标为验收标准
（§2 已声明）。

这个区分必须写在这里，否则下一轮复审会拿旧教训把它自己否掉。

判据：**看词表的构造过程有没有看过评测集**。看过 = 旋钮；没看过 = 语言资源。

## 7. 授权链条

两个上游都是 MIT，都明确允许随仓库分发与商用：

- **jieba**（`fxsjy/jieba`）：`LICENSE` 为 MIT，Copyright (c) 2013 Sun Junyi。
  仓库整体授权覆盖 `jieba/dict.txt`。
- **THUOCL**（`thunlp/THUOCL`）：`LICENSE` 为 MIT，Copyright (c) 2018 THUNLP。
  README 另有明文：「面向国内外大学、研究所、企业、机构以及个人免费开放，
  **可用于研究与商业**」，并要求引用其 2016 年词库论文。

义务履行：`stdlib/分词词典来源.md` 完整转录两份 MIT 文本与版权行，并按 THUOCL
要求写明「使用了清华大学开放中文词库」及引用格式。

**残留风险（如实记录，不粉饰）**：jieba 的 `dict.txt` 上游语料来源（人民日报语料
等）jieba 自身未逐条声明。我们依赖的是其仓库的 MIT 授权 + 署名，这是业界通行做法
（jieba 已被 Debian 收录分发），但**不等于逐词条可追溯授权**。若日后上游澄清出更严
格的条件，处置方式是换源重生成——因为词典是生成产物，`重生成词典.py` 一条命令即可
替换底座，不影响 FMM 代码。这是选择「生成脚本 + 记账」而非「手工维护词表」的另一
个理由。

## 8. 幂等口径（G12 · AC-M5-07-01/02/03）不变

新增外部文件读取**不破坏**现有三条 AC，但实现上必须守住：

1. 文件读取只发生在**导入期**，`segment()` 运行期一次文件都不碰；
2. `WORDS` 仍是模块级 `frozenset`，`MAX_WORD_LEN` 仍由词典推导；
3. 不引入 `global`、不引入模块级可变容器、不写 `sys.modules` / 环境变量 / 文件——
   `test_AC_M5_07_02_源码无global与可变模块级容器` 的静态断言继续生效；
4. `module_loader._load_python_backing` 的进程级缓存 `_PY_BACKING_CACHE` 保证同一
   路径只加载一次，8.2 ms 的构建成本每进程只付一次。

词典文件缺失时的行为：**直接抛异常，不静默降级到内置小词典**。静默降级会让
「词典没打包进去」这种发布事故变成线上悄悄劣化，比启动即失败糟得多。

## 9. 需要改动的既有断言

- `test_词典至少500条`：`>= 500` 是下界，扩容后仍绿。建议同步上调为
  `>= 20000` 并新增上界，否则这条断言在扩容后等于没在守（参照 v0.22.0
  「守卫绿 ≠ 守卫在守」教训）。
- `test_词典条目全为汉字`：继续保留。`_build_dictionary()` 的全汉字过滤会挡掉
  THUOCL 里含字母数字的条目，断言不会红。
- 新增：`test_种子集全部在库`（§3.2 的必留约束）、`test_词长上限为8`、
  `test_词典文件sha256与元信息一致`。

## 10. 不做的

- **逆向 / 双向最大匹配（BMM / BiMM）**：本轮只扩词典，不改算法。歧义消解要另立
  ADR 并拿出「FMM 切错、BiMM 切对」的具名用例集。
- **词性标注 / 命名实体识别 / 新词发现**：`docs/标准库.md` 已声明不做，本轮不变。
- **用户自定义词典接口**：无具名需求。FMM 主循环支持任意词典，真有诉求时再开。
- **动 `_tokenize_chinese`**：见 §2。
