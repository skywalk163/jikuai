## §1 主张与边界

**核心主张：LLM 只选口径，不算数。** 自然语言理解（问句 → 选哪些块、填哪些实参）交给
LLM；口径计算（达成率怎么加权、缺陷率先汇总后相除）由确定性块算；`组`/`跑` 的代码
合成与执行链路**整条不调用 LLM**。这是本项目区别于「LLM 直接写 SQL / 直接算数」的
落点——LLM 错选口径会被 §4 校验器和 §5 拒答拦下，LLM 不经手任何一个数字。

**不做真 Text-to-SQL。** 理由：一旦让 LLM 直接产出可执行查询，口径正确性就回到「祈祷
模型没算错」，本项目的确定性合成层卖点被架空。等价 SQL 导出（v0.28.0 W159）只作
「展示查询过程」，不进执行路径。

**边界**：规划器不进 wheel（§7）；不碰检索层的拒答（§5）；不新增 Web 路由
（演示端点安全化是 v0.28.0 W161）。

## §2 双模式，共用一个校验器

两条命令，职责切分明确：

- `jk 块 规划 "问句" [--json]` → 出**规划上下文包**（§3）。纯离线、确定性、CI 真跑。
  它不接触任何模型——只是把「问句 + 检索候选 + 语义层 + 块元数据」组装成 LLM 能照着
  回填的受限结构。**正在读这段的 agent 自己就是那个 LLM**：`规划` 出包，你回填。
- `jk 块 问 "问句" --模型 <端点> [--json]` → 端到端：上下文包 → 外部端点 → 回填 JSON
  → 校验器 → 组 → 跑 → 答案 + 溯源。给 demo 用。

**硬约束：两条路径回填后走同一个 `validate_filled`（§4）。** `问` 不因为「模型是自己
调的、应该更可信」就旁路校验。外部端点的响应一律当**不可信输入**。这条是为了让
`规划`（人/agent 手填）和 `问`（模型自填）的正确性保证完全一致——校验器是唯一真源。

不给 `--模型` 调 `问` → 退 1 并指向 `规划`，**不静默降级**为某个内置默认端点。

## §3 规划上下文包：为什么「选响应」不够

现有「选响应」的候选字段是 `名称/领域/层级/导出名/描述/分数/路径`
（`schema.CANDIDATE_REQUIRED`）——**它不带块的输入槽**。这正是 v0.26.0 W145 实测里
LLM 写不出实参、只能靠人手写 124 步实参的直接根因：候选告诉你「有个块叫 `产量汇总`」，
但不告诉你它吃几个参数、每个参数什么类型。

上下文包在候选基础上补齐（字段常量在 `schema.py`，W148）：

```
需求
语义命中[业务词, 表, 字段, 口径说明]        # 从 制造/语义层.json 的 42 条业务词命中
候选[
  …选响应候选全部字段,
  输入槽[名, 类型],                          # 新增：LLM 照它填 参数
  输出类型                                    # 新增：LLM 据它接链
]
分歧告警[分歧点, 两侧块名, 实测差值, 须显式选一条]   # §5
回填契约                                      # 给 LLM 的回填格式说明（字段名、必填项）
拒答建议[覆盖, 理由]                          # §5，含"制造域无领域先验"这类已知缺口
```

`输入槽` 是把「实参写死」从事后校验前移到**信息供给**：LLM 知道每个槽的名和类型，
才有可能一次填对。校验器（§4）是兜底，上下文包是使能。

**回填响应**（LLM 回填后、过校验器前的形状，W148 定）：

```
需求
方案                                          # PLAN_* 结构，LLM 的产出
模型                                          # 回填来源标识：人手填 '人工'，端到端填端点名
溯源?                                         # 可选，端到端时带上每个数字的来源块名
```

`模型` **不可省**：ADR-41 §8 的录像回放要靠它标明这份回填出自谁，缺了就无法判断
「换模型后结果变了」还是「链路本身变了」。空串同样拒。

**拒答走 `拒答建议` 而不是回填响应里的拒答分支**：判「库外能力」是规划器在出上下文包
时就该做完的事（§5 的词表覆盖判定不需要 LLM 参与）。让 LLM 再回一个「我拒答」的分支，
等于把已经确定的判断交回给不确定的一方。所以回填响应里 `方案` 是必需字段。


## §4 回填校验器：五条硬规则

`planner.validate_filled(填充方案, 上下文包)` → `(通过?, 拒绝理由列表)`。任一不过即拒。
每条都要有反例测试（W157，≥5 类反例）：

1. **每步 `参数` 必填，长度 = 该块输入槽数。** 缺一个就拒。比粘合器的 `?` 占位更早
   一道闸——`?` 占位是「组出来了但推不出实参」，这条是「根本没让你省略实参」。
   *根因*：v0.26.0 W145 对照实验证明，省略 `参数` 让粘合器自动推链会**静默错绑**
   （`读表(赵产量列)`），既不落 `?` 也不写拒绝理由，运行期才死。制造域尤其致命。
2. **块/领域/导出名必须来自上下文包 `候选`。** 白名单，防 LLM 幻觉块名。
3. **分歧点两侧同时出现 → 拒；问句命中该口径而一侧都没选 → 拒。** 逼 LLM 显式选一条
   口径（§5）。
4. **产物必过 `schema.validate_plan`。** 协议多余字段、类型错误在这里兜底。
5. **`--严格` 下，无声明类型的共享常量不许喂精确形参。** 配合 §6 的粘合器治根。

拒绝理由必须**可操作**：说清缺哪个槽、该填什么类型，不是一句「校验失败」。

**W157 落地口径（2026-08-19）**：实现签名是
`planner.validate_filled(回填, 上下文包, 严格=False) -> list[str]`——返回**中文拒绝理由
列表，空列表 = 通过**，不是本节初稿写的 `(通过?, 理由)` 二元组。改的理由：全仓校验器
（`schema.validate_*`、粘合器的拒绝理由）都是这个约定，`通过 = not validate_filled(...)`
一行可得，多带一个布尔只是多一处可以写反的地方。另配 `ensure_filled`（不通过抛
`SchemaError`），与 `schema.ensure_*` 同构。第 4 条实际调 `validate_filled_envelope`
（内含 `validate_plan`）且**先跑**：形状不对时后四条读到的 `步骤` 可能压根不是数组，
先回形状错误，不叠一堆派生噪音。


## §5 拒答放规划器层，不放检索层

**检索层本轮一行不改。** `retrieval.py` 无分数阈值、永远返回 top-K，这是四轮实测后的
既定设计：近边缘需求上各置信信号的可分性 AUC 仅 0.52–0.67（0.5=随机），唯一能拒掉
94% 无覆盖需求的阈值会同时误杀 64% 真命中（`bench_retrieval_reject.py`）。
**任何想在检索层复活分数阈值的改动，先去读那四轮结论。**

规划器层的拒答判据是**词表覆盖判定**，与分数无关：
- 语义层业务词未登记 **且** 候选块无一自报对应口径 → 拒（远离档）。
- 近边缘档**不自动拒**：出 `分歧告警`（两侧块名 + 实测差值）逼 LLM 显式选一条，
  选不出才拒。

分档报数（远离档 / 近边缘档），与检索层的 0.0% 并列——**它们量的是不同层，规划器的
拒答数字不许拿来掩盖检索器仍是 0.0% 这个事实**。

讲口径分歧要**拿缺陷率那 57% 去讲**（2026-06 先汇总后相除 0.050550 vs 行级比率平均
0.032218）。达成率那处在本数据集只差万分之几，讲会讲得很弱。

## §6 `共享` 携带声明类型：改动面与预期代价

**根因链**（v0.26.0 W145 + Explore 实测）：`glue.py:376-380` 把 `共享` 常量一律入池为
`('任意', None)` → `type_feeds`（`glue.py:236-238`）里 `任意` 双向放行 → 每个字符串常量
对每个形参都「类型兼容」→ 多候选消解退回「最近产出优先」随便挑 → 静默错绑。

**改动**（W149-W152）：
- `schema.py` 的 `共享` 键集从硬编码 `('名','值')` 加可选 `('类型',)`，取值域落 ADR-26
  类型词表。
- `glue.py` 入池读声明类型，无声明才退 `任意`。
- 多个 `任意` 候选竞争同一槽 → 落拒绝理由，不再「最近产出优先」。
- `type_feeds` 的类型格语义**不动**（`任意` 仍是顶）；改的是「不再无脑把常量标成
  `任意`」。

**预期代价（写死在此，不许到时候当回归回退）**：这会让 `bench_glue.py` 的自动链式
命中率**下降**——因为一批原本靠 `任意` 放行「蒙对」的绑定，现在会变成显式拒绝。
这是**正确的代价**：把静默错绑换成显式拒绝。v0.22 主教训「守卫绿 ≠ 守卫在守」的反面
就是这条——**数字丑但真，优于数字漂亮但错绑**。W152 必须并列报改前/改后两套数字，
下降项逐项写明原因。语义荒谬率仍须 = 0（硬底线）。

**W151-W152 落地实测（2026-08-18，纠正了本节初稿的一处判断错误）**：

初稿以为「消解判据 = 有没有声明类型」——有声明类型的候选走 recency，无声明的拒。
**实测把这条证伪了**：Q_PUB_001 的 5 个共享常量（CSV 路径、列名、两个日期、产量列名）
全都**合法且正确地**是 `字符串`，声明类型一个都挡不住 `表载入.路径` 按书写顺序错绑到
`赵产量列`。病根不是「没声明类型」，是**拿共享常量的书写先后当消解证据**。

修正后的判据（已落 `glue.py`）：多候选且槽名字面消解失败时——
- 候选里有**步骤产出**（非共享常量）→ 取最近产出。产出之间 recency 有语义（数据前向
  流动），L13 等既有链式走这一支。
- 候选**全是共享常量** → 拒绝（落 None + 可操作理由）。常量书写先后不是证据。

bench_glue.py 三轮数字：
- 改前：自动链式命中率 **100.0%** / 语义荒谬率 0.0% / 拒绝质量 100.0% / 边界 100.0%
- W151+W152 初版（判据错用「声明类型」）：命中率跌到 **92.3%**，误伤 L13——L13 的两个
  常量 `赵文`/`赵分` 都无声明，被新拒答逻辑挡下。
- 定版（判据=共享常量 + L13 的 `赵分`→`赵分隔符` 改名）：命中率回 **100.0%**。

**L13 的 fixture 改名不是「把测试改绿」**：`赵分` 剥前缀=`分`，与形参名 `分隔符` 既不
精确也不后缀也不包含匹配，改前它是**靠 recency 蒙对**的（两个无类型常量，恰好挑中对的）。
改名 `赵分隔符` 后剥前缀=`分隔符`，与形参名**精确匹配**（置信度 1.0）——L13 从「靠书写
顺序蒙对」升级成「靠槽名字面真对」。这正是本轮要的方向：**能力靠证据，不靠巧合**。
语义荒谬率全程 0.0%（硬底线未破）。


## §7 规划器为什么不进 wheel

落 `tools/ai-bridge/planner.py`，由 `blocks_cli._planner()` 仿 `_glue()` 动态加载。
不是偷懒：`glue.py` 本来就在 `tools/ai-bridge/`、不进 wheel（`MANIFEST.in` 只
`recursive-include src/jikuai/stdlib`），`blocks_cli._glue()`（`blocks_cli.py:190-213`）
找不到就抛 `BlockError('组/跑 需要仓库内的 tools/ai-bridge/')`。规划器依赖 `组`/`跑`，
**不可能比它的依赖可用性更强**——装了 wheel 的用户本来就跑不了 `组`/`跑`。

副作用（都是好的）：不动 `MANIFEST.in`、不动 `块背衬PY数`（当前 35）、不碰 G20。

## §8 录像回放：端到端评测的唯一可行解

LLM 输出不可复现，而 CI 在 FreeBSD、无外网、无 API key。若在 CI 里真调模型，评测不可
复现且无法离线；若 mock 掉模型，等于 mock 掉被测对象。

解法：`tools/ai-bridge/规划录像/` 录制每条问句的**回填 JSON**（含模型标识 + 时间戳）。
- CI 只回放录像，跑「校验器 → 组 → 跑」——确定性、离线、可进门禁（G23）。
- 真调模型只在本机人工跑，结果单独归档；与录像的差异如实记，不掩盖。

关键：**回放不 mock 校验器**。被测的是「校验器 + 组 + 跑」这条确定性链路对一份给定
回填的处理，模型的角色由录像固定下来。模型换了、prompt 改了，重录即可，被测链路不变。

## §9 被本 ADR 明确排除的选项

- **让 LLM 直接写 `.jk` 或 SQL**：见 §1，架空确定性合成层。
- **在检索层加分数阈值拒答**：见 §5，四轮实测已证伪。
- **规划器进 wheel 做成独立可分发组件**：见 §7，依赖 `组`/`跑` 决定了它进不了 wheel。
- **`问` 对自调模型旁路校验**：见 §2，破坏「校验器是唯一真源」。
- **为把「完整命中率恒 0」做上去而从评测集期望里删 `表载入`**：那个 0 是真缺口
  （问句从不提「载入」，TF-IDF 抓不到），删期望是自欺。
