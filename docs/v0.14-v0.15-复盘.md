### 检索路径实测（bench_retrieval，本轮实跑）

主评测集（56 用例）与留出集（25 用例）三臂对照——**留出集才是无污染裁判**。

| 数据集 | 关键词 R@1 / R@3 / MRR | TF-IDF R@1 / R@3 / MRR | 神经 R@1 / R@3 / MRR |
| --- | --- | --- | --- |
| 评测集.json（56） | 0.5000 / 0.6429 / 0.5801 | 0.6964 / **1.0000** / 0.8274 | 0.6250 / 0.8036 / 0.7313 |
| 评测集-留出.json（25） | 0.4800 / 0.6000 / 0.5613 | 0.6400 / 0.7600 / 0.6947 | **0.6400 / 0.8400 / 0.7333** |

- 主评测集 TF-IDF 的 R@3=1.0 系过拟合，与调优路线记录一致；留出集是唯一裁判
- **留出集上神经 R@3=0.8400 > TF-IDF R@3=0.7600**，神经路径继续保持首次跑赢启发式的优势（v0.13.0 W8 首次达成，v0.15.0 未再刷）
- 链式集（`评测集-链式.json`，30 用例）**全部 0.0** —— 见下节「错估的估算」

## 三、错估的估算（每条一句话）

- **Web 无框架比想象容易**：标准库 `http.server` + 手写 5 端点 + 单页 gzip 13.55 KB 就够，`pip install flask` 从头到尾没必要，产品一致性和实现难度并不冲突
- **AI 桥接的神经路径不稳定**：本机连不上 HuggingFace 是常态，`HF_HUB_OFFLINE=1` + `HF_ENDPOINT` 镜像是既定 workaround，任何 CI 侧的 neural bench 都必须能降级到 skip
- **链式集 bench 不适用（schema 不匹配）**：`bench_retrieval.py` 用「候选块名 ∈ 期望名列表」判命中，链式集期望的是**多步块名序列**（比如 `[个税, 金额雅写]`），单块召回天然打不中——这是评测 schema 与数据集 schema 不匹配，不是回归；`评测集-链式.json` 需要新写一条链式召回 bench（多步覆盖率）而不是复用现有工具
- **`definition` 从跳目录改跳文件**：VS Code F12 在目录上会打开文件浏览器面板，跳到具体 `.jk` 文件的 `函数 <导出名>：` 那一行才是真正的开发者习惯
- **`降级说明` 从通道内字段收进 schema**：最初想在候选卡片里塞个「本次走了启发式因为找不到向量」的说明，起初三边各写各的字符串，最终统一收进 `schema.make_candidate` 的 `降级说明` 可选字段，通道零重复

## 四、哪些设计判断被证实/证伪

- **三段式 CLI 的 pipe/JSON 双通道**：证实好用。`jk 块 选 --json | jk 块 组 - | jk 块 跑 -` 端到端可跑；JSON 通道直接被 LSP/Web 复用（三边同 schema）——三段式定型为「一次设计三处复制」的杠杆
- **类型图链式的召回**：证实可用但非银弹。自动链式跑到 ≥60% 后收益变平，剩下 40% 是需要人工声明 `参数` 的异质元组解构（`税单 → [月收入, 个税, ...]`），类型系统只能提示不能自动
- **L2 块生态 105+ 的数字够不够**：证实够门面 demo 使用（10 个 demo 覆盖五域），但真到「用户档案」这类跨域块，L2 数量偏少（v0.15.0 仅 3 个）——L3 及以上组合暂无系统性铺开，留给 v0.16.0
- **命名空间机制是否顺**：证实基本顺。`JIKUAI_PKG_ROOTS` 单变量 + 索引合并 + G13 跨命名空间三招下来第三方块能被 `列表`/`选`/`跑` 看到；隐患是短名碰撞（`转义/环境`）——G13 抓得住但用户第一次撞会觉得晦涩，需要文档兜底
- **零第三方依赖坚守**：证实是正确的品牌主张。Web 层不引 Flask/FastAPI、LSP 用手写 JSON-RPC、neural 依赖隔离在 `tools/ai-bridge/`——运行时零 pip 依赖的语言，官方 UI 也不 `pip install`
