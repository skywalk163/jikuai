## 三、错估的估算（每条一句话）

- **版本号漂移比想象严重**：以为只是 `pyproject` 一处，实际是四处（`pyproject` / `__init__` / `main.py` / `editors/vscode/package.json`）从 v0.7.0 开始就没同步过，跨了整整九个版本；`_version.py` + `dynamic` 引用 + G15 门禁才彻底闭环，光「记得改」不够
- **链式召回上神经胜出的先验被证伪**：v0.13.0 起我们坚信「神经 > TF-IDF」是通用结论，链式集数字打脸——**TF-IDF 在多步召回上反超**。原因是链式需求措辞更接近块的词面（「个税」「金额雅写」这类术语原样出现），TF-IDF 的词面匹配天然占优；神经的语义泛化在链式场景反而稀释了强信号
- **L3 粘合器覆盖率远低于预期**：以为 L3 只是"更多的 L2"，实际 L3 入参 5-8 个同型 `数` 槽（贷款额/月薪/年月日全是数），纯类型图无从区分同型不同义 —— 末步整体命中 **0/3**、槽级 **35%**。这不是 bug 而是 ADR-28 §3.3 早已预判的推导爆炸；反过来证明「不开 L4，先看 L3 数字」是正确判断
- **`.vsix` 打包比想象低成本，验证比想象高成本**：npm/vsce 侧脚本 20 行搞定，难的是"本机得先有 Node + VS Code"，而主开发机就是没有 —— 这是**代码就绪与人工验证的天然错位**，v0.15.0 W16 欠账在 v0.16.0 W33 补了代码但生出新的验证欠账
- **文档待办比想象散**：本以为集中在复盘 §5，实际散在 复盘 / `lsp/README.md` / `docs/包管理.md` / `docs/语法参考.md` §13.2 / AOT `subset_gate.py` / `docs/ADR-28` 六处；`docs/BACKLOG.md` 收敛 28 条 / 8 类才把口径统一

## 四、哪些设计判断被证实/证伪

- **单一真源 + 门禁强制** 证实是唯一可靠办法：G15 上线前四处版本号手动同步了 9 个版本没成功过；上线后一处改动、门禁挡漂移，是**从来没错过**的模式。这条经验推广：`BLOCK_INDEX_VERSION` 独立于语言版本 也是同一逻辑（该独立就独立，该唯一就唯一，看语义边界不看直觉）
- **零第三方依赖坚守** 继续被证实：Web 可写化本以为要引框架，实际原生 JS + `fetch` 单页 16.28 KB（上限 18 KB）搞定；LSP `documentSymbol` / `signatureHelp` 手写 JSON-RPC 也搞定；**没有一处让步**
- **"先出评估结论再动手" 证实值得**：W31 Web 可写化的"要不要引框架"评估表逐条判定后自然结论"不引"，动手前就有依据，动手后无返工。这个模式建议推广到 v0.17.0 的"要不要引 LSP 跨文件符号表"决策
- **AI 桥接三臂对照 + 双数据集** 继续被证实必要：单集数字过拟合是常态，留出集才是裁判；本轮链式集又一次证明这条铁律。**没有留出集就没有可信数字**
- **命令无条件注册** 证实好：v0.15.0 W16 原设计"LSP 起来才注册命令"是坏的（挂了时命令面板里连按钮都没有，用户不知道该修啥）；无条件注册 + 命令内部自检，可读中文提示替代黑箱错误
- **W16 欠账"沿用现有 editors/vscode/ 而非新建 lsp-client-vscode/"** 证实对：原 WBS 写的新目录会产生两份扩展；沿用已有的一次到位
