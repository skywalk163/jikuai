## 三、错估的估算（逐条记）

1. **「W44 三处稳定性违规必须先清账才敢放开规则」估准了，但清账方式偏了预期**。原本设想「优先把 L1 提 stable 而非降 L2」（WBS 预案），实测发现 `税单`/`地址剖解`/`姓名拆分` 三个都可以直接提 stable，因为 `稳定性` 承诺的是**接口兼容**（元组元数与形状）而非**解析准确率**。`地址剖解` 对直辖市/无街道地址是启发式，那属于 `描述` 该讲的事，不该拿 `稳定性` 字段代偿。**教训**：先想清楚 `稳定性` 字段的语义边界，再去看谁能升级。

2. **ADR-30 §2.3 的「多候选匹配不上即留空」写死在草稿里，实测被 L13 打脸**。评测集 L13（`文本合成` 的分隔符）需要「取最近产出的 `赵分`」，而共享常量池里的 `赵分`/`赵果1` 两个都类型兼容，字面匹配「分隔符」对两者都不命中——按草稿会留空，打掉一条 v0.14 起验证过的用例。修正为「多候选匹配不上落回最近产出兜底」，`同一步骤内同型槽不复用` 才是真正「宁可留空」的地方。**教训**：新规则先跑既有钉板 bench 再定稿。

3. **W44 L3 扩容至 ≥6 未做**。原因不是没时间做 W44 stability 部分（那部分 ~2 小时清完），而是**写正确的新 L3 块需要深入 .jk 语义**——按 ADR-28 §3.6 逐块设计入参形状（`_槽名` → `_类型` → `_依赖块产出` 对齐）、给 `块.json` 挑合规依赖、`测试.jk` 补正例，任何一处错都会拖红七门中的 G11/G13+/G14。**教训**：新写块比想象的重，v0.17 计划里塞进这个应该更保守估。

4. **协议-三通道.md 从 v0.15.0 W20 起再没更新过 Web 端点章节**。W31 上线四个写端点（存/列/取/删）未同步文档；W46 又上了 PUT。审计时才发现这个静默漂移。**教训**：三通道协议文档要加个 CI 检查，Web `_POST路由` / `_PUT` 路由的键集必须与协议文档里的端点列表一致。留 v0.18.0 做。

## 四、被证实/证伪的判断

**证实**：
- 「神经 > TF-IDF」在**单块召回**继续成立（留出 R@3 神经 80% vs TF-IDF 76%，W44 元数据改动后重跑仍成立）。v0.13.0 起的结论稳。
- 「链式召回 TF-IDF 反超神经」在 W44 后仍成立（留出 88.2% vs 35.3%，差 53 pp）。v0.16.0 W27 的证伪结论**不是因为 experimental 元数据造成的偶然**。
- 「零运行时 pip 依赖」硬门槛在 v0.17.0 全部新代码里守住（`service/symbol_index.py`、`match_slot_name`、`hashlib` 版本标记都是标准库）。
- 「宁可留空不硬塞」原则在 ADR-30 落地：场景乙实测硬塞 0 次。

**证伪**：
- **扩 ADR-26 类型词表（`数` → `金额/年/月/日/比率/计数`）能消解同型槽歧义**——被 W42 数据证伪。生年/今年、生月/今月、生日/今日 三对即使细分子类型仍是同子类型冲突，占失配 100% 的 A 类里绝大多数扩词表也无解。这是本轮最重要的证伪：**避免了一次会返工 108 块类型标注的错路线**。
- 「ADR-28 §3.2 稳定性传递收窄到 L3 是因为存量违规多」——W44 实测**只有 3 处**违规，不是当年 W29 担心的规模。**教训**：收窄一条规则时把「存量违规规模」当反对理由要给具体数字，别只说「肯定很多」。
