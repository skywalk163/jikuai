# 极快 JiKuai v0.17.0 WBS · 下三个月（M10-M12）

- 起草：2026-08-10
- 周期：W37-W48（3 个月）
- 主题：LSP 跨文件符号表全量 + 粘合器同型槽歧义消解 + Web 原地更新
- 前置：v0.16.0（发布卫生归零 + 链式召回真度量 + L3 场景块 + LSP 二阶）
- 关联：`docs/BACKLOG.md`（唯一待办真源）、`docs/v0.16-复盘.md`

**周次分配偏离说明**：不是均分 4/4/4，而是 **M10 五周 / M11 四周 / M12 三周**。
理由：跨文件符号表被 v0.16.0 BACKLOG §1 明确定性为「独立大工程」，四周做全量
（索引 + 引用图 + references + rename）风险过高。多给一周，且把 rename 排在
M10 末周作为**唯一允许降级项**——若 W41 撞墙，rename 推 v0.18.0，references
与符号索引已足够独立交付。

**执行原则**

1. **W37 是准入前置**：候选 schema 缺 `导出名` 是 v0.16.0 遗留的真缺陷（命令面板
   选块插入的 `导入 <名>` 在目录名≠导出名时是错的），三通道同步修完再开新功能。
2. **符号索引不得阻塞主线程**：LSP 单请求响应时间是硬约束，索引构建必须异步/惰性，
   `documentSymbol` / `hover` / `completion` 的现有延迟不许退化。
3. **零运行时第三方依赖继续硬守**：符号索引、引用图、粘合器改动一律标准库；
   neural 依赖只准待在 `tools/ai-bridge/`。
4. **粘合器改动必须双集报数**（调优集 + 留出集），且**分任务类型报**
   —— v0.16.0 已证伪「神经 > TF-IDF」是通用结论，单块看神经、链式看 TF-IDF。
5. 改块元数据必过 G12 → **必须重跑 embeddings**（`HF_HUB_OFFLINE=1`）。
6. **`.vsix` 本轮不硬碰**：v0.16.0 代码已就绪但未真机验证，本轮不排期
   （待 Marketplace 上架需求出现再说）。BACKLOG 里保留条目，不装作已完成。

### W37 · 候选 schema 补 `导出名` · **准入前置**

**目标**：修 v0.16.0 遗留缺陷。`CANDIDATE_REQUIRED` 是 `名称/领域/层级/描述/分数/路径`，

选块插入的 `从 blocks.财务.个税 导入 个税。` 是**错的**。

**动作**
- `src/jikuai/service/schema.py`：`CANDIDATE_REQUIRED` 加 `导出名`（必需 str）。
  这是 **Breaking Change**，消费者需同步
- `candidate_from_hit` / `make_candidate`：从 `索引.json` 的 `导出` 字段取值填入
  （**不做启发式推断**，与 v0.15.0 W20 给 `层级` 定的规矩一致：取自索引不是猜）
- **三边同步**（W20 立的硬门槛，通道内零字面量）：
  - `src/jikuai/pkg/blocks_cli.py` 的 `选 --json`
  - `lsp/jikuai_lsp/server.py` 的 `executeCommand: 极快.选块`
  - `tools/web/server.py` 的 `POST /api/选` + `static/app.js` 候选卡片
- `editors/vscode/src/extension.ts` 的 `buildImportStatement` 去掉「缺失时用 `名称`
  兜底」的降级分支——字段变必需后兜底就是掩盖 bug
- `docs/协议-三通道.md` 更新候选 schema 定义 + Breaking Change 迁移说明
- 测试：`tests/test_service_schema.py` 正反各 ≥2 条；三通道各补 1 条断言 `导出名`
  存在且与索引一致；**专门造一条目录名≠导出名的用例**（用 `个税`/`缴税` 这类真实块）

**DoD**
- 三通道 `选` 响应都带正确 `导出名`；grep 不到手写字段名

### W38 · ADR-29 跨文件符号表架构 + workspaceFolders 接线

**目标**：先定架构再动手（W31 验证过的模式）。跨文件符号表是 references / rename /
codeAction 的共同底座，架构错了三个能力一起返工。

**动作**
- `docs/ADR-29-跨文件符号表.md`（新）：
  - **索引粒度**：符号 = 函数定义 / 类定义 / 类方法 / 顶层变量 / 块导出名。
    明确**不索引**局部变量（作用域内改名不需要跨文件）
  - **索引范围**：`workspaceFolders`（多根）+ `blocks_root()` + 已打开文档。
    明确单根/多根/无根三种情形的行为
  - **构建时机**：启动后**异步**全量扫一遍 + `didChange` 增量更新单文件。
    **不许同步阻塞 initialize**（否则大仓库开编辑器就卡住）
  - **失效策略**：文件改动只重建该文件的符号；跨文件引用图按「被引用方 → 引用方集合」
    反向索引，改一个文件只更新它作为引用方的那部分
  - **内存上限**：定一个符号数上限与超限行为（降级为「仅当前文件」并在
    `window/showMessage` 告知，不静默退化）
  - **与 `module_loader` 的关系**：dotpath 解析复用既有实现，不另写一份
- `lsp/jikuai_lsp/server.py`：`initialize` 解析并记录 `workspaceFolders`
  （当前只查 `blocks_root()` 与文档自身目录，见 BACKLOG §1）
- `capabilities.py`：`workspace.workspaceFolders.supported = True`；
  **同步更新 `freeze_signature()`**（W13 立的规矩）+ 冻结测试
- 测试：`tests/test_lsp_workspace_folders.py`（≥5 条）覆盖单根/多根/无根/
  动态增删根

**DoD**
- ADR-29 定稿，六个决策点都有明确结论与理由
- workspaceFolders 端到端可见；caps 冻结测试同步且绿
- 现有 LSP 用例零回归

**依赖**：W37

## M11（W42-W45）· 粘合器同型槽歧义消解 + L3 扩容

### W42 · 归因：L3 粘合率为什么只有 35%

**目标**：v0.16.0 W30 实测末步整体 0/3、槽级 35%，根因已定性为「同型 `数` 入参
无法按类型区分」。本周把**定性变成可量化的分类**，再谈解法。

**动作**
- `tools/ai-bridge/bench_glue_l3.py`（新）：把 W30 的一次性探针脚本化，
  产出**逐槽失配归因**——每个未填上的槽归类到：
  - A 类：同型不同义（`数` vs `数`，靠类型无解）
  - B 类：上游无产出（链路里确实没有能填它的块）
  - C 类：类型词表标注不够细（能靠 ADR-26 扩词表解决）
  - D 类：粘合器实现缺陷（能修）
- 对 3 个 L3 块的 20 个槽逐一归类，**给出 A/B/C/D 各占多少**
- 结论写进 `docs/ADR-30-槽绑定歧义消解.md` 的「问题定义」节

**DoD**
- 20 个槽全部归类，四类占比有数字
- 若 C+D 占比 ≥40%，说明「扩词表 + 修实现」就能显著改善，走 W43 路线 1；
  若 A 类占绝对多数，走路线 2（需求语义辅助）。**先看数字再选路线**

**依赖**：W37（可与 M10 并行）

## 风险与预案

- **W39 符号索引阻塞主线程**：这是最大技术风险。预案——若异步方案复杂度失控，
  退化为「惰性建索引：首次 references 请求时才建，建的过程显示进度」。
  **绝不接受同步阻塞 initialize**
- **W41 rename 撞墙**：已有明文降级条款，推 v0.18.0
- **W43 路线选错**：W42 的四类归因数字是选路线的唯一依据；若两条路线数字都不支持，
  如实记为「当前手段无解」并把它写进 BACKLOG，不硬做
- **W44 存量稳定性追溯引发连锁**：`工资条`/`用户档案` 是 demo 主力，
  降 experimental 会影响对外展示。预案——优先把 L1 转 stable 而非降 L2
