# 极快 JiKuai v0.18.0 WBS · 下三个月（M13-M15）

- 起草：2026-08-11
- 周期：W49-W60（3 个月）
- 主题：L3 扩容还债 + LSP 收尾 + 协议 CI + VSIX 真机验证
- 前置：v0.17.0（LSP 跨文件符号表 + 粘合器槽名消解 + Web 原地更新）
- 关联：`docs/BACKLOG.md`（唯一待办真源）、`docs/v0.17-复盘.md` §五 待办候选

**周次分配**：**M13 五周 / M14 四周 / M15 三周**。理由：M13 的 L3 扩容是 v0.17.0 承诺未做的债（写正确的 .jk 聚合块 + 过七门 + 重生成 embeddings），历史证明单块 ≥1 周；四周做四块加双集回归压力大，多给一周作缓冲。

**执行原则**

1. **W49 是准入前置**：v0.17.0 未做的 L3 扩容是承诺债，本轮头 5 周专门还，别再往后推。
2. **协议文档 CI（W55）不选做**：v0.17.0 W47 审计发现 W31 端点静默漂移一年半，教训是「文档同步不该靠人工审计」——必须有门禁。
3. **`codeAction` 三次跳过要么做要么关闭 ADR**（W53）：不许第四次跳过。跳过要另立 ADR 明写「本项目边界不做，理由 X」，进入设计边界。
4. **粘合器改动必须双集报数**（沿用 v0.16/v0.17 规矩），且**分任务类型报**。
5. 改块元数据必过 G12 → **必须重跑 embeddings**（`HF_HUB_OFFLINE=1`）。
6. **零运行时第三方依赖硬守**。neural 依赖只在 `tools/ai-bridge/`。

## 风险与预案

- **W50-W51 L3 块设计不通**（v0.17.0 W44 的真实原因）：单块无法在 1 周内完成参数收敛 + 过七门。**预案**：本轮就 3 块（下限），把剩下的推 v0.19.0。**不为凑 5 块降低质量**
- **W53 `codeAction` 走访场景发现真需求**：本轮时间够就做，不够则新增 `docs/ADR-31-codeAction设计` 定型下轮 DoD。**不许模糊搁置**
- **W55 协议 CI 检查漏路由**：CLI 子命令的表结构与 Web/LSP 不同，一个脚本三种解析。**预案**：三通道各写一个解析器函数，共用输出 diff；不追求一份通用脚本
- **W57 VSIX 装不上**：客户端版本 / marketplace 政策 / 签名要求都可能拦。**预案**：先做能装的部分（.vsix 文件生成 + 侧载安装），marketplace 上架列独立后续
