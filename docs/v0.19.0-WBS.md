# 极快 JiKuai v0.19.0 WBS · 下三个月（M16-M18）

- 起草：2026-08-11
- 周期：W61-W72（3 个月）
- 主题：块包一体 + 生态冷启动（本地闭环）
- 前置：v0.18.0（L3 扩到 7、G16 协议门禁、集成反馈落地、`.vsix` 真机验证通过）
- 起点：main HEAD = `911bfc61dc03c81b75a31fc664c8ceb7b23b317d`
- 关联：`docs/路线图-v0.19-v0.20.md`（本轮主轴与版本切分）、`docs/BACKLOG.md`（唯一待办真源）、`docs/ADR-27-第三方块注册表.md`、`docs/包管理.md`、`src/jikuai/pkg/`

**周次分配**：**M16 四周 / M17 五周 / M18 三周**。理由：M16 是「文档纠偏 + 桥接设计（ADR-32）」——设计不定死，M17 的实现就会返工，宁可多给一周把 ADR 敲实；M17 的块包桥接实现 + 造真实内容 + 端到端钉板是本轮最大不确定性（既动 installer 又动 `scan_blocks` 发现链），五周。

**执行原则**

1. **先纠偏再动代码（W61）**：路线图盘点已证 BACKLOG §3 / `包管理.md` 落后代码七个版本（注册表/发布/安装三通道其实早已能跑）。动手实现前先把文档与代码对齐，否则后续判断全建在错误前提上。
2. **ADR-32 定「最小桥接」**（W63-W64）：块与包是两套体系（`blocks.py:118-121` 自述「块不会被安装进 `极快_包/`」）。桥接只做「包当块的运输壳」——块元数据格式不动，安装器只负责落地 + 接线 `JIKUAI_PKG_ROOTS`。**不把两套模型强行捏一起**。
3. **门禁必造反例测试**（W62 的 G17，沿用 v0.18.0 W55/G16 教训）：只测正例等于没有门禁。G17 上线必用 `tmp_path` 造「文档漏写命令 / 代码漏声明 / 别名不一致」等反例逐一证明抓得到。
4. **生态内容从真实需求反推**（W66-W67）：为凑数造的第三方块没人用。从 quye 等真实集成方的实际诉求反推要造哪些块包，不拍脑袋。
5. **HTTP 分发不在本轮**：`registry.py` docstring 明写「HTTP 分发留到接入 token 鉴权 + 包签名之后」——那是 v0.20.0。本轮只做本地闭环。
6. **零运行时第三方依赖硬守**；改块元数据必过 G12 → **必须重跑 embeddings**（`HF_HUB_OFFLINE=1`）。

### W63 · ADR-32 块包格式设计 · **最小桥接定型**

**目标**：定清「块包」格式——一个包可携带块，安装器把块落到约定目录并接线 `JIKUAI_PKG_ROOTS`。兑现 ADR-27 §4 末尾旧承诺（`ADR-27-第三方块注册表.md:103`「未来若需包管理器自动安装，只需让安装器把块放到约定目录并追加环境变量」）。

**动作**
- 新增 `docs/ADR-32-块包格式.md`，定型：
  - **块包 manifest 标识**：包 manifest 里如何声明「本包携带块」（候选：`极快包.toml` 加 `[blocks]` 段或约定 `块/` 子目录）——**块元数据格式不动**，只加「这个包里哪些目录是块根」的声明
  - **安装落点**：块随包物化到 `极快_包/<名称>/`（沿用 `installer.py:104` 落点），块根是其下的约定子目录
  - **发现接线**：安装后如何让 `scan_blocks`（`blocks.py:615`）经 `extra_roots()`（`blocks.py:312`，读 `JIKUAI_PKG_ROOTS`）发现这些块。决策点：是写进环境变量，还是新增一份「已装块包 → 块根」的索引让 `extra_roots()` 合并读取？倾向后者（不污染用户 shell 环境）
  - **命名空间**：第三方块的 `命名空间` 字段（ADR-27 已留可选字段）如何从包名推断，避免与内置块重名遮蔽
- **决策点**：环境变量 vs 索引文件二选一，在 ADR 里写死理由

**DoD**
- ADR-32 定稿；「最小桥接」边界明确（块格式不动 / 安装器只管落地 + 发现接线）
- 拒绝的方案也记（为什么不把块和包模型统一）——避免下轮重议

## 风险与预案

- **块包格式设计过度**（W63）：块与包强行统一会做出四不像。**预案**：ADR-32 死守「最小桥接」——包只是块的运输壳，块元数据格式不动，安装器只负责落地 + 接线发现。W64 桩验证不通就回炉，不带病进 M17
- **W64 发现链走不通**：环境变量/索引方案在真机上接不上 `scan_blocks`。**预案**：W64 就是拦这个的，走不通即回 W63 改 ADR，不推到 W65
- **生态冷启动造的是玩具**（W67）：凑数的第三方块没人用。**预案**：从 quye 等真实集成方需求反推；宁可就 3 个真需求块包，不硬凑 5 个
- **命名空间遮蔽**（W69）：第三方块与内置块重名污染检索。**预案**：ADR-27 已留 `命名空间` 可选字段，W66 打包名命名空间，W69 专项验证隔离
- **W67 改块元数据漏跑 embeddings**：块入库检索不到。**预案**：每周复盘 checklist 硬卡（`HF_HUB_OFFLINE=1` 重跑）
