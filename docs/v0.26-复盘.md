## 一、被证实的判断

### 1. 两层架构（引擎层通用 + 口径层精确）站住了

ADR-40 §3.3 在四个备选里选了「引擎层 `列表<字典<字符串,任意>>` + 口径层精确元组」。
三个月做完的结果：**25 个块没有一个报出实现 bug**。W145 人工验收里所有报错都是块
**按口径主动拒绝**，不是算错——对照实验里那句 `JiKuaiError：表载入：CSV 文件不存在：
actual_quantity` 就是 `表载入` 的正确行为。

`连接` 是 WBS 点名的「本轮最高风险项」（W135 给了整周，理由是块库零关系代数、
一错则上面所有口径块的数都是错的）。真数据上 1:1 行数守恒成立：Q_PUB_005 的 L003 子集
联表后白/夜班各 181 行合计 362 = 筛出的实绩行数；Q_HID_004 全表联表后各 1448 行合计
**2896** = ADR-40 §4.2 的冻结值。**风险预算押在这里是对的**。

### 2. 「空 ≠ 0」这条纪律是真有用的活样本，不是洁癖

W130 冻结空值策略时写的是一句原则。本轮它变成了可量化的东西：

`fact_orders.delay_days` 里 **57 个空**（未交付）与 **977 个 0**（按期交付）并存。
整表延期均值——

- 非空口径：2213 / 1793 = **1.234244**
- 把未交付填 0：2213 / 1850 = **1.196216**

**被污染下拉 0.038028。** 这个数不大，但它的方向是系统性的：越是交付差的时期未交付单越多，
填 0 就把延期压得越低。**一个「看起来只是默认值」的选择会让指标朝着掩盖问题的方向偏。**

空值纪律在三处独立复现：`延期排行` 排除 57、Q_HID_005 `延期汇总` 排除 57、
`停线汇总` 缺测 0（`downtime_minutes` 零空值，与 ADR-40 §4.3 一致）。

### 3. 「描述互相点名」让口径可审计，在 W145 真起了作用

W140 定的规矩是双块的 `描述` 必须点名对方。它在 W145 兑现的方式不是「文档更好看」，
而是**写方案的人被迫两个口径都跑**：Q_PUB_005 四个数一起报（白班加权 0.969950 /
白班均值 0.970209 / 夜班加权 0.849740 / 夜班均值 0.850028），Q_PUB_004 现成列与重算
两条线互相校验（191.095 / 191.087）。

**互相点名把「选口径」这个动作从隐式变成显式**——看见描述里写着「还有另一个口径」的人，
很难只跑一个然后当结论。

### 4. 外键完整性与主键唯一性：全部零问题

W139 的 `质量体检` 块跑出来：`schema_relationships.csv` 里 **11 条真外键孤儿行数全 0**，
8 张表**主键重复数全 0**。W139 DoD 那句「若不为 0 要写进 ADR-40 §4 而不是悄悄兜掉」
这次没有需要写的例外。

值得记的是**做法**而不是结果：`tests/test_v0_26_0_w139_质量体检.py` 从
`schema_relationships.csv` **现读**这 11 条关系，不在测试里手抄——数据集换了会当场红。

### 5. `赛题/` 不进产物，从推理升级成实测

W130 之前这条只是照 `MANIFEST.in` 推理（只 `recursive-include src/jikuai/stdlib`）。
本轮真跑了命令：wheel 431 条目含「赛题」= 0，sdist 667 条目含「赛题」= 0，G20 通过。
`MANIFEST.in` 与 `.gitignore` 都不用动。

顺带实测出的附带事实反而更要紧：**sdist 收了 `tests/`（100 条目）但没收 `docs/` 与
`scripts/`**。所以引用 `赛题/chatbi/数据集/` 的测试会随 sdist 发行、而它要读的数据集不会——
这类测试必须自带「数据集目录不存在就 skip」的守卫，否则从 sdist 装出来的环境里会假红。

## 二、被证伪或修正的判断（本轮重点）

### 1. 「三个现成比率列」→ 实测只有两个

**当初为什么那么想**：ADR-40 §5 初稿把「三处口径分歧点」和「三个现成比率列」写成了
一一对应——三处分歧、三个比率列，结构上很顺。

**实测把它推翻在哪一步**：W138 建语义层要给「是否现成比率列」打标，逐表扫表头时发现
`fact_quality_defects` 的列是 `defect_id, defect_date, line_id, model_id, process,
defect_type, defect_count, severity, rework_status`——**没有 `defect_rate`**，
全数据集也没有第三个 `_rate` / `_per_` 形态的列。

**最难看的一点是它自己打自己的架**：§5.3 从初稿起就写着缺陷率「无现成列」。
所以这不是「数据集与文档不一致」，是**同一篇 ADR 的导语与小节互相矛盾了一整轮没人发现**——
导语是概括句、§5.3 是细节句，写的时候在不同的注意力档位上。**概括句是最容易带错数字的
地方，因为它读起来不像一个需要核对的断言。**

分歧点仍是三处（达成率、单车电耗、缺陷率），G22 第 3 条不受影响。修正框记在 ADR-40 §5。

### 2. 「三处分歧点各出两个块」这条门禁规则不成立（W145 点名重点之一）

W130 冻结口径时写的是「**每处两个块**，各自声明」，G22 第 3 条初稿也照抄「各有两个块，
缺一红」。**做到 W144 才发现第三处不该那样判。**

推翻它的是缺陷率的实测差值：

| 口径 | 2026-06 数值 |
| --- | --- |
| 先按维度+窗口汇总分子分母再相除（采纳） | **0.050550** |
| 先算行级比率再平均（另一侧） | **0.032218** |
| 差 | **57%** |

根因是两表粒度不同：缺陷表 2992 行带工序 / 缺陷类型 / 严重度三维，产量表 2896 行——
**行级比率根本对不上**，这不是「另一种看法」，是错的。

**所以「各出两个块」这条规则本身在这里有害**：为一个已知错误的口径造块，等于把错口径
升格成「可选口径」，正是 AGENTS.md 第四节要防的「兄弟能力缺位」——照着用会跑通、结果是错的。

G22 第 3 条最终改成**三处不同判法**：

- **达成率 / 单车电耗**：两侧口径**都对** → 按「双块」判（两侧块在位 + 各自描述含口径自述
  + 互相点名对方）。
- **缺陷率**：另一侧是错的 → 按「**单块 + 描述显式否决另一侧 + 分子侧姊妹块在位**」判。
  `缺陷率` 描述要含「先汇总后相除」（采纳口径）+「行级比率」（点名另一侧）+ 一句明确否决，
  且 `缺陷汇总` 在位并被点名。反例测试证明抹掉否决句就红。

**教训**：门禁规则不能从「结构对称」推出来。**「有几处分歧」是业务事实，「怎么落地」
取决于另一侧是不是也对**——这两件事被初稿混成了一件。§5 的标题仍叫「三处分歧点」也是这个原因。

### 3. 三处口径分歧点的实测差值（W145 点名重点之一）

| 分歧点 | 默认口径 | 另一侧 | 实测差值 | 落地形态 |
| --- | --- | --- | --- | --- |
| 平均达成率 | 加权 `sum(actual)/sum(planned)` | 行级算术平均 `mean(achievement_rate)` | L003 白班 **0.969950** vs **0.970209**、夜班 **0.849740** vs **0.850028**（本数据集只差万分之几）；块自测最小例（5/10 与 100/100 两行）差 **>0.2** | 双块互相点名 |
| 单车电耗 | 现成列 `energy_per_vehicle` | 按 `line_id+model_id+日期+shift` 关联重算 | 逐行 **2896/2896 等值**（最大绝对差 0.005 = 现成列两位小数舍入，最大相对差 **5.4e-5**，零漏配）；**按产线聚合后分叉**：L003 **+0.6126**、L008 **−0.1247** | 双块互相点名 |
| 缺陷率 | 先汇总后相除 | （错）先算行级比率再平均 | 2026-06 **0.050550** vs **0.032218**，差 **57%** | 单块 + 显式否决 + `缺陷汇总` 在位 |

**达成率这一处有个必须诚实说明的地方**：本数据集上两口径只差万分之几（L003 白夜班各 181 行、
班内产量分布均匀），结论方向也不受口径影响（夜班低约 0.12）。**所以「口径分歧很重要」这个
主张在本数据集上并不由这一处支撑**——它由缺陷率那 57% 支撑。演示时拿达成率讲口径分歧
会讲得很弱，要拿缺陷率讲。

### 4. 「单车电耗两口径等值」不是重算块写错——但它同时又会分叉

W141 的 DoD 写的是「若完全相同，说明重算块写错了或数据生成时口径一致，两种情况都要
查清并记档」。查清结果是后者：`energy_per_vehicle` 恒等于 `electricity_kwh` / 同键
`fact_production_actual.actual_quantity`，**数据生成时口径就一致**。

**但按产线聚合后确实分叉**：L003 **+0.6126**、L008 **−0.1247**。

这两句话看着矛盾，其实不矛盾：逐行等值是「每行的商相等」，聚合分叉是「行级平均 vs
比值聚合的顺序差异」——同一个 Simpson 类现象。**关键证据是 L008 那个负号**：
如果分叉来自现成列的两位小数截断，偏置只会单向；一正一负说明它来自聚合顺序，
不是舍入。

**这一条已经立了断言钉住**，因为它天然像 bug：后人看到「文档说等值、我这里跑出来不等」
会去「修」重算块，而正确行为恰恰是分叉。**记档的目的不是解释现象，是防止有人把正确的
东西改坏。**

### 5. 引擎层「无类型图保护」这个代价，本轮真的咬到人了（W145 点名重点之一）

ADR-40 §3.1 写得很清楚：`值类型: 任意` 在 `glue.py` 的 `type_feeds` 双向放行，
**类型图在引擎层不起作用**，正确性只靠单测。WBS 执行原则 2 还专门加了一句
「不许拿『粘合器会检查』当理由省测试」。

**这句话在 W130 是一句纸面免责声明。W145 的对照实验把它变成了实测。**

拿 Q_PUB_001（最简单的 3 步链）去掉全部 `参数`、只留同一批 `共享` 常量，`jk 块 组` 给出：

```jikuai
定义赵果1=读表(赵产量列)。
定义赵果2=截期(赵果1 赵产量列 赵车型维 赵六月末)。
定义赵果3=计产(赵果2 赵产量列 赵车型维)。
```

三行实参**全错**：文件路径槽拿到 `"actual_quantity"`、`起日` 槽拿到列表
`【"model_id"】`、`维度列` 槽拿到字符串。运行期死在
`JiKuaiError：表载入：CSV 文件不存在：actual_quantity`（行 15 列 9）。

**最严重的不是错，是错的方式**：

- **没有一个 `?` 占位**
- **没有一行「类型图未能自动链上」的拒绝理由注释**

也就是说粘合器在这里既没推对、**也没拒绝**，是**静默错绑**。链路是：`共享` 常量在
`glue.TypeGraph.plan` 里一律入池为 `任意` → `任意` 双向放行 → 每个字符串常量对每个形参
都「类型兼容」→ 多候选消解退回「最近产出优先」→ 按池子倒序随便挑一个。制造域形参又
清一色是 `字符串` / `列表<字符串>`，`match_slot_name` 的槽名字面匹配对
`赵产量列` ↔ `日期列名` 这种也匹配不上。

AGENTS.md 四·6 承诺的是「推不出来就落 `?` 占位 + 写拒绝理由」。**在引擎层这条承诺不成立**，
因为拒绝的前提是类型图能判定不兼容，而 `任意` 让它永远判兼容。

**连带推翻一个漂亮数字**：W145 归档里「`?` 占位 0 次 / 15 份方案退出码全 0」看起来像
自动推链的成绩，实际上——**15 份方案共 124 步的 `参数` 全部是人手写的**
（`赛题/chatbi/产出/README.md` §三），自动链式一次都没被真正依赖。
**「零占位」在这里不是能力指标，是「没用过那条路径」的副作用。**

这也直接决定了 v0.27.0 规划器的设计约束：**必须自己把每一个实参写死，不能指望
`--自动链式`**。若要修粘合器，方向是让 `共享` 携带声明类型，或者至少让「多个 `任意`
候选竞争同一槽」这件事进拒绝理由。

### 6. `delivered_quantity` 未交付订单最小值是 4，不是 10

语义层初稿写 10，W142 复测是 **4**。小错，但它是「凭印象填元数据」的典型——语义层是
溯源说明的数据来源，写错的数字会被原样报给使用者。

## 三、必记单点：词法原子性这道只验了「导出名」，漏了「块目录名」

**这是本轮最该记的一条。**

WBS 执行原则 7 是 W133-W137 的实测教训沉淀下来的：「分配导出名必须过两道，不是一道——
全局唯一（G13）与词法原子」。它救了 `归月`/`归旬`/`归组`/`择列`/`列排` 五个名字。

**但这条原则只说了「导出名」。** W140-W142 三个块**全部栽在块目录名上，一个都没栽在
导出名上**：

| 原定目录名 | 切分 | 肇事字 | 改后 | 导出名 |
| --- | --- | --- | --- | --- |
| `达成率加权` | `达成率`(IDENT) + `加` + `权`(IDENT) | `加` 是 **VERB** | `达成率权重` | `达权`（未动） |
| `班次对比` | `班`(IDENT) + `次` + `对比`(IDENT) | `次` 是 **KEYWORD**（循环） | `班间对比` | `班比`（未动） |
| `单车电耗现列` | `单车电耗现`(IDENT) + `列` | `列` 是列表构造 **VERB** | `单车电耗现成` | `车耗现`（未动） |

原因是目录名会出现在 `从 blocks.制造.<目录名> 导入 <导出名>。` 的**点分路径段**里，
必须过 `check_module_segment_atomicity`。切成多 token 的直接后果是 `ParseError`——
**块写得再对也导不进来**。

**三处的导出名一字未动，调用方完全无感。** 这就是它容易漏的原因：原则 7 盯的是「调用名」
这个显眼的东西，而真正的雷在「文件系统路径」这个看起来跟语言无关的地方。

已补进 WBS 执行原则第 8 条：**分配块名要目录名 + 导出名两个都验，验完再动手写文件。**

另有一条边界要一起记，否则下一轮会误以为「所有名字都要过原子性」：`块.json` 的
`输入[].名` **目前不过**原子性门禁（既有 `维度列` / `度量列` 就切成两 token 且全绿），
但仍建议自律取原子名。

**收尾时的 1 failed 也归在「必记」这一栏**：`test_契约脚本_json_输出可解析` 红，
根因是 G12 的向量索引停在 112 块而块库已经 137 块。重跑 embeddings 后 G10-G22 全绿、
退出码 0。这是 WBS 执行原则 5（每批块落地后立刻刷索引 + embeddings）没被严格执行的
直接代价——它也是项目自己记录的最常见返工原因。

## 四、评测集四档实测数字（W143，如实报、未调参）

按 AGENTS.md §六的既有纪律分档，不新造规矩。

| 档 | 条数 | 数字 |
| --- | --- | --- |
| **调优集** | 15 | K=10 块覆盖率 **0.2711** / 完整命中率 **0.0** / Recall@1 0.2667 / Recall@3 0.6 / MRR 0.4606 |
| **留出集**（只跑一次，不看 miss 明细） | 5 | K=10 块覆盖率 **0.2824** / 完整命中率 **0.0** / Recall@1 **0.8** / Recall@3 0.8 / MRR 0.8 |
| **远离档**（负例） | 10 | 拒答率 **0.0%**、制造块占位率 0.2 |
| **近边缘档**（负例） | 8 | 拒答率 **0.0%**、**兄弟块诱骗率 0.625**（8 条里 5 条 top-K 直接返回兄弟块） |

三点必须写清，否则这张表会被读成假的：

**1. 完整命中率恒 0 是真缺口，不是 bug，也没开后门。** 根因很具体：每条 `期望` 都含
`表载入`（任何链路的第一步都要先把 CSV 载进来），而问句从不提「载入」——问的是
「6 月各车型总产量」。TF-IDF 词面路径抓不到一个问句里根本不出现的词。
**我们没有把 `表载入` 从期望里删掉来把这个数做上去。**

**2. 留出集 Recall 反而高于调优集**（Recall@1 0.8 vs 0.2667）。这不是过拟合反转，
是 hidden 题的指标词与块名词面更贴。**留出集只跑了一次、没看 miss 明细**，
所以这个数只能当观察，不能当「泛化更好」的结论——5 条的样本量本来也支撑不了那种结论。

**3. 近边缘档的兄弟块诱骗率 0.625 是本轮最该警惕的数字。** 拒答率 0.0% 是已知设计
（`retrieval.py` 无阈值、永远返回 top-K，AGENTS.md 第四节已写明四轮实测证伪了所有

## 七、遗留（→ v0.27.0）

W145 产出的 8 条能力缺口，按严重度排。**全部只是报告，本轮未改任何块。**
明细见 `赛题/chatbi/产出/README.md` §六，已登记 BACKLOG §12。

1. **无「时间窗口对比 / 环比 / 基线偏离」块**（4 题踩到，优先级最高）。所有
   「是否上升 / 是否异常 / 是否偏高」类问句都落在这里。
2. **自动推参在制造域是静默错绑**，规划器必须写死每个实参；若修粘合器，
   方向是让 `共享` 携带声明类型。
3. **口径块的元组输出接不上引擎层的列表输入**，每次要人写 `赵果N【0】` 拆包（本轮 2 处）。
4. **`窗口` 只能切单个闭区间**，缺「补集 / 多区间」——做基线对比时只能取 01-01～06-09，
   把 06-25～06-30 那 6 天丢在外面。
5. **绝对量 vs 比率的排名混淆无块层防护**（L005 总电耗第 1、单车电耗第 2；
   L002 总电耗第 3、升幅第 1）。
6. **分组结果不能直接排序**（`延期汇总` / `缺陷汇总` 出元组 + 按维度键升序）。
7. **时间词锚点列无单一真源**（`order_date` vs `planned_delivery_date` 的选择会改变
   未交付单数：口径 A 得 0、口径 B 得 9）。本轮两个口径结论没翻转，**但这是运气**。
   语义层应为每个业务词登记默认锚点列。
8. **`邻期关联` 一对多致右表重复计数**（Q_HID_002 邻期窗口内 L002-焊装 1599，
   真实值 465+97=562）。结构可比、**绝对值不可用**。
