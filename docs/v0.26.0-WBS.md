**周次分配**：**前置清账 3 周（W130-W132）/ 引擎层 5 周（W133-W137）/
语义层与口径层 5 周（W138-W142）/ 评测与门禁 3 周（W143-W145）**。

引擎层给 5 周的理由：连接算子是本轮唯一没有任何现成参照的东西（块库零关系代数），
且它一错，上面所有口径块的数都是错的。宁可在这里多花一周把反例测试写足。

**执行原则**

1. **口径先定，代码后写**。ADR-40 §5 那三个分歧点在 W130 就定死，不许边写边想。
   涉及比率的块，先写测试再写实现。
2. **引擎层不假装被类型图守着**。ADR-40 §3.1 已写明 `值类型: 任意` 会让 `type_feeds`
   双向放行。引擎层的每个算子都必须有独立单测，**不许拿「粘合器会检查」当理由省测试**。
3. **本轮不碰 LLM，不碰 UI**。W145 的验收方式是人手写 `方案.json` 跑 CLI。
   规划器在 v0.27.0——把 NL 那一层挪后，是为了先让「口径层是对的」这件事独立成立。
4. **新门禁必造反例**（沿用 v0.18.0 W55 / v0.19.0 W62 规矩）：G22 上线必用 `tmp_path`
   造反例逐一证明抓得到，不少于 3 类。只测正例等于没有门禁。
5. **每批块落地后立刻刷索引 + embeddings**。忘刷索引是项目自己记录的最常见返工原因
   （`贡献指南.md`）。本机离线设 `HF_HUB_OFFLINE=1` `TRANSFORMERS_OFFLINE=1`。
6. **零运行时第三方依赖硬守**。CSV 走 Python 标准库 `csv` 的 sidecar，不引 pandas。
7. **分配导出名必须过两道，不是一道**（W133-W137 实测教训）：**全局唯一（G13）**
   与 **词法原子（`check_export_atomicity`）**。只 grep `索引.json` 查唯一性会派出
   根本无法导入的死名——`归月`/`归旬`/`归组` 的 `归` 是 reduce 副词（ADVERB），
   `择列`/`列排` 的 `列` 是列表构造动词，五个名字全被切成多 token、无法作导出名。
   本轮实际落地名：`读表 表况 筛行 择字段 定序 摘前 联表 维聚 截期 标月 标旬 邻联`。
8. **词法原子这道对「块目录名」同样成立，而且更容易忘**（W140-W142 实测教训，三个块
   全栽在这里、一个都没栽在导出名上）。目录名会出现在 `从 blocks.制造.<目录名> 导入
   <导出名>。` 的**点分路径段**里，必须过 `check_module_segment_atomicity`：
   - `达成率加权` → `达成率`(IDENT) + `加`(**VERB**) + `权`(IDENT) → 改 `达成率权重`
   - `班次对比` → `班`(IDENT) + `次`(**KEYWORD**) + `对比`(IDENT) → 改 `班间对比`
   - `单车电耗现列` → `单车电耗现`(IDENT) + `列`(**VERB**) → 改 `单车电耗现成`

   三处的导出名（`达权`/`班比`/`车耗现`）全部原样保留，**调用方无感**。所以分配块名时
   要**目录名 + 导出名两个都验**，验完再动手写文件。另注：`块.json` 的 `输入[].名`
   目前**不过**原子性门禁（既有 `维度列`/`度量列` 就切成两 token 且全绿），但仍建议
   自律取原子名。
