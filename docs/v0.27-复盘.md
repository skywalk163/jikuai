## 一、被证实的判断

### 1. 「候选必须带 `输入槽` 与 `输出类型`」——但证据比想象的弱，要说清

上下文包给每个候选带 `输入槽[{名,类型}]` 与 `输出类型` 之后，15 份录像回放
**组失败 0 份、通过的 11 份组跑全通**。

**但这不证明「LLM 现在写得出实参了」**：那 15 份录像是把 W145 的**人工**方案转录成回填
信封（`模型: 人工·v0.26.0 W145`），本轮**一次真模型都没调**。它证明的是两件较弱的事：
协议**承载得下**这些信息，以及「校验器 → 组 → 跑」这条确定性链路对一份给定回填的处理
可复现。真模型的数字要等有端点时补，别把这条读成已验证。

### 2. 拒答判据用「词表覆盖」而不是分数阈值，仍是对的

远离档 10 条拒下 5 条（50.0%），全程零阈值、零 AUC 依赖。第五次实测没有推翻前四轮的结论
（分数路线 AUC 0.52–0.67）。词表路线的失效模式是**可解释的**（业务词字面命中就判覆盖），
比一个说不清为什么拒的阈值好排查。

### 3. 「录像回放是端到端评测的唯一可行解」站住了

CI 在 FreeBSD、无外网、无 API key。真调模型不可复现，mock 掉模型等于 mock 掉被测对象。
录像回放两头都躲开了：判定一致率 **100%**、耗时 ≈ 8.5s、可进门禁。**绿的判据是「判定与
登记相符」而不是「全部通过」**——15 份里 4 份登记为该拒且真被拒。这个设计让台架在补块或
改规则时会当场红，而不是悄悄变绿。

### 4. 门禁要「静态 + 行为」两套断言（G23 的核心判断）

G23 造了 6 类反例，其中**「把 `validate_filled` 改成恒返回空列表」只有行为断言抓得到**
（函数在、调用点在、静态全绿）；而**「摘掉 `_规则3` 调用」只有静态断言抓得到**（六个合成
场景里那条规则的拒因恰好被别的规则盖住时就漏）。两套缺一都有盲区。这是 v0.22.0 主教训
「守卫绿≠守卫在守」第一次被做成双向锁。

## 二、被证伪或修正的判断（本轮重点）

### 1. 「规划器层的拒答能替 agent 挡住近边缘」——证伪

| 档 | 用例 | 规划器层拒答率 | 兄弟块诱骗率 |
| --- | --- | --- | --- |
| 远离（整类能力不在库里） | 10 | **50.0%** | — |
| 近边缘（口径差一档） | 8 | **0.0%** | **62.5%** |

近边缘档 **一条都没拒下**，兄弟块诱骗率 **62.5% 与检索层逐位相同**。根因不神秘：覆盖判定
是业务词的**字面子串匹配**，`中位达成率` 里有 `达成率`、`单车水耗` 里有 `水耗`，必然判
「覆盖」。

**这条的代价是文档风险而不是代码风险**：多一层带「拒答建议」字样的东西，最容易被读成
「现在有安全网了」。所以 W161 在 AGENTS.md 第四节明确写了三句反话——它拦整类缺位、
拦不住口径差一档；它拒下的那部分**不改变检索层仍是 0.0%**；覆盖判定只登记制造域 42 条
业务词，另六域一律判未覆盖是**作用域边界不是能力缺失**。

### 2. 「默认 `top=8` 的候选白名单够用」——证伪，且暴露出规则 2 与召回耦合

规则 2 要求回填的块名逐字取自上下文包 `候选`。实测正确方案用到的块在 TF-IDF 排名里
**最深到第 89 名**（`Q_HID_004` 的 `表载入`——问句从不说「载入」，词面抓不到），于是：

| K | 期望块覆盖率（调优/留出） | 白名单可承载率 |
| --- | --- | --- |
| 8 | 20.7% / 25.4% | **0.0% / 0.0%** |
| 20 | 50.6% / 41.8% | 0.0% / 0.0% |
| 40 | 80.6% / 72.8% | 30.0% / 20.0% |

`top=8` 下白名单**装不下任何一份**正确方案。处理办法是把两件事拆开报：回放本身用全库当
白名单（把规则 2 从瓶颈位置挪开，测的才是规则 1/3/4/5），另把「装不装得下」单独量成
`白名单可承载率` 分档公开。**不合成一个好看的总分**。

### 3. 「期望块完整命中率恒 0」——修正

v0.26.0 记的是恒 0。实测 K=8/20 才是 0，**K=40 时调优集 53.3%、留出集 20.0%**。此前的
「恒 0」是在小 K 下观察到的，当成了结构性缺陷。缺口是真的（`表载入` 这类词面抓不到的
步骤），但没有那么绝对。

### 4. 成功度量未达成：5 道留出题 **3 通过 / 2 被拒**

WBS 的 DoD 写「5 道留出题在没看过 miss 明细的前提下答对」。实测
`Q_HID_001/002/004` 通过并跑通，**`Q_HID_003`、`Q_HID_005` 被规则 3 拒**——两条都命中
ADR-40 §5.4「时序对比参照系」分歧点，而方案里 `窗间对比` / `基线偏离` 一个都没选。

**关键区别：这 2 条是录像陈旧，不是能力缺失。** §5.4 的两块在本轮 W153–W155 已经落地；
录像是 W145（v0.26.0，那时两块还不存在）转录来的，方案里自然没选边。修法很轻——补一条
`模型: 人工·v0.27.0 口径` 的新录像、显式选一侧、清单登记 `期望判定: 通过`，旧录像原样
留着继续咬人。**本轮没做，挂到 v0.28.0。** 所以本轮的诚实结论是：

> 成功度量 **3/5 达成**。缺的 2 条不是「答不出」，是「录像还没按新块重录」。

不改成 5/5 的原因：把陈旧录像改成能过，和「为了让指标好看而改期望」只隔一层自我说服。
留着这个 3/5 比一个自己给自己补上的 5/5 有用。

## 三、必记单点（踩过的坑，按会不会再踩排序）

1. **`UnicodeEncodeError` 不是 `OSError`**。HTTP 请求行与头值必须 ASCII（CVE-2019-9740
   的防线）。URL 带中文路径、token 带中文时 `http.client` 抛的是 `UnicodeEncodeError`
   （`ValueError` 子类）。任何「把网络失败收敛成可读理由」的 except 只写 `OSError` 就会
   漏，用户吃裸 traceback。
2. **`bench_chatbi.py` 那套导入期 `_reconfigure_utf8()` 不能抄进会被测试导入的模块**。
   它换掉 `sys.stdout`/`sys.stderr`，会把 pytest capture 的 tmpfile 关掉，整轮 pytest 在
   teardown 抛 `ValueError: I/O operation on closed file`——**一个测试都跑不了**。同理
   bench 为读赛题 CSV 而 `chdir`，必须 `finally` 还原（pytest 在进程内调它）。
3. **`tools/ai-bridge/` 里有个 `select.py`**。`planner.py` 会把自身目录 `insert(0, ...)`
   到 `sys.path`，压在标准库前面就遮蔽 `select`（Linux 上 `subprocess` 等要它）。删不行
   （`import glue` 还要用），**挪到末尾**两件事同时满足。G23 与 `bench_planner.py` 都这么
   处理。
4. **协议字段名的静态扫描要扫「键位」不扫全部字符串**。`planner.py` 的 `main()` 里
   `add_argument('需求')` 是 argparse 位置参数名，与协议字段撞名却不是协议使用；按全字符串
   扫会假红，而假红会逼人给门禁开豁免注释——那是门禁死亡的开始。同理 `分歧点表` 的键 `名`
   与 `SLOT_REQUIRED[0]` 撞名，连它的循环变量一起豁免。**撞名是事实，混成一套才是病。**

## 四、估算偏差

- **G23 第 4 条比预期贵**：估「秒级」，实测 **≈8.5s**（15 份录像逐份过校验器 → 组 → 跑，
  还要读 8 张 CSV）。仍决定串进主门禁而不学 G20 只打提示——v0.25.0 W129 / v0.26.0 W144
  两次实证「新门禁没在 CI 真跑过就不算落地」，8 秒换这个是划得来的。
- **`planner.py` 的字面量扫描比预期难**：原以为「扫所有等于协议字段名的字符串」就行，
  实际撞上三组非协议键常量（`_I*`/`_Y*`/`_S*`）+ `分歧点表` + argparse 参数名，最后落成
  「扫键位 + 豁免名单 + 豁免循环变量」三段式。
- **三臂对照本轮不跑（判断，不是遗忘）**：新增段是防误读注解 + `bench_planner` 已跑出的
  确定性数字，不是需要人臂验证的说服性选块指导；跑它要人开三个会话跑 105 次 agent，几乎
  翻不了第六轮既有结论。降级挂 v0.28.0，**并入条件**：下次真改第四节的选块指导语句时连
  本次一并跑。记档在 BACKLOG §12.4，不悄悄丢。
