## 本轮范围（已拍板，五个岔路）

1. **LLM 只选口径，不算数**。NL 理解交给 LLM，`组`/`跑` 仍是确定性的。
2. **双模式**：默认出**规划上下文包**（离线、确定性、CI 真跑）；`--模型` 可选接外部
   端点做端到端 demo。两条路径共用同一个回填校验器。
3. **范围 = 内核 + §12.3 高优两条**。图表块 / 运营日报 / 溯源面板 / 等价 SQL 导出 /
   数据质量检查 **推 v0.28.0**；§12.3 中优六条顺延。
4. **「实参写死」双管齐下**：规划器侧强制（校验器）+ 粘合器侧治根（`共享` 带类型）。
5. **缺口块出双块**：`窗间对比` + `基线偏离`，互相点名，沿用制造域双块范式。

## 本轮明确不做

- 语言级「表」一等类型（ADR-40 §3.3，留 v0.29.0 后另立 ADR）
- 把引擎层纳入类型图（`值类型: 任意` 的退化是已知代价，不假装它被守着）
- 真 Text-to-SQL（等价 SQL 导出在 v0.28.0，且只作「展示查询过程」）
- 在检索层做分数阈值拒答（**四轮实测已证伪，本轮 `retrieval.py` 一行不改**）
- 把规划器塞进 wheel（见执行原则 3）

**执行原则**

1. **拒答只做「词表覆盖判定」，不做分数阈值**。四轮实测已证伪基于分数的自动拒答
   （近边缘档各置信信号 AUC 仅 0.52-0.67，能拒掉 94% 无覆盖的阈值会误杀 64% 真命中）。
   规划器层的拒答判据是「语义层业务词是否登记 + 候选块是否自报对应口径」，与分数无关。
   **任何想复活分数阈值的改动，先去读 `bench_retrieval_reject.py` 的四轮结论。**
2. **指标变丑不许回退**。W152 预期让 `bench_glue.py` 的自动链式命中率下降——那是把
   静默错绑变成显式拒绝的**正确代价**。必须如实报改前/改后两套数字。
   v0.22 的主教训是「守卫绿 ≠ 守卫在守」，这一条是它的反面：**数字丑但真**，
   优于数字漂亮但错绑。
3. **规划器落 `tools/ai-bridge/planner.py`，不进 wheel**。理由不是偷懒：`glue.py`
   本来就在 `tools/ai-bridge/`、不进 wheel（`MANIFEST.in` 只
   `recursive-include src/jikuai/stdlib`），`blocks_cli._glue()` 找不到就抛
   `BlockError('组/跑 需要仓库内的 tools/ai-bridge/')`。规划器依赖 `组`/`跑`，
   **不可能比它的依赖可用性更强**。副作用：不动 `MANIFEST.in`、不动
   `块背衬PY数`、不碰 G20。
4. **LLM 不可复现 ⇒ 录像回放**。CI 在 FreeBSD、无外网、无 API key。真调模型只在本机
   人工跑并归档；CI 只回放 `tools/ai-bridge/规划录像/` 里录制的回填 JSON，跑
   「校验器 → 组 → 跑」。**端到端评测的确定性靠录像，不靠 mock 掉校验器。**
5. **新门禁必造反例**（沿用 v0.18.0 W55 / v0.19.0 W62 / v0.26.0 W144 规矩）：G23 上线
   必用 `tmp_path` 造反例逐一证明抓得到，不少于 3 类。只测正例等于没有门禁。
6. **协议字段只从 `schema.py` 常量取**。上下文包是新协议结构，字段名一律进常量，
   通道里出现手写字面量视为违约（W20 起 grep 把关）。新常量要同步
   `docs/协议-三通道.md`，否则 G16 双向一致会红。
7. **分配块名必须「目录名 + 导出名」两个都验**（v0.26.0 W140-W142 教训：三个块
   **全栽在目录名上**）。目录名进 `从 blocks.制造.<目录名> 导入 <导出名>。` 的
   点分路径段，必须过 `check_module_segment_atomicity`；导出名另过 G13 全局唯一 +
   `check_export_atomicity`。**验完再动手写文件。**
8. **加块必刷索引 + embeddings，加/减 sidecar `.py` 必同步 `块背衬PY数`**。后半句是
   v0.26.0 首推双红的直接原因（14 → 35 没同步，本机 G10-G22 全绿抓不到，因为 G20 要
   `python -m build`）。当前常量值 **35**，在 `scripts/check_wheel_contents.py:46`。
9. **留出档只跑一次、不看 miss 明细**。`评测集-chatbi-留出.json` 5 条与
   `评测集-留出.json` 25 条同一条纪律。规划器的端到端数字同样分档报，
   **只报调优集等于自欺**。

### W157 · 回填校验器 `planner.validate_filled()`

**目标**：把「实参必须写死」变成协议级强制，比 `?` 占位更早一道闸。

**动作** —— 五条硬规则，任一不过就拒并给可读理由：
1. 每步 `参数` **必填**，且长度等于该块输入槽数。缺一个就拒。
2. 块 / 领域 / 导出名必须来自上下文包 `候选`（白名单，防幻觉块名）。
3. 分歧点两侧同时出现 → 拒；问句命中该口径而一侧都没选 → 拒。
4. 产物必过 `schema.validate_plan`。
5. `--严格` 下：无声明类型的共享常量不许喂精确形参（配合 W151）。

**DoD**
- **五条各有独立反例测试**（缺参数 / 幻觉块名 / 双侧口径 / 协议多余字段 /
  裸 `任意` 喂精确槽），共 ≥5 类反例
- 拒绝理由是**可操作的**（说清缺哪个槽、该填什么类型），不是「校验失败」

### W158 · CLI `jk 块 规划` 与 `jk 块 问`

**目标**：两条命令落地，退出码守既有约定（`0` 成功 / `1` 输入错误 / `2` 执行期报错）。

**动作**
- `_ALIASES`（`blocks_cli.py:78-90`）加 `规划`/`问` + 英文别名；`_DISPATCH`
  （`1181-1191`）加两个 `_cmd_*`；新函数签名 `List[str] -> int`。
- `jk 块 规划 "问句" --json` → 上下文包，纯离线。
- `jk 块 问 "问句" --模型 <端点>` → 上下文包 → 端点 → 回填 → 校验器 → 组 → 跑。
  **不给 `--模型` 退 1 并指向 `规划`**，不静默降级。
- `--模型` 的端点从环境变量取 key，**不接受命令行传 key**（会进 shell history）。
  端点响应一律当**不可信输入**过校验器，不许旁路。
- 同步 `_USAGE`（`43-75`）与 `main.py:104-105` 的顶层 usage——后者已经漏了
  `组`/`跑`/`新建`，本轮顺手补齐。

**DoD**
- 两条命令的正常路径 + 未知选项 + 缺 `--模型` 各有断言
- `jk 块 问` 在端点返回垃圾 JSON 时退 1 并给可读理由，不抛裸异常

**W158 落地口径（2026-08-19）**
- `_glue()` 与 `_planner()` 抽出共用的 `_按路径加载(文件名, 模块名, 用途)`——importlib
  那套 dance 抄第二遍就该提取，两处的错误文案也因此同源。
- 端点契约：**POST 上下文包 JSON → 回填响应 JSON**。scheme 走白名单（只收
  `http`/`https`）；`file:`/`data:` 交给 `urlopen` 会去读本机文件，那不是「调模型」。
- 拒答判定为库外时，`规划` 退 0（判定是包里的一个字段，不是命令失败），
  `问` 退 1 且**在调端点之前就停**——省掉那次推理，也不给模型一个注定要编的上下文。
- 真踩到的一处：URL 里带中文路径 / token 里带中文，`http.client` 抛的是
  `UnicodeEncodeError`（请求行与头值必须 ASCII，CVE-2019-9740 的防线），它**不是**
  `OSError`。只捕 `OSError` 会让用户吃一个裸 traceback，故一并捕 `ValueError`。
- 端点用**真的**本机 HTTP server 测（`127.0.0.1:0`），不 mock `_请求回填`：协议白名单、
  鉴权头、垃圾响应处理都在那个函数里，mock 掉等于把要测的东西测没了。
