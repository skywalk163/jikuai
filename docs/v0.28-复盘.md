## 一、被证实的判断

1. **「安全化排最前且给三周」是对的。** 它是本轮唯一一条做不好会造成真实危害的项
   （旧 `/api/跑` 等价本地 RCE），其余各项做不完只是功能缺失。排最前的直接收益是：
   后面十几个 WBS 项都可以在「有一套能给人点的端点」这个既成事实上做，不用留悬念。
2. **「新开一套而不是给旧服务加安全模式 flag」是对的。** 危险能力与安全能力共处一个
   handler，靠 flag 区分，一次配置失误就穿透，而且没法审计——两套物理隔离的代码才说得清
   信任边界。落地后 G24 能对新端点做「静态 + 行为」两套断言，正是因为它是独立模块。
3. **「新门禁必须静态 + 行为两套断言」是对的，而且这一轮又验证了一次。** 只静态时把白
   名单的循环体注释掉照样绿；只行为时把校验器改成「凡不认识的块就拒」也能全场景过，而
   白名单其实已经没了。这条是 v0.27.0 G23 的教训，v0.28.0 直接当执行原则用。
4. **「三块加姊妹出口块，而不是改 0 层块的返回形状」是对的。** 0 层块出元组、`定序`/
   `摘前` 吃表，元组接不进链。新增三个层级 1 的纯 `.jk` 姊妹块（函数体就一句
   `返回 赵元组【0】`），**0 层块与 `glue.py` 一行未动**，代价只是丢掉排除计数。
5. **「口径分歧点要靠块的 `描述` 自报、由调用方显式选一条」这条路线继续成立。** 第五处
   （绝对量 vs 比率排名）加进去以后，日报、角色视角三份方案、溯源面板都能各自把「我站
   哪一侧」写在明面上，没有一处需要引擎层帮忙判断。
6. **「产出物必须真跑一遍、逐字读列名」是对的。** W173 首版把 `基线偏离` 的度量列写死
   成字面「度量」，生成的 SQL 语法完全正确、贴到库里直接报列不存在。这类「看着像样、
   其实错」的 bug 只有拿真方案跑一遍才看得见。

## 二、被证伪或修正的判断（本轮重点）

1. **WBS 说 W174 走「业务词 → 表 → `描述` 提到该表的块」一跳就够 —— 实测承载率
   `0.0%`，一点没动。** K=8 漏掉的块全是**通用管道块**（`表载入` 20/20、`窗口` 17、
   `选取` 12、`连接` 5…），它们的 `描述` 里根本没有表名，那条映射结构上碰不到。
   **缺的不是口径块，是骨架。** 改走两跳后 0.0% → **60.0% / 60.0%**（调优 / 留出）。
2. **BACKLOG 记的「K=40 能到 30.0%」是块库 139 的数；145 下实测只有 20.0%。**
   新块进来摊薄排名，「把 top 调大」的收益**随块库反向缩水**，语义层旁路不随。这反而
   加强了「不靠调大 top 解决」的原判断。
3. **WBS 预期「第五处分歧点会让既有录像判定翻转」—— 零翻转。** `bench_planner` 判定
   一致率 1.0、通过 11 / 拒 4，与新增前逐位相同。原因是规则 3 只在两侧同选或一个都没选
   时拒，而既有录像本就只选一侧。**所以另立了 `test_反例3e…` 专门拿真触发词过真规则 3**
   ——否则这个守卫是绿的，但从来没被考过。
4. **WBS 说 `邻期关联` 加「左行标识」—— 那是错的一侧。** Q_HID_002 里左表是订单、右表是
   缺陷、只有 `model_id` 撞名，所以 `defect_count` 是**右表**列且不带前缀，被乘一遍的是
   右侧。只盖 `左行序` 会掉到 ≤8 条订单行，1599 和 562 都得不到。落地为两列。
5. **WBS 说 W172 复用 `窗间对比`/`基线偏离` 双块就能出趋势判断 —— 双块走不完 DoD。**
   它们**只出比率、不出升/降/持平标签**，而且**看不到日期**（窗口在上游已被 `截期`
   切好，两块拿到的是聚合后的表）。「参照系是哪一段」在双块里推不出来，必须第三个块承。
6. **W168 的缺口 2 是表达能力缺口，不是那道题的错误来源。** Q_PUB_004 换成全补集口径后
   L002 升幅 `0.258857 → 0.259574`，差 **0.07 个百分点**，两种基线下榜首都是它。
   **W155 的 reference 一行没改**——没有为了让两个数对上去动它。
7. **立项 WBS 的 W178 清单漏了赛题官方第 ⑤ 项「≥1 份自动生成的运营日报样例」。**
   比对 `赛题说明_参赛者版.docx` 第七节原文才发现：docx 的六项 ≠ WBS 的七个 bullet。
   **下次做交付物先读 docx 原文再对 WBS**，别拿二手清单当验收标准。
8. **「无条件注入手工挑的 6 块骨架」看起来更好，实际是过拟合。** 调优档 80% / 留出档仍
   60%，多出的 20 点全在调优档，而那份名单本身就是从调优档的 miss 诊断里挑的。
   **数字漂亮不是理由**，不取。
9. **`时间锚点` 不该进协议字段集。** 它对回填无约束力（规划器不会因锚点对不上而拒），
   而 `schema._check_str` 拒 `None`，可空的必填字段要开校验特例。改为缀进
   `语义命中.口径说明` 尾部，ADR-41 §3 的冻结字段集与 G23 断言 1a 一行未动。

## 三、必记单点（踩过的坑，按会不会再踩排序）

1. **判「名字是不是词法原子」只能走 lexer，不许用正则。** 正则判等于旁路分词器，正是
   W167 那个坑的成因；也不能读 parser 的 `FuncDef.params`——`_parse_param_list` 只收
   `IDENT`，坏名字到它手上已经被切干净了。正则只配用来定位子句、切出作者写下的那个词。
   （这条已经固化成门禁 G25。）
2. **「禁止调用」的静态扫描要走 AST 的 Call 节点，不许按文本 grep。** `run_source` 必然
   出现在文档串和「要交给 subprocess 跑的引导字符串」里，按行扫必然假红。且**不能把
   `compile` 列进禁用名**——`re.compile` 是正常用法。
3. **鉴权 Token 必须纯 ASCII，且要在启动这一刻就拒非 ASCII。** HTTP 头值只收 latin-1，
   带中文的 Token 会让**客户端**发请求时抛 `UnicodeEncodeError`——报错落在调用方、
   离病根很远。（与 v0.27.0「`UnicodeEncodeError` 不是 `OSError`」同源。）
4. **子进程执行必须显式给 `PYTHONIOENCODING=utf-8` + `PYTHONUTF8=1`。** Windows 上子
   进程默认按 GBK 写 stdout，父进程按 UTF-8 解就抛 `UnicodeDecodeError`。顺手把
   `JIKUAI_DEMO_TOKEN` 从子进程环境里 `pop` 掉——被执行的代码没理由看到它。
5. **门禁的反例副本要放在被测模块旁边，不能放 `tmp_path`。** `demo_server.py` 靠
   `__file__` 往上两级算 `_REPO` 再挂 `src/`，挪到临时目录就 import 不到 `jikuai`，
   那样红的是「加载失败」而不是「门禁抓到了」，证不出任何东西。
6. **多对多关联「膨胀在哪一侧」必须去读方案、看度量列属于哪张表**，不能凭「左表是主表」
   的直觉。前缀只加给撞名列，所以不带前缀的列**可能是右表的**。
7. **中文产出物存档不能走 shell 重定向，要让 Python 自己写文件。** Windows 控制台按
   GBK 转码，`单车电耗均值` 这类列名落盘就是坏的；`Tee-Object` 同样坏。已有
   `PYTHONIOENCODING=utf-8` 也只管进程内编码，管不了 PowerShell 那一层。
8. **跑全量回归的固定姿势是**
   `cmd /c "set PYTHONUTF8=1&& set PYTHONIOENCODING=utf-8&& python -m pytest -q --tb=no -rEf > 文件 2>&1"`
   **，两个坑各栽过一次。**
   - **不要用 PowerShell 的 `Out-File`/`Tee-Object`**：W179 首跑日志在 54% 处出现上百个
     连续 `E`，看着像大规模回归，实际是那条管道自己崩了（`NativeCommandError` 把 pytest 的
     stderr 当命令错误），进度流被搅成假的。
   - **不设 `PYTHONUTF8=1` / `PYTHONIOENCODING=utf-8` 时，子进程默认编码会退化到 GBK**：
     W180 bump 后那次跑出 `1 failed / 1810 passed / 3087 errors`，错误**全是
     `UnicodeDecodeError`**，从 `test_…w164_演示端点.py` 起成片。全仓十几个测试文件靠
     `subprocess` 起子进程读 stdout，父进程按 UTF-8 解就成片炸。**这就是本节第 4 条那个坑，
     只是发作在测试运行器一侧而不是被测代码一侧。**
   - **判据**：看到成片 `UnicodeDecodeError` 先**复现单条**。单条过（本轮
     `test_错令牌401` 单跑 EXIT=0）就是环境编码问题，别当回归查。加上环境变量重跑得到
     **3323 passed / 88 skipped**，与 W179 逐位一致。
9. **`test_registry_server_deploy.py::test_要求TLS_闸门在读body之前` 在全量并跑时会
   偶发红**，报 `ConnectionAbortedError [WinError 10053]` 而不是断言不符：闸门先回 403
   再关连接，客户端体量还没发完，Windows 协议栈就用 RST 代替 FIN 把已发出的 403 一起
   丢掉。**判抖动的方法是单文件复跑。刻意不修**：让服务端回错前排空 body 等于自己开
   DoS 口子，在测试里重试等于掩盖。见了这一条别当回归查，见了别的照查。
10. **写 `.jk` 时「标识符/下标表达式后面紧跟 `(`」会被解析成函数调用。**
    `小于 赵率 (减 0 赵阈值)` 被读成 `赵率(...)`，报「类型错误：不可调用的对象」，
    看着像数据问题。嵌套动词实参先落中间变量。
11. **`共享` 常量在合成源码里排在所有步骤调用之前，所以它引用不了 `赵果N`。** 要把
    「已载入的表」塞进复合字面量实参，解法是在共享值里**就地 `读表(…)`**。
    `glue.py` 的段落顺序（导入 → 共享 → 步骤 → 打印）是固定的，调顺序解决不了。
12. **给同一道题加第二份录像时，别改旧录像的 id 腾位置。** 录像 `id` 此前同时充当评测集
    key，一题只能一条。解法是新 id + 别名字段（`_v27` 后缀 + `问句id` 指回原 id），
    这样「旧录像一字不改」和「问句逐字比对评测集」两条纪律都保住。
13. **给 bench 加样本前先看那个数进不进已发布指标的分母。** W175 的 3 份新录像刻意不进
    `白名单可承载率`，否则 W174 刚报的 0.0% → 60.0% 就换了分母、跨轮次没法比。
    **加样本很容易顺手把口径也改了，那是最难发现的一类指标造假。**

  再设计两跳、再跑一档过拟合对照才敢定版。低估的根因是 WBS 起草时**没有先量一次「K=8
  到底漏了哪些块」**——只要量了，「漏的全是管道块」这个事实立刻会推翻一跳方案。

- **W179 的墙钟被低估**：DoD 只写了「pytest 全量绿」，实际本轮要跑两遍全套（一遍裸测、
  一遍覆盖率），加上首跑因捕获链损坏而作废，实际是三遍。

## 六、遗留（→ v0.29.0）

1. **`jk 块 问 --模型 <端点>` 的真实模型端点验证**，仍未做。它与三臂对照不同——三臂是
   收益已被实验证明有限，这条是**从未验证过**，属真缺口，**不许悄悄改成「不做」**。
2. **演示端点的公网部署 / HTTPS / 反代 / 限流**。本轮明确只做到「本机可跑的安全端点」，
   赛题「在线访问链接」一栏**如实空着**，并有测试守着它不许被填成本机地址。
3. **演示视频**：要人操作录制，agent 侧不产，清单里记为「需人做」。
4. **`_候选索引` 键不含 `命名空间`**（W176 判不修）。并入条件 = 第三方块包真进规划器候选
   那轮；改四元组要连协议与回填契约一起扩。
5. **`选中块` 只按块名比对**（W176 判不修）。并入条件 = 出现跨域同名块，或分歧点表本来
   就要改域字段那轮。
6. **语言级「表」一等类型**（ADR-40 §3.3）与**把引擎层纳入类型图**，都仍未排期。
   v0.26.0 记的「引擎层无类型图保护会咬到人（自动推参静默错绑）」这条风险仍在。
7. **门禁盲区一处，已记档**：给订单侧硬塞一个形状合法、同表、列存在的 `时间锚点`，
   **G22 拦不住**，只有机械规则测试拦得住（`test_反例_给订单侧硬塞默认锚点不会被G22拦`）。
