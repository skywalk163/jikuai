## 二、W181 · 参考回填端点

落点 `tools/ai-bridge/参考回填端点.py`。独立进程 HTTP 端点，收上下文包、回**裸回填
JSON**。三模式：

- `标量`：从包的 `候选` 里挑入参全标量的块造一步方案（可复用的机械造填）
- `录像`：按 `需求` **逐字**匹配 `规划录像/清单.json` 转投人工方案，`模型` 改写成
  `参考端点·录像转投（原：…）`——录像本体是人工产物，经端点走一趟不会变成模型产物
- `幻觉`：故意回不存在的块名，用来在**真进程**上证明规则 2 拦得住

**安全姿态刻意与 `demo_server.py` 不同档**：它只回 JSON、不执行任何东西（无
`run_source`、无 `subprocess`、不 import `glue`），所以**不学 demo_server 的「未设
Token 就拒绝启动」**——那条闸是为「会执行代码的端点」立的。监听地址**硬编码
`127.0.0.1`、不给 `--主机`**；Token 从 `JIKUAI_PLANNER_TOKEN` 取，设了就
`hmac.compare_digest` 校验 Bearer，**非 ASCII 启动即拒**（v0.28.0 W164 的教训）。

**造不出回填时回 422 + 中文理由，不给 200 + 空对象**：后者会被 CLI 报成「校验拒绝」，
把「端点没这能力」误读成「端点填错了」。`录像` 模式的两道自查（逐字匹配、录像块必须
全在本次候选里）都走这条路。

- 测试 `tests/test_v0_29_0_w181_参考回填端点.py` **19 passed**（造填逻辑 7 + 取令牌 3
  + 起服务 2 + 真 socket 往返 6，含 401/对的 Bearer/错的 Bearer 三档鉴权）
- **偏离（技术自裁）**：WBS 原文的「抽共用回填拼装模块」只做到「新模块提供
  `造标量回填` 作为规范实现」，**没有回头改 v0.27.0 W158 测试里那份 3 行的
  `_造回填`**。理由：为 3 行逻辑在 test ↔ tool 之间建耦合，风险大于收益；两处
  语义一致且都有断言守着。
- **实测发现（意料之外，已钉成测试）**：`top=1` 下 Q_PUB_001 的三个块**照样全在候选
  里**——W174 的语义层直取旁路挂在候选表尾部、**不受 `top` 约束**。所以「调小 top
  模拟白名单装不下」是错的构造法，承载不下那条测试改用「清空 `候选`」构造，另立
  `test_调小top拦不住语义旁路所以承载不随top缩水` 把这个事实钉住。

## 三、W182 · 真跑台架

落点 `tools/ai-bridge/真跑_问.py`。起**两个独立子进程**：参考回填端点（进程 A）
← 真 HTTP → `blocks_cli` 引导（进程 B）。5 条用例、`期望判定` 人拍板：

- `录像正例`（通过）/ `标量正例`（通过）
- `幻觉反例`（拒，`校验拒绝` + `白名单`）
- `鉴权不匹配反例`（拒，`HTTP 401`；令牌只给端点不给客户端）
- `库外问句反例`（拒，`拒答`；端点进程**一个请求都没收到**）

**实测 5/5 判定一致。** 客户端引导直接调 `blocks_cli.run`（`jk` 是 console_script，
本机未 `pip install -e .` 时不在 PATH 上），子进程环境显式给
`PYTHONUTF8=1` + `PYTHONIOENCODING=utf-8` + `PYTHONPATH=src`，并把
`JIKUAI_PLANNER_TOKEN` 先 `pop` 掉再按用例注入。

- **必记单点（首跑真栽了）**：`tools/ai-bridge/select.py` 遮蔽标准库 `select`，而
  运行脚本时 Python 把脚本目录塞进 `sys.path[0]`。`http.server` 链式
  `socketserver → selectors → select`，**只要在 sys.path 重排前 import，`select`
  就以本地那个进了 `sys.modules` 缓存**，之后再重排也没用。发作的样子极不像病根：
  端点绑得上、URL 也印出来了，`serve_forever()` 一进 `selectors` 就
  `AttributeError`，进程当场退，客户端只看到 `WinError 10061 连接被拒绝`。
  修法 = **sys.path 重排必须排在 `http.server` 导入之前**（比 `bench_planner.py:126`
  那处更靠前，因为那支不 import socketserver）。台架顺手把**端点子进程的 stderr
  收进记录**（`端点异常` 字段）——不收这个就查不到病根。
- 第二个坑：用例表里最初把端点令牌写成中文，**端点按自己的非 ASCII 闸拒绝启动**，
  报出来是「端点进程启动就退了」，看着像台架坏了。已加
  `test_端点侧令牌必须纯ascii` 守住。
