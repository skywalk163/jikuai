# 包管理（M8）

极快的包管理工具随主包发行，入口是 `jk 包`。设计参考 pip / npm / Cargo
的公共交集，命名与文件格式全部中文化。

## 快速上手

```bash
# 1. 在项目目录里生成清单
jk 包 初始化 我的应用

# 2. 添加一个本地目录依赖
jk 包 添加 甲 --路径 ../甲

# 3. 添加一个 git 仓库依赖
jk 包 添加 乙 --仓库 https://example.com/乙.git --标签 v1.2.0

# 4. 在新机器上按清单还原全部依赖
jk 包 装

# 5. 看看装了什么
jk 包 列表
```

装好之后直接 `导入`：

```jikuai
导入 甲。
打印 甲.平方(5)。
```

## 命令表

- `jk 包 初始化 [名称]` —— 生成 `包.json`，并把 `极快_包/` 追加进
  `.gitignore`。已存在清单时**不覆盖**，直接报错退出。
- `jk 包 添加 <名称> [来源]` —— 写入依赖并立即安装。来源三选一：
  版本约束（`^1.0.0`）、`--路径 <目录>`、`--仓库 <URL> [--标签 <tag>]`。
- `jk 包 移除 <名称>` —— 从清单删掉依赖，并清理 `极快_包/` 里的目录。
- `jk 包 装 [--含开发]` —— 按清单解析安装全部依赖，写回 `包.锁`。
- `jk 包 列表` —— 列出清单声明的依赖及其实际安装状态。
- `jk 包 运行 <脚本名>` —— 执行清单「脚本」表里的命令（工作目录为项目根）。

英文别名：`init` / `add` / `remove`(`rm`) / `install`(`i`) / `list`(`ls`) /
`run` / `help`。

## 文件布局

```
项目根/
├── 包.json          清单（人写，提交进版本库）
├── 包.锁            锁文件（工具生成，提交进版本库）
├── 极快_包/         依赖安装目录（写进 .gitignore）
│   ├── 甲/
│   └── 乙/
└── main.jk
```

## 清单格式 `包.json`

```json
{
  "名称": "我的应用",
  "版本": "0.1.0",
  "描述": "一句话说明",
  "作者": "张三",
  "许可": "MIT",
  "入口": "main.jk",
  "极快版本": ">=0.6.0",
  "依赖": {
    "甲": {"路径": "../甲"},
    "乙": {"仓库": "https://example.com/乙.git", "标签": "v1.2.0"},
    "丙": "^1.0.0"
  },
  "开发依赖": {
    "测试助手": {"路径": "../测试助手"}
  },
  "脚本": {
    "测试": "python -m pytest tests"
  }
}
```

必填字段只有 `名称` 与 `版本`。

**包名规则**：只允许中文、ASCII 字母数字、下划线、连字符，1–64 字，
不含点与路径分隔符（包名会拼进安装目录路径，放宽等于开一个目录穿越口子）。
与内置标准库模块（`分词`/`排版`/`校验`/`成语`/`正则`/`简繁`/`历法`/`工具`）
重名的包名会被拒绝，避免遮蔽标准库。

**为什么用 JSON 而不是 TOML**：`tomllib` 是 Python 3.11+ 才进标准库的，
而极快的 `requires-python` 是 `>=3.10`。为一个清单文件引入 `tomli`
依赖不值得——核心包零运行时依赖这条底线优先于语法美观。

## 版本约束

对齐 pip / npm / Cargo 的交集写法：

- `1.2.3` / `==1.2.3` —— 精确版本
- `^1.2.3` —— 兼容「最左侧非零段」：`[1.2.3, 2.0.0)`；
  主版本为 0 时收紧为 `[0.1.2, 0.2.0)`
- `~1.2.3` —— 锁定主+次，只放开修订号：`[1.2.3, 1.3.0)`
- `>=1.0.0, <2.0.0` —— 逗号表示逻辑与
- `*` / 省略 —— 任意正式版本

**预发布版本不被范围约束隐式命中**。`^1.0.0` 不会装到 `2.0.0-rc1`，
`*` 也不会。要装预发布必须在约束里显式写出预发布号，
例如 `>=2.0.0-alpha, <3.0.0`。这条规则和 npm / Cargo 一致，
避免用户莫名装到半成品。

## 锁文件 `包.锁`

锁文件的唯一职责是让同一份清单在任何机器上装出**完全一样**的依赖树。
因此它刻意**不写时间戳、机器名等易变字段**，条目按包名排序、
JSON 固定缩进——同样的输入产出字节相同的文件，不会制造无意义的 git diff。

```json
{
  "锁版本": 1,
  "包": [
    {"名称": "甲", "版本": "1.0.0", "来源": "路径",
     "路径": "../甲", "校验和": "sha256:...", "依赖": ["丙"]}
  ]
}
```

`校验和` 是包内 `.jk` / `.py` / `.json` 源文件的稳定 sha256
（跳过 `.git/`、`__pycache__` 等易变内容）。

锁文件格式不兼容变更时 `锁版本` 会 +1，旧版本直接拒读而不是猜测语义——
遇到这个报错删掉 `包.锁` 重新 `jk 包 装` 即可。

## 模块解析优先级

`导入 甲` 的查找顺序：

1. 当前 `.jk` 文件所在目录的 `甲.jk`
2. 项目根 `极快_包/甲.jk`
3. 内置 `stdlib/甲.jk`
4. `JIKUAI_PATH` 环境变量列出的目录
5. 项目根 `极快_包/甲/<入口>`（包是目录，入口由它自己的 `包.json` 决定）

项目根 = 从当前文件向上第一个含 `包.json` 的目录。没有清单时
包管理整条路径直接跳过——纯脚本用户不装依赖也不受影响。

包目录形态排在扁平单文件之后，保证升级到包管理不会改变既有脚本行为。

## 依赖解析策略

- **扁平单副本**：同名包全项目只装一份。`node_modules` 那种嵌套多副本
  在极快里根本无法生效——语言按**模块名**解析 `导入 甲`，无法表达
  「在乙的上下文里 甲 指另一个版本」。既然如此就老实做扁平，
  冲突在解析期报错而不是偷偷装两份。
- **首次遇到即锁定**：广度优先遍历依赖图，同名包后续再出现时只校验
  约束相容性，不做版本回退求解。
- **环检测**：命中循环依赖时给出完整链路，而不是栈溢出。
- **裁剪**：`jk 包 装` 会清掉 `极快_包/` 里已不再被依赖的包，
  使安装目录与清单严格一致（对齐 `npm ci` 而非 `npm install`）。

## 安全边界

- **包名校验**：所有写盘路径都经 `validate_package_name`，拒绝路径分隔符与点。
- **入口路径校验**：包 `入口` 字段不允许靠 `..` 逃出包目录。
- **git 抓取**：`subprocess` 全部 `shell=False` + 显式 argv 列表，
  URL 前加 `--` 分隔符防止被当成选项解析。
- **`jk 包 运行`** 走 shell 执行，因为脚本命令是清单作者自己写的可信内容。
  **不要**运行来源不明的第三方 `包.json` 里的脚本——这一点与
  `npm run` 的信任模型相同。
- 拷贝依赖时跳过 `.git/`、`__pycache__`、嵌套 `极快_包/`，不跟随符号链接。
