# 包管理（M8）

极快的包管理工具随主包发行，入口是 `jk 包`。设计参考 pip / npm / Cargo
的公共交集，命名与文件格式全部中文化。

## 快速上手

```bash
# 1. 在项目目录里生成清单
jk 包 初始化 我的应用

# 2. 添加一个本地目录依赖
jk 包 添加 甲 --路径 ../甲

# 3. 添加一个 git 仓库依赖
jk 包 添加 乙 --仓库 https://example.com/乙.git --标签 v1.2.0

# 4. 在新机器上按清单还原全部依赖
jk 包 装

# 5. 看看装了什么
jk 包 列表
```

装好之后直接 `导入`：

```jikuai
导入 甲。
打印 甲.平方(5)。
```

## 命令表

- `jk 包 初始化 [名称]` —— 生成 `包.json`，并把 `极快_包/` 追加进
  `.gitignore`。已存在清单时**不覆盖**，直接报错退出。
- `jk 包 添加 <名称> [来源]` —— 写入依赖并立即安装。来源三选一：
  版本约束（`^1.0.0`）、`--路径 <目录>`、`--仓库 <URL> [--标签 <tag>]`。
- `jk 包 移除 <名称>` —— 从清单删掉依赖，并清理 `极快_包/` 里的目录。
- `jk 包 装 [--含开发]` —— 按清单解析安装全部依赖，写回 `包.锁`。
- `jk 包 列表` —— 列出清单声明的依赖及其实际安装状态。
- `jk 包 运行 <脚本名>` —— 执行清单「脚本」表里的命令（工作目录为项目根）。
- `jk 包 发布 [--确认] [--分类 <分类>] [--允许覆盖] [--签名 <别名>]` —— 把当前包发布到本地注册表。
  **默认演练**（只体检、报文件数与校验和，不落盘），确认无误后加 `--确认` 才真发布；
  同名同版本默认拒绝覆盖，要覆盖须显式 `--允许覆盖`。
  `--签名 <别名>` 用该别名的私钥签校验和，签名者/签名字段随索引条目落盘（见 `密钥` 子命令）。
- `jk 包 搜索 [关键词]` —— 搜索本地注册表里的包（省略关键词则列全部）。
- `jk 包 注册表` —— 显示注册表根目录与统计（总包数 / 总版本数）。
- `jk 包 密钥 生成 <别名>` —— 生成一对 Ed25519 签名密钥；私钥落 `<密钥根>/<别名>.私钥`，
  公钥落 `<密钥根>/<别名>.公钥`（同名已存在时拒绝覆盖，避免误改签名身份）。
- `jk 包 密钥 列表` —— 列出本机密钥根下所有别名及其可签/仅验状态。
- `jk 包 密钥 导出 <别名>` —— 打印 44 字符 base64 公钥，用于交给注册表管理员登记。
- `jk 包 密钥 信任 <别名> <公钥>` —— 把一把 base64 公钥**追加**进本地信任库
  （`<信任根>/<别名>.公钥`，每行一把）。签名者轮换密钥时用：旧公钥保留，
  用旧钥签的老包照样能装。这是唯一能给**已 pin 过**的别名新增公钥的途径——
  注册表侧出现新公钥**不会**被自动接受（ADR-36 §2.4）。
- `jk 包 密钥 撤信 <别名> <公钥>` —— 从本地信任库移除一把公钥（密钥泄露时用）。
  撤到一把不剩则删掉该别名的信任文件，下次装包重新走首次信任（TOFU）。
- `jk 包 帮助` —— 显示用法。

中文别名：`删除`（同 `移除`）、`安装`（同 `装`）。

英文别名：`init` / `add` / `remove`(`rm`) / `install`(`i`) / `list`(`ls`) /
`run` / `publish` / `search` / `registry` / `key` / `help`。

`密钥` 的子子命令另有英文写法 `generate`(`gen`/`new`) / `list`(`ls`) /
`export` / `trust` / `untrust`(`revoke`)。**它们不是顶层命令**，不在上面那张
命令表里，G17 门禁只锁顶层命令 ↔ `cli.py` 的 `_ALIASES`（见「已知缺口」）。


注册表根目录解析顺序：`JIKUAI_REGISTRY` 环境变量 → `~/.jikuai/注册表`。
`JIKUAI_REGISTRY` 可以是本地路径也可以是 `https://...` URL（远程注册表）。
密钥根目录解析顺序：  `JIKUAI_KEY_ROOT` 环境变量 → `~/.jikuai/密钥`。
信任库根目录解析顺序：`JIKUAI_TRUST_ROOT` 环境变量 → `~/.jikuai/信任`。

### 远程注册表（v0.20.0 / ADR-34）

`JIKUAI_REGISTRY=https://...` 即可让所有注册表依赖走远程，无需新命令。
远程注册表就是本地注册表目录的静态镜像（`GET /索引.json`、`GET /包/<名>/<版本>.tar.gz`）。

- `JIKUAI_REGISTRY_TOKEN`：Bearer token（CI 场景直接设环境变量）。公共注册表
  不设也能读。401/403 时 CLI 会提示配 token
- `JIKUAI_REGISTRY_TIMEOUT`：单次请求超时秒数（默认 30）
- `JIKUAI_REGISTRY_INSECURE`：置 `1` 才放行明文 `http://`（内网/测试用，默认拒）
- `JIKUAI_REGISTRY_MAX_RESPONSE`：单次 HTTP 响应体大小上限（字节，默认 512 MiB）。
  防恶意服务端用超大响应耗尽客户端内存（W86 安全审计）。非正/非数字回落默认

本机多注册表凭证也可写到 `~/.jikuai/凭证.json`（`{URL前缀: token}`，最长前缀匹配），
与密钥/信任库同一隔离原则：凭证绝不进 `包.json` / 项目目录。

### 解压限额（v0.21.0 / W86 安全审计）

远程注册表是外部可控输入，tar.gz 的路径安全由 `_safe_extract_targz` 兜住，
但体量需另设上限——几 KB 的归档可解压出几十 GB（tar bomb），撑爆客户端磁盘。
三条上限按 tar 头部声明的 `size` 在解压前判定，非正/非数字回落更安全的默认：

- `JIKUAI_PKG_MAX_MEMBERS`：归档成员数上限（默认 4096）
- `JIKUAI_PKG_MAX_MEMBER_BYTES`：单成员解压后大小上限（默认 64 MiB）
- `JIKUAI_PKG_MAX_TOTAL_BYTES`：解压后合计大小上限（默认 256 MiB）

per-dependency 注册表覆盖：依赖规格写成 `{"注册表": "https://...", "版本": "^1.0"}`，
该依赖强制走指定注册表，忽略全局默认。

### 远程发布（v0.21.0 / ADR-35）

`JIKUAI_REGISTRY` 是 `https://...` 时，`jk 包 发布` 走远程发布：

```bash
set JIKUAI_REGISTRY=https://reg.example.com
set JIKUAI_REGISTRY_TOKEN=...
jk 包 发布 --签名 甲 --确认
```

客户端做快照、算校验和、签名、打 tar.gz，一次 `POST /publish` 推完整报文
（JSON + base64 归档）；落盘与索引一致性由服务端保证。三条与本地不同的规矩：

- **强制签名**。不带 `--签名` 直接拒，**不发请求**。写端没有存量兼容负担，
  比读侧的「未签名过渡告警」更严。服务端也拒 —— 客户端拒是体验，服务端拒是安全。
- **一律拒覆盖**。已发布的 `名称@版本` 再推 → 409，且**没有任何放行开关**。
  `--允许覆盖` 只对本地注册表有效。覆盖会让下游 `包.锁` 里钉住的校验和失效，
  且失败点在使用者那边。要重发请提升版本号。
- **`--演练` 仍默认**。演练时只做本地体检（快照/校验和/签名），不发请求。

**服务端**（`tools/registry-server/`，不随主包发行 —— 它是运维组件不是语言组件）：

```bash
python tools/registry-server/server.py --注册表 D:\注册表 --授权 D:\授权.json \
    --监听 127.0.0.1 --端口 8765 --审计 D:\审计.jsonl
```

`授权.json` **改动无需重启**（v0.22.0 / ADR-36 §2.3）：服务端每个请求前 `stat`
一次该文件，`mtime_ns` 或 `size` 变了就重载。撤销一个泄露的 token 只需从
`令牌` 里删掉那条、保存，下一个请求就认不出它了。重载**不重置频次配额**（仍在
的 token 的滑动窗口原样搬过去），也不会因为一次写坏 JSON 而瘫——读/解析失败时
继续用上一份已生效的配置，并在下次请求再试。

- `JIKUAI_REGISTRY_SERVER_MAX_BODY`：单请求体上限（字节，默认 32 MiB）。
  先于 JSON 解析生效，超限直接 413

**授权**靠服务端的 `授权.json`（不进版本库）。token 只存 sha256，比对走
`hmac.compare_digest`；每条 token 绑定「签名者 + 可发布包名白名单」：

```json
{
  "协议": 1,
  "令牌": {
    "<token 的 sha256 hex>": {
      "签名者": "甲",
      "公钥": "<jk 包 密钥 导出 甲 的输出>",
      "可发布": ["甲包", "甲-*"],
      "每小时次数": 20,
      "单包字节": 16777216
    }
  }
}
```

- **公钥由管理员登记在服务端**，报文里不带 —— 否则攻击者自签自证，签名沦为装饰
- **签名者必须与 token 绑定一致**，防 A 的 token 推署名 B 的包
- **`可发布` 是白名单**，支持精确名与 `前缀-*`；**没有「全部」通配**（纯 `*` 在
  加载配置时就报错，让「授予全权」这个动作在配置里显形）；无匹配即拒
- 拒绝与放行**都进审计日志** `审计.jsonl`（一行一条 JSON）。日志**不记 token**，
  `签名者` 已足够定位是谁 —— 连续越权尝试是入侵信号，只记成功等于丢掉最有用的部分

## 包签名与验签（ADR-33）

发布方用 Ed25519 私钥签**校验和字符串**（`sha256:<hex>`），签名与签名者写进
索引分片条目；发布方公钥落在注册表根的 `密钥/<签名者>.公钥`。

`jk 包 装` **自动**验签，无需 flag（安全默认不该 opt-in），三道检查：

1. **完整性**：索引里记的 `校验和` 与本地重算的必须一致，不一致拒装。
   这道检查独立于签名，是包完整性的地板。
2. **签名**：有签名就必须验得过，验不过拒装。
3. **未签名**：v0.20.0 期间 stderr 告警但放行；**v0.21.0 起拒装**。
   注册表里现在还有 v0.19.0 及之前发的未签包，给一个版本的过渡期。

信任模型是 **TOFU（Trust On First Use）+ 显式白名单**，不是 PKI：

- 首次见到某签名者 → 从注册表拉公钥、pin 进本地信任库
- **一旦 pin 过，装包时就不再看注册表了**。pin 文件是权威，注册表侧那份公钥
  只是分发渠道上的副本；改它不影响已建立的信任（v0.22.0 / ADR-36 §2.4 纠正了
  v0.21.0 「注册表公钥 != pin 就拒装」的判断——只要签名验得过 pin 过的公钥，
  包就没被动过）
- 签名验不过任何一把已 pin 的公钥 → **拒装**。此时若注册表里出现了一把不在
  pin 列表里的新公钥，错误信息会指出「可能是轮换也可能是投毒」并给出
  `jk 包 密钥 信任 <别名> <公钥>` 的命令；确认公钥确属该签名者后手工执行。
  **新公钥永不自动并入 pin**——否则攻破注册表的人追加一把自己的公钥就能签发
  受信包，TOFU 归零
- pin 文件是「每行一把 base64 公钥」，第一行为当前主公钥，后续行是仍受信的
  历史公钥。**任意一把验过即通过**，所以轮换密钥不会让该签名者的历史包集体
  装不上（v0.21.0 及之前的真实痛点）。旧的单行 pin 文件天然合法，零迁移
- 密钥泄露时用 `jk 包 密钥 撤信 <别名> <公钥>` 移除那一把；撤到一把不剩则
  信任文件被删除，回到「未建立信任」状态，下次装包重走首次 pin
- `JIKUAI_TRUSTED_SIGNERS`（`os.pathsep` 分隔）给显式白名单：设了就只信名单
  里的签名者，**即便签名本身有效**；设成空串则一律拒绝

信任库与密钥根刻意分开：密钥根装**本机自己**的签名身份（发包用），信任库装
**别人**的公钥（装别人的包时验签用）。两者泄露后果不同，分目录避免误操作。

路径 / 仓库来源不参与验签——它们没有索引条目，也就没有签名可验。


## 文件布局

```
项目根/
├── 包.json          清单（人写，提交进版本库）
├── 包.锁            锁文件（工具生成，提交进版本库）
├── 极快_包/         依赖安装目录（写进 .gitignore）
│   ├── 甲/
│   └── 乙/
└── main.jk
```

## 清单格式 `包.json`

```json
{
  "名称": "我的应用",
  "版本": "0.1.0",
  "描述": "一句话说明",
  "作者": "张三",
  "许可": "MIT",
  "入口": "main.jk",
  "极快版本": ">=0.6.0",
  "依赖": {
    "甲": {"路径": "../甲"},
    "乙": {"仓库": "https://example.com/乙.git", "标签": "v1.2.0"},
    "丙": "^1.0.0"
  },
  "开发依赖": {
    "测试助手": {"路径": "../测试助手"}
  },
  "脚本": {
    "测试": "python -m pytest tests"
  }
}
```

必填字段只有 `名称` 与 `版本`。

**包名规则**：只允许中文、ASCII 字母数字、下划线、连字符，1–64 字，
不含点与路径分隔符（包名会拼进安装目录路径，放宽等于开一个目录穿越口子）。
与内置标准库模块（`分词`/`排版`/`校验`/`成语`/`正则`/`简繁`/`历法`/`工具`）
重名的包名会被拒绝，避免遮蔽标准库。

**为什么用 JSON 而不是 TOML**：`tomllib` 是 Python 3.11+ 才进标准库的，
而极快的 `requires-python` 是 `>=3.10`。为一个清单文件引入 `tomli`
依赖不值得——核心包零运行时依赖这条底线优先于语法美观。

## 版本约束

对齐 pip / npm / Cargo 的交集写法：

- `1.2.3` / `==1.2.3` —— 精确版本
- `^1.2.3` —— 兼容「最左侧非零段」：`[1.2.3, 2.0.0)`；
  主版本为 0 时收紧为 `[0.1.2, 0.2.0)`
- `~1.2.3` —— 锁定主+次，只放开修订号：`[1.2.3, 1.3.0)`
- `>=1.0.0, <2.0.0` —— 逗号表示逻辑与
- `*` / 省略 —— 任意正式版本

**预发布版本不被范围约束隐式命中**。`^1.0.0` 不会装到 `2.0.0-rc1`，
`*` 也不会。要装预发布必须在约束里显式写出预发布号，
例如 `>=2.0.0-alpha, <3.0.0`。这条规则和 npm / Cargo 一致，
避免用户莫名装到半成品。

## 锁文件 `包.锁`

锁文件的唯一职责是让同一份清单在任何机器上装出**完全一样**的依赖树。
因此它刻意**不写时间戳、机器名等易变字段**，条目按包名排序、
JSON 固定缩进——同样的输入产出字节相同的文件，不会制造无意义的 git diff。

```json
{
  "锁版本": 1,
  "包": [
    {"名称": "甲", "版本": "1.0.0", "来源": "路径",
     "路径": "../甲", "校验和": "sha256:...", "依赖": ["丙"]}
  ]
}
```

`校验和` 是包内 `.jk` / `.py` / `.json` 源文件的稳定 sha256
（跳过 `.git/`、`__pycache__` 等易变内容）。

锁文件格式不兼容变更时 `锁版本` 会 +1，旧版本直接拒读而不是猜测语义——
遇到这个报错删掉 `包.锁` 重新 `jk 包 装` 即可。

## 模块解析优先级

`导入 甲` 的查找顺序：

1. 当前 `.jk` 文件所在目录的 `甲.jk`
2. 项目根 `极快_包/甲.jk`
3. 内置 `stdlib/甲.jk`
4. `JIKUAI_PATH` 环境变量列出的目录
5. 项目根 `极快_包/甲/<入口>`（包是目录，入口由它自己的 `包.json` 决定）

项目根 = 从当前文件向上第一个含 `包.json` 的目录。没有清单时
包管理整条路径直接跳过——纯脚本用户不装依赖也不受影响。

包目录形态排在扁平单文件之后，保证升级到包管理不会改变既有脚本行为。

## 依赖解析策略

- **扁平单副本**：同名包全项目只装一份。`node_modules` 那种嵌套多副本
  在极快里根本无法生效——语言按**模块名**解析 `导入 甲`，无法表达
  「在乙的上下文里 甲 指另一个版本」。既然如此就老实做扁平，
  冲突在解析期报错而不是偷偷装两份。
- **首次遇到即锁定**：广度优先遍历依赖图，同名包后续再出现时只校验
  约束相容性，不做版本回退求解。
- **环检测**：命中循环依赖时给出完整链路，而不是栈溢出。
- **裁剪**：`jk 包 装` 会清掉 `极快_包/` 里已不再被依赖的包，
  使安装目录与清单严格一致（对齐 `npm ci` 而非 `npm install`）。

## 安全边界

- **包名校验**：所有写盘路径都经 `validate_package_name`，拒绝路径分隔符与点。
- **入口路径校验**：包 `入口` 字段不允许靠 `..` 逃出包目录。
- **git 抓取**：`subprocess` 全部 `shell=False` + 显式 argv 列表，
  URL 前加 `--` 分隔符防止被当成选项解析。
- **`jk 包 运行`** 走 shell 执行，因为脚本命令是清单作者自己写的可信内容。
  **不要**运行来源不明的第三方 `包.json` 里的脚本——这一点与
  `npm run` 的信任模型相同。
- 拷贝依赖时跳过 `.git/`、`__pycache__`、嵌套 `极快_包/`，不跟随符号链接。
