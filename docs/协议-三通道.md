# 三通道统一 JSON 协议（v0.15.0 W20）

极快的三条对外通道——CLI（`jk 块 …`）、LSP（`workspace/executeCommand`）、
Web（`tools/web/server.py`）——吐出的 JSON 必须来自**同一份定义**。这份定义的
**唯一真源**是 `src/jikuai/service/schema.py`（`from jikuai.service import schema`）。

> 硬规矩：**任何通道不得自行发明字段**。要加字段，先改 `schema.py`（加常量 +
> 构造器 + 校验器），再改通道。通道里出现手写的协议字段名字面量（用于构造
> 输出的裸字符串，如 `'候选'`/`'名称'`/`'返回值'`）视为违约——W20 起用
> `grep` 把关。读取入参时也按 `schema` 常量取键，不硬编码。

---

## 一、三类核心 schema

### 1. 候选（candidate）

一条「选块」结果。`schema.make_candidate` 构造，`schema.validate_candidate`
校验。

| 字段 | 类型 | 必需 | 口径 / 说明 |
| --- | --- | --- | --- |
| `名称` | str | 必需 | 块名（词法原子，见 ADR-15） |
| `领域` | str | 必需 | 单个领域名（在白名单内） |
| `层级` | int | 必需 | 块的分层等级 L0/L1/…；**取自 `索引.json`**，不是启发式猜的（见 `schema.level_table`），查不到落 `0` |
| `描述` | str | 必需 | 一句话功能描述 |
| `分数` | number | 必需 | 检索相关度；**统一保留 4 位小数**（`round(x, 4)`），三通道数字要能逐字比对 |
| `路径` | str | 必需 | 检索路径标签 `[神经]`/`[启发式]`，可为空串 |
| `命名空间` | str | 可选 | 为 W22 第三方块预留，内置块不带此键 |

- 构造器：`make_candidate(名称, 领域, 层级, 描述, 分数, 路径='', 命名空间=None)`
- 从检索结果转换：`candidate_from_hit(hit, 层级=None)`（`层级` 不传就查
  `level_table()` 读 `索引.json`）

### 2. 方案（plan）

三边 `组`/`跑` 共用的**输入**。`schema.make_plan` 构造，`schema.ensure_plan`
校验（不通过抛 `SchemaError`）。

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `步骤` | list[步骤] | 必需 | 方案主体；**非空数组**。有它才算方案 |
| `需求` | str | 可选 | 自然语言需求，仅作注释 |
| `共享` | list[{名,值}] | 可选 | 共享常量/输入，每项须含 `名` 与 `值` |
| `打印` | list[str] | 可选 | 要打印的结果变量名；省略则打印全部步骤产出 |

每条 `步骤`：

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `块` | str | 必需 | 导入用的目录名 |
| `领域` | str | 必需 | 块所在领域 |
| `导出名` | str | 必需 | 调用名（可与 `块` 不同） |
| `参数` | list | 可选 | 实参名列表；省略即交给 `--自动链式` 的类型图去推 |
| `说明` | str | 可选 | 步骤注释 |

- 构造器：`make_step(块, 领域, 导出名, 参数=None, 说明=None)` /
  `make_plan(步骤, 需求=None, 共享=None, 打印=None)`

### 3. 执行结果（result）

三边 `跑` 共用的**输出核**。`schema.make_result` 构造，`schema.validate_result`
校验。

| 字段 | 类型 | 必需 | 口径 / 说明 |
| --- | --- | --- | --- |
| `stdout` | str | 必需 | 程序标准输出的**原始字符串**（不是按行切的数组） |
| `stderr` | str | 必需 | 程序标准错误的原始字符串（诊断走这里） |
| `返回值` | str | 必需 | `repr()` 后的字符串；失败时为空串 |
| `耗时毫秒` | number | 必需 | `time.perf_counter` 测得，保留 3 位小数 |
| `错误` | str | 可选 | **仅失败时出现**（成功时不出现，而非空串），格式 `<类名>：<消息>`，不带 traceback |
| `诊断` | list[诊断] | 可选 | 仅有位置信息时出现，供 Web 编辑框把行/列高亮出来（W19）；拿不到就省略，不伪造 |

每条 `诊断`：

| 字段 | 类型 | 必需 | 口径 |
| --- | --- | --- | --- |
| `行` | int | 必需 | **1-based 码点**，对齐 `diagnostics.model.Position`（不是 UTF-16、不是字节） |
| `列` | int | 必需 | **1-based 码点** |
| `级别` | str | 必需 | 诊断级别（如「运行错误」） |
| `消息` | str | 必需 | 中文诊断消息 |
| `代码` | str | 可选 | 诊断编码（如 `JK-E1001`） |

- 构造器：`make_result(stdout='', stderr='', 返回值='', 耗时毫秒=0.0, 错误=None, 诊断=None)`

## 二、两个信封

### 选响应（select envelope）

`选` 的响应形状，三通道共用。`schema.make_select_envelope` 构造，
`schema.validate_select_envelope` 校验。

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `需求` | str | 必需 | 原始需求文本 |
| `候选` | list[候选] | 必需 | 候选列表（可为空数组） |
| `降级说明` | str | 可选 | 请求了神经检索但拿不到查询向量时的降级原因；见下方「契约变更史」 |

- 构造器：`make_select_envelope(需求, 候选, 降级说明=None)`

### 跑响应（run envelope）

`跑` 的响应形状，CLI 与 Web 共用（LSP 不提供 `跑`）。
`schema.make_run_envelope` 构造，`schema.validate_run_envelope` 校验。

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `源码` | str | 必需 | 合成出的极快源码；结果没有源码就无法复现，前端也靠它配合 `执行结果.诊断` 高亮出错行 |
| `执行结果` | 执行结果 | 必需 | 见上「执行结果」 |
| `需求` | str | 可选 | 方案里的需求注释，方案没写就不出现 |

- 构造器：`make_run_envelope(源码, 执行结果, 需求=None)`

### 组响应（synthesize response）——不上 schema 常量

`组` 的响应是单字段 `{"源码": str}`。W20 复盘裁决：**单字段响应不值得为它单立
一份 schema 常量**，Web 端键名从 `RUN_ENVELOPE_REQUIRED[0]`（即 `源码`）借用。
这里记一笔即可，不进 `schema.py` 的字段清单。

## 三、通道 × schema 对应关系

- **CLI `jk 块 选 <需求> --json`** → `选响应`（`make_select_envelope`）
  - 候选逐条 `candidate_from_hit`；`--神经`/`--向量` 拿不到向量而降级时填 `降级说明`
- **CLI `jk 块 组 <方案>`** → 入参是 `方案`（glue 入口 `ensure_plan`），输出是 `组响应`（纯源码走 stdout）
- **CLI `jk 块 跑 <方案> --json`** → 入参是 `方案`，输出是 `跑响应`（`make_run_envelope`，内嵌 `执行结果`）
  - 非 `--json`（人读）模式：stdout 直出、stderr 转发；退出码 0 成功 / 1 输入错误 / 2 执行期报错
- **LSP `workspace/executeCommand` 命令 `极快.选块`** → `选响应`（`make_select_envelope`）
  - LSP 不起 sidecar（避免拖住编辑器），故不带 `降级说明`
- **Web `POST /api/选`** → `选响应`（`make_select_envelope`，`神经:true` 降级时带 `降级说明`）
- **Web `POST /api/组`** → `组响应` `{源码}`
- **Web `POST /api/跑`** → `跑响应`（`make_run_envelope`，与 CLI 完全一致）
- **Web `GET /api/blocks`** → `stdlib/blocks/索引.json` 原文（块索引，非本协议范畴）
- **Web `GET /api/能力`** → 能力探测 `{神经可用: bool, 索引版本: str, 块数: int}`（见下）

### `GET /api/能力`

给 W19 前端点亮「神经」开关用。字段名固定，前端已按此契约在写，**不要改**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `神经可用` | bool | sidecar 命令可解析（`embed_client.resolve_command`）**且** 向量索引能加载（`retrieval.load_vector_index`）；两个判据都复用运行时现成逻辑，不自己 `os.path.isfile` 拍脑袋 |
| `索引版本` | str | `索引.json` 的版本；读不到给 `''` |
| `块数` | int | `索引.json` 的块条目数；读不到给 `0` |

## 四、契约变更史

### v0.15.0 W20 —— 三通道收敛（本次）

- **CLI `选/跑` 的 `--json` 输出改成协议形状（breaking change）**：
  - `选 --json`：旧输出 `{"需求", "候选":[{名称,领域,描述,分数,路径}]}`（候选来自
    `Hit.as_dict()`，**缺 `层级`**）→ 新输出走 `make_select_envelope` +
    `candidate_from_hit`，候选**新增 `层级` 字段**，并在神经降级时带 `降级说明`。
  - `跑 --json`：旧输出 `{"需求","源码","结果":[stdout 每行],"返回值"}`（失败时是
    另一套 `{"需求","错误","源码"}`）→ 新输出是 `跑响应`
    `{"源码","执行结果":{...}[,"需求"]}`。差异：
    - `执行结果.stdout` 是**原始字符串**而非按行切的数组；
    - 新增拦下的 `执行结果.stderr`（旧版没拦 stderr）；
    - `耗时毫秒` 用 `time.perf_counter`；
    - 成功/失败**同一套形状**（失败只是多个 `错误` 字段），不再是两套结构。
- **LSP `极快.选块`** 由手写 `{需求,候选}` 改为 `make_select_envelope`。
- **Web `/api/选`** 改用 `make_select_envelope`；**`/api/跑`** 由裸 `执行结果` 改为
  `跑响应` 信封，与 CLI 完全一致；**新增 `/api/能力`** 能力探测端点。
- **glue.synthesize** 入口改调 `schema.ensure_plan`，取代手写的方案字段校验。

### 可选字段的引入理由

- **`降级说明`（选响应）**：用户主动勾了「神经」却拿到启发式结果，必须被告知。
  藏进服务端日志等于骗人；塞进 HTTP 头则只有 Web 能用。因此把它做成协议的正式
  可选字段，三通道都能承载，只在降级时出现、与 `候选` 平级，不破坏候选结构。
- **`诊断`（执行结果）**：运行/编译出错时若能拿到 1-based 码点行/列，就结构化带出，
  供 Web 编辑框把出错行高亮出来（W19）。运行期异常常常没有位置信息，这时省略——
  **不伪造**位置。行/列口径与 `diagnostics.model.Position` 一致（1-based 码点）。
