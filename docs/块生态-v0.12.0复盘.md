## 三、核心技术发现

### 3.1 词法原子性约束（ADR-15 §3.7）

免空格分词器的固有代价。导出名、形参名、块目录名——三者都必须是 lexer 单 token，否则调用方引用不到。四条轨道独立撞上并被迫改名 11 个目录。已建 CI 门禁兜住。

**影响面**：块命名自由度受限。推荐词库收录 `汇总/合计/聚合/清洗/规整/解析/编码/校对/裁剪/采集/落盘/装载` 等实测原子名。

### 3.2 点分路径每段只吞一个 token

`parser._read_module_name()` 每次 DOT 后只消费一个 token。目录名被切成多 token（如 `配置加载` → `配置`+`加`+`载`）会 ParseError。ADR-15 初稿写反了这一点，已加勘误。

### 3.3 Python 对象成员访问的安全暴露面

缺陷 3 修复（开放 opaque 对象 `getattr`）扩大了暴露面。用双层 dunder 拦截（语法层 + 反射层）封堵，但本质上 pybridge 不是沙箱——doc 已诚实标注。

### 3.4 evaluator 的类身份分裂

`test_v0_7_0_aot::TestIsolation` 删 `sys.modules` 后不恢复，导致跨文件的 `isinstance`/`except` 在后续测试里失效。已治本修复（`try/finally` + 完整快照恢复）。

## 五、v0.12.0 附带修复的 6 个既有缺陷

1. `读取`/`写入` 动词声明与实现不一致 → evaluator 补实现
2. lexer 不接受负号字面量 `-5` → 加前置规则
3. opaque Python 对象无成员访问 → `_member_lookup` fallback + dunder 拦截
4. 字典缺 `值集`/`对集`/`合并` → 新增 3 个内建动词
5. 免括号嵌套动词结合方向 → 不改语义，补文档+测试固化
6. `TestIsolation` sys.modules 泄漏 → 快照恢复

## 六、遗留技术债

- 块导出名词法原子性限制块命名自由度（治本需 lexer 加"导入声明反哺白名单"通路，代价大）
- 极快字符串没有方法（`.encode()` 不可用，须绕 `builtins.bytes()`）
- 无内建 join 动词（`拼接` 是变参 concat 不是 join 列表）
- `_eval_Define` 用异常做正常控制流（性能与抗污染性）
- pybridge 反射旁路只堵了 `getattr` 族，`eval(f"{{x.__class__}}")` 理论上仍可绕（但 `eval`/`exec` 已在 DENY_LIST）

## 七、对 v0.13.0 的建议输入

1. **块扩容方向**：优先中国特色规则密集领域（发票、社保、公积金、农历节气、金融文本）——压缩比实测最高的地方

3. **粘合升级**：从模板合成升级到类型对齐（块的输入/输出类型契约驱动自动 `赵果N → 赵果N+1`）

5. **lexer 命名放松**：评估"导入声明反哺白名单"的双向依赖代价——如果可控，v0.13.0 做了能释放大量命名自由度
