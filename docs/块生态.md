## 1 什么是块

**一个"块"就是一个带 `块.json` 元数据的 `.jk` 模块**。组合它们不需要新语法，
就用现有的 `导入` 语句、逗号 `，` 管道与函数调用——块生态是**基于现有语言的
组织学**，不是**新的语言层**。

一句话总结：

> 块 = `.jk` 模块 + `块.json` 元数据 + 单元测试。组合 = `从 ... 导入 ...` + `，` + 函数调用。

任何"用现有 `导入`/`函数`/`类` + 一份元数据文件能表达"的东西都不引入新语法。
花括号 `{}`、`|>` 管道符、`::` 命名空间分隔、`实现 接口A, 接口B`、`模板 X { 生成 { ... } }`
等在 ADR-15 §2.3 中已一并拒绝——不必再往块生态里塞新写法。

**唯一推荐的块调用形式**：

```jikuai
从 blocks.数据.求和 导入 汇总。
打印 汇总(列 1 2 3 4 5)。      -- 15
```

`导入 blocks.数据.求和。` 形式虽然可用（会绑定叶段名 `求和`），但叶段名常与内建动词重名，容易踩坑。**文档只推荐 `从 ... 导入 <导出名>` 这一种写法**。

## 2 命名约束

**这是写块之前必须理解的硬约束。** 如果导出名不满足此条件，调用方根本引用不到你的块。

### 2.1 现象

```
块求和 → 块(IDENT) + 求和(VERB)             调用方报 JK-E5002
累加   → 累(IDENT) + 加(VERB)              调用方报 JK-E5002
赵列表 → 赵(IDENT) + 列(VERB) + 表(IDENT)  调用方报 JK-E5002
汇总   → 汇总(IDENT)                        正常工作
合计   → 合计(IDENT)                        正常工作
```

### 2.2 根因

极快的 lexer 是免空格的最长匹配分词器。内建动词（如 `加`、`减`、`列`、`求和`、`长度`……）会被从标识符中切出来。

ADR-09 的类作用域白名单机制只覆盖「同一次分词内的用户定义名」。块的导出名定义在被导入模块的文件里，调用方分词时根本不知道这个名字存在——白名单里没有它，成员访问松弛也只松弛到「本次分词的用户定义名」。

因此：

- 模块**内部**可以正常定义和调用 `块求和`（本次分词有 `函数 块求和` 声明）
- 调用方**无论**用 `从 ... 导入 块求和` 还是 `别名.块求和`，都会被切成 `块` + `求和`，报 `JK-E5002 模块 X 未导出：块`

这不是 bug，是免空格分词的固有代价。修复方向（让 loader 反哺 lexer 白名单）需要打通双向依赖，代价远大于约定命名。

### 2.3 规则

1. **导出名必须词法原子** —— 整体被 lexer 识别为单个 IDENT token
2. **形参名同理** —— 虽然只影响模块内部可读性，但一并约束以免踩坑
3. **块目录名 / `块.json` 的 `名称` 字段不受此约束** —— 它们只出现在点分路径里，由 `_read_module_name()` 松弛接受任意词形 token

### 2.4 自检命令

在提交块之前，用以下命令验证导出名的原子性：

```bash
python -c "import sys; sys.path.insert(0,'src'); from jikuai.lexer import tokenize; n='汇总'; print([(t.type.name,t.value) for t in tokenize(n+'。') if t.type.name not in ('NEWLINE','EOF','PERIOD')])"
```

期望输出：只有一个元组 `[('IDENT', '汇总')]`。如果出现多个 token，说明这个名字不是原子的，不能做导出名。

替换 `n='汇总'` 为你想验证的名字即可。例如验证 `累加`：

```bash
python -c "import sys; sys.path.insert(0,'src'); from jikuai.lexer import tokenize; n='累加'; print([(t.type.name,t.value) for t in tokenize(n+'。') if t.type.name not in ('NEWLINE','EOF','PERIOD')])"
```

输出 `[('IDENT', '累'), ('VERB', '加')]` —— 两个 token，不合格。

### 2.5 推荐命名词库（原子性已实测）

以下名字经 §2.4 自检命令逐一验证，均为单个 IDENT：

`汇总` `合计` `聚合` `总和` `清洗` `规整` `解析` `编码` `校对` `裁剪` `采集` `落盘` `装载`
`整合` `融合` `编排` `格式` `转换` `校验` `抽取` `提取` `摘要` `扫描` `搜集` `产出` `处理`

**注意**：ADR-15 §3.7 早期词库中列出的 `归并` **不合格**——`归` 是内建副词（reduce），
会切成 `('ADVERB','归') + ('IDENT','并')`。用 `整合` 或 `融合` 替代。这也说明：
词库只是参考，**每个名字都必须自己跑一遍 §2.4 的自检命令**。

### 2.6 禁用字样

任何含以下内建动词字样的名字都不合格：

`加` / `减` / `乘` / `除` / `列` / `求和` / `长度` / `排序` / `连接` / `包含` / `反转` / `替换` / `分割` / `拼接` / `打印` / `输入` / `读取` / `写入`

此外，内建副词 `只` / `皆` / `归` 与关键字 `导入` / `导出` / `函数` / `返回` / `定义` 等也不能做导出名。

完整论述见 [ADR-15 §3.7](ADR-15-块生态架构.md)。

## 3 块目录结构

块按**领域**组织，目录名即领域名。v0.12.0 首批四个领域：`数据/`、`中文/`、
`网络/`、`工具/`。

允许两种物理布局并存，选哪一种由块的复杂度决定：

**布局 A · 单文件块**（适合原子块、无附属测试的极简块）：

```
stdlib/blocks/<领域>/<块名>.jk        主模块
stdlib/blocks/<领域>/<块名>.块.json   元数据（同名前缀 + .块.json 后缀）
```

**布局 B · 目录块**（推荐，适合有测试或含 `.py` 实现的块）：

```
stdlib/blocks/<领域>/<块名>/
├── <块名>.jk       主模块（导出块的公共 API）
├── <块名>.py       可选：Python 实现（ADR-16 §3.3 混合模块）
├── 块.json         块元数据
└── 测试.jk         单元测试
```

**领域字段是数组**（见 §4），一个块可以在物理上属于某个领域目录、同时通过
`领域` 字段声明自己也归属别的领域。物理目录只是"落在哪儿"，语义分类交给
`块.json`。

**模块名解析**（已实现）：`导入 blocks.数据.求和。` 或 `从 blocks.数据.求和 导入 汇总。` 时，`module_loader.resolve()` 按三级回退查找：

1. `stdlib/blocks/数据/求和.jk`（布局 A）
2. `stdlib/blocks/数据/求和/求和.jk`（布局 B）
3. `stdlib/blocks/数据/求和/main.jk`（备选入口）

点分路径解析已在 v0.12.0 W1 落地，当前可正常使用。

## 4 `块.json` 元数据字段

`块.json` 复用 `包.json` 的 JSON 格式与字段命名族，追加块专属字段。所有字段
名为中文，UTF-8 编码，无 BOM。

字段清单（必填以 `*` 标注）：

- `名称` * —— 块名，与文件名或目录名一致
- `版本` * —— 语义化版本号，格式 `MAJOR.MINOR.PATCH`
- `层级` * —— 整数 `0..N`。`0` 表示原子块（不聚合其他块），`N` 表示聚合了 `N-1` 级块
- `领域` * —— 字符串数组，允许多归属（如 `["数据", "中文"]`）。当前允许值：
  `数据` / `中文` / `网络` / `工具`；扩展需走 ADR-15 §3.6 的领域注册流程
- `描述` * —— 一句话说明这个块干什么，供 CLI 检索与 AI 桥接使用
- `输入` —— 数组，每项 `{"名": ..., "类型": ...}`；文档化用，运行时不强制
- `输出` —— 对象 `{"类型": ...}`；文档化用，运行时不强制
- `依赖块` —— 数组，列出这个块 `导入` 的其他块名；CI 会校验字段与实际
  `导入` 语句一致（G11 门禁，已上线）
- `极快版本` —— 版本约束串（同 `包.json` 的 `极快版本`），如 `">=0.12.0"`
- `示例` —— 单行极快代码字符串，供 `jk 块 详情` 输出
- `稳定性` —— `experimental` / `stable` / `deprecated`。CLI 默认只推荐 `stable`

**完整示例**（`stdlib/blocks/数据/求和/块.json`）：

```json
{
  "名称": "求和",
  "版本": "0.1.0",
  "层级": 0,
  "领域": ["数据"],
  "描述": "对数值列表求和，返回总和",
  "输入": [{"名": "列表", "类型": "列表"}],
  "输出": {"类型": "数"},
  "依赖块": [],
  "极快版本": ">=0.12.0",
  "示例": "从 blocks.数据.求和 导入 汇总。\n打印 汇总(列 1 2 3 4 5)。",
  "稳定性": "stable"
}
```

**运行时不强制类型**：极快是动态类型语言，`输入`/`输出` 字段只作文档与检索
用途，不做运行时校验。这与 ADR-15 §3.6 "不做强类型运行时校验" 一致。

## 5 组合示例

以下示例演示如何用**现有语法**把块拼起来。

### 示例 1 · 数值汇总（已可运行）

```jikuai
-- 依赖：blocks.数据.求和（已存在，导出 `汇总`）
从 blocks.数据.求和 导入 汇总。

打印 汇总(列 1 2 3 4 5)。          -- 输出：15
打印 汇总(列 10 20 30)。           -- 输出：60
```

- `从 ... 导入 汇总` 把导出名 `汇总` 直接绑进当前作用域
- `列 1 2 3 4 5` 是极快已有的列表构造动词
- 无新语法

### 示例 2 · 管道组合（待块落地）

```jikuai
-- 依赖：blocks.数据.求和（已存在）、blocks.数据.清洗（在建）
从 blocks.数据.求和 导入 汇总。
从 blocks.数据.清洗 导入 规整。    -- 待 M2 交付

定义赵数据=列 1 0 3 0 5。
打印 规整(赵数据)，汇总。          -- 去除零值后求和，预期：9
```

- 逗号 `，` 是极快已有的管道分隔符（元数解析规范 §1.2），把上一步结果作为
  下一步动词的第一参数

### 示例 3 · 中文文本规范化（待块落地）

```jikuai
-- 依赖：blocks.中文.分词包装（在建）、blocks.中文.简繁包装（在建）
从 blocks.中文.分词包装 导入 切词。
从 blocks.中文.简繁包装 导入 转简。

打印 转简("中國程序員的中文編程語言")，切词。
```

- `分词包装` / `简繁包装` 是 M2 阶段交付的一级块，对现有 `stdlib/分词` /
  `stdlib/简繁` 做薄封装并补齐 `块.json` 元数据

更多可运行示例见 [`examples/blocks/`](../examples/blocks/)。

## 6 命令行工具

`jk` 主入口新增 `块` 子命令族（M1 · W3 上线）。命令形式：

- `jk 块 列表 [--领域 <名>] [--层级 <N>] [--稳定性 <级别>]`
- `jk 块 查找 <关键词>`
- `jk 块 详情 <块名>`
- `jk 块 校验 <块目录>`
- `jk 块 索引`

### 6.1 `jk 块 列表`

列出已注册的块。默认只列 `稳定性: stable`。

```
$ jk 块 列表 --领域 数据
名称           层级  稳定性   描述
求和           0    stable   对数值列表求和，返回总和
...
```

### 6.2 `jk 块 查找`

按名称与描述做模糊检索。

```
$ jk 块 查找 "求和"
求和           0  stable   对数值列表求和，返回总和（数据）
```

### 6.3 `jk 块 详情`

显示某块的完整元数据 + 示例。

```
$ jk 块 详情 求和
名称：求和
版本：0.1.0
层级：0
领域：数据
描述：对数值列表求和，返回总和
输入：列表（列表）
输出：数
依赖块：（无）
极快版本：>=0.12.0
稳定性：stable
示例：
  从 blocks.数据.求和 导入 汇总。
  打印 汇总(列 1 2 3 4 5)。
```

### 6.4 `jk 块 校验`

社区贡献者本地自查用。校验点：

- `块.json` 存在且 JSON 合法
- 必填字段齐全（§4 带 `*` 的项）
- `依赖块` 与 `.jk` 中的 `导入` 语句一致
- 导出名词法原子性检查（§2）
- `测试.jk` 存在且能通过

退出码：0 通过 / 非 0 失败并打印诊断。

### 6.5 `jk 块 索引`

扫描 `stdlib/blocks/` 生成 `stdlib/blocks/索引.json`，供 CI 与 AI 桥接消费。
索引格式见 ADR-15 §3.4。CI 在每次合并前通过 G11 门禁校验索引一致性。

**索引生成脚本**（已实现）：

```bash
python scripts/generate_block_index.py            # 正常生成
python scripts/generate_block_index.py --check    # CI 门禁模式，不写盘
```

## 7 贡献一个块

六步流程，全部本地操作，无需注册中央仓库（v0.12.0 不做云端仓库）。

**第一步 · 新建目录**

在合适的领域下建目录：

```
mkdir stdlib/blocks/数据/我的块
```

**第二步 · 写 `.jk` 主模块**

```jikuai
-- stdlib/blocks/数据/我的块/我的块.jk

函数 处理 接收 赵输入：
  返回 赵输入。      -- 这里写你的实际逻辑
。

导出 处理。
```

只导出真正对外的 API。未 `导出` 的名字调用方看不见（`JK-E5002`）。

**第三步 · 跑原子性自检**

**在选定导出名之前**，用 §2.4 的自检命令验证你的导出名是否词法原子：

```bash
python -c "import sys; sys.path.insert(0,'src'); from jikuai.lexer import tokenize; n='处理'; print([(t.type.name,t.value) for t in tokenize(n+'。') if t.type.name not in ('NEWLINE','EOF','PERIOD')])"
```

输出必须只有一个 `('IDENT', '处理')` 元组。如果出现多个 token，换个名字。参考 §2.5 推荐词库。

**第四步 · 写 `块.json` 元数据**

按 §4 的字段清单填写。至少要有 `名称` / `版本` / `层级` / `领域` / `描述`。`稳定性` 新块统一填 `stable`。

**第五步 · 写 `测试.jk`**

```jikuai
-- stdlib/blocks/数据/我的块/测试.jk

从 blocks.数据.我的块 导入 处理。

打印 处理("样本输入")。
```

推荐每块 ≥ 5 条用例，覆盖正常路径、空输入、边界值。

**第六步 · 跑校验**

```
jk 块 校验 stdlib/blocks/数据/我的块
```

退出码 0 即可提交 PR。CI 的 G11 门禁会自动校验索引一致性。

## 8 与 AI Agent 的关系

必须诚实：块生态**不是**"零 token 替代 AI Agent"，而是把 AI 从代码生成器
**降级为块选择器**——

- **AI 负责**："挑哪些块 + 怎么连"
- **极快负责**："把这些块跑起来"

### 8.1 有效范围

对**已知模式**（读文件 → 清洗 → 统计 → 输出报表这类流水线任务），块组合能：

- 消除代码级幻觉（块是预测试过的稳定代码，不是 AI 现场生成）
- 大幅降低 token 消耗（AI 只需输出粘合层，几十行代码级 → 几行块组合级）
- 提升可复现性（同一自然语言需求 → 同一段极快代码）

**预期 token 压缩比 10~50 倍**（相对传统 AI 从零生成代码；具体数字见路线图
M3 · AI 桥接的基准报告）。

### 8.2 无效范围

块只能覆盖组合空间**之内**的任务。以下情形块生态帮不上：

- 需求本身跨越所有已知模式（比如全新算法、领域外的业务规则）
- 需要生成新块（生成新代码本身还是 AI 的活）
- 需要跨语言/跨系统的集成设计

这些场景仍需**传统 AI Agent**。差异在于：即使 AI 生成新代码，块生态提供了
**兜底粘合层**——AI 只需产出块选择列表 + 极少量粘合代码，剩下的组合与执行
由极快与已有块承担。

### 8.3 不做的承诺

以下条目**不承诺**，也不写进任何用户可见的文案：

- 零 token
- 完全取代 AI Agent
- 100% 需求覆盖
- 一次组合终身不改

写得诚实一点比写得漂亮一点更值钱。这条也是 ADR-15 §2.1 的立场。
