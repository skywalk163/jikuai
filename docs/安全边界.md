# 极快 JiKuai · 安全边界声明

> 版本：v0.6.0 起生效 · 对应 ADR-21
> 本文件是极快语言安全边界的**权威声明**。若与其他文档冲突，以本文件为准。

## 一句话结论

**极快的 Python 互操作（pybridge）不提供完整沙箱隔离，不适用于执行不受信任的代码。**

---

## 1. pybridge · Python 互操作

### 1.1 现状机制

pybridge 通过**黑名单（拒绝清单）**拦截若干高危 API：

- `os.system`
- `subprocess.Popen`
- `builtins.eval`
- `builtins.exec`

以及路径校验：`load` 拒绝 `..` 路径穿越与绝对路径逃逸（`_validate_script_path`）。

### 1.2 为什么这不是沙箱

黑名单是**枚举**，不是语义分析。以下路径可以绕过它，这是黑名单机制的固有局限，
不是待修的缺陷：

- 间接引用：`importlib.import_module("os").system(...)`
- 动态名字构造：`getattr(__builtins__, "e" + "val")`
- 任何未列入清单的危险 API：文件读写、网络访问、`ctypes`、`pickle` 反序列化等

一个真正的沙箱需要在解释器或操作系统层面做能力削减（capability reduction），
本周期不实现。

### 1.3 适用场景

✅ 运行**你自己编写的** Python 代码
✅ 运行**来源可信的**第三方库（如 `math`、`json`、`numpy`）
✅ 本地开发、脚本自动化、数据处理

### 1.4 禁用场景

❌ 执行不受信任的第三方代码
❌ 执行用户上传 / 用户输入构造的代码
❌ 多租户环境下的代码隔离
❌ 面向公网的在线代码执行服务（Playground、评测机等）

### 1.5 若必须承载不可信输入

**pybridge 不能作为安全边界。** 请在其外部叠加系统级隔离：

- 独立子进程 + 资源限制（`RLIMIT_*`）+ seccomp / AppArmor
- 容器（只读根文件系统、无网络、非 root 用户、内存与 CPU 上限）
- 一次性虚拟机 / 微 VM（Firecracker 一类）

## 2. AOT 编译产物（v0.7.0 · Experimental）

AOT 试验会把 `.jk` 源码转成原生二进制。信任前提：

- **编译过程信任源码**：`.jk` 源码等同于可执行代码，不要编译不受信任的源码
- **产物不带沙箱**：生成的二进制拥有运行它的用户的全部权限
- **实验性**：产物格式与命令行接口可能在后续版本变更，不要用于生产交付

---

## 3. 调试适配器 DAP（v0.7.0）

调试器需要读取与修改运行中程序的状态。信任前提：

- **调试会话通道未加密未鉴权**：DAP 走本机 stdio，不监听网络端口
- 若未来引入 TCP 传输，必须只绑定 `127.0.0.1` 并加会话令牌
- **不要**在共享主机上让不受信任的用户接入你的调试会话

---

## 4. 内建 `读取` / `写入`（v0.16.0 起）

内建文件 I/O 动词与 pybridge **共用同一把路径闸**
（`pybridge._validate_script_path`，与 `jikuai.load` 同源，不另写一份）：

- 路径必须落在**当前工作目录（CWD）**内。绝对路径、含 `..` 的穿越路径、
  跨盘符一律拒绝 → `JK-E4002`
- `读取` 有 **10 MiB** 单文件上限（`evaluator._READ_FILE_SIZE_LIMIT`）。
  `读取` 是整段吞入内存的接口，不设顶时误指向大二进制会瞬间耗尽内存
  → `JK-E4003`
- 编码固定 UTF-8；诊断消息中的绝对路径经 `_scrub_paths` 脱敏
- **没有放宽开关**。需要越出 CWD 或流式处理大文件，走 `蟒:` 桥在宿主
  Python 侧显式封装——把「放宽文件权限」这个决定留在宿主代码里显式做，
  比给动词加一个容易被顺手打开的 flag 更安全

⚠️ 这道闸挡的是**误操作与朴素的路径穿越**，不是恶意代码：

- 判定走 `os.path.abspath` 的**词法**归一，不调 `realpath`，因此 **CWD 内
  指向外部的 symlink / junction 不会被挡下**（已声明限制，不是缺陷）
- `.jk` 源码等同可执行代码，能写 `.jk` 的人本来就能通过 `蟒:` 桥做任意事。
  信任前提与 §1 一致


---

## 5. 模块加载



- `.jk` 模块名拒绝路径分隔符与 `..`（`module_loader.resolve`）
- 混合模块的同名 `.py` 通过 `importlib.util.spec_from_file_location` **隔离加载**，
  不写入 `sys.path`，避免全局副作用
- 但 `.py` 侧代码本身**不受限制**——`stdlib/` 下的文件等同于可执行代码，
  不要把不受信任的文件放进 `stdlib/` 或 `JIKUAI_PATH` 指向的目录

---

## 6. 报告安全问题

若发现超出上述已声明范围的安全问题（例如绕过了 `_validate_script_path`
的路径穿越、或诊断输出泄露了本机绝对路径），请作为缺陷提交。

已在本文件中声明的限制（黑名单可绕过、AOT 产物无沙箱等）**不视为缺陷**。
