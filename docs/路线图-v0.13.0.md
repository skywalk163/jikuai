# 极快 JiKuai v0.13.0 路线图 · 块生态进阶

- 版本：v0.13.0
- 周期：12 周（3 个月）
- 起草日期：2026-08-09
- 前置：v0.12.0 复盘（docs/块生态-v0.12.0复盘.md）
- 关联：ADR-15（块生态架构）

---

## 一、目标

v0.12.0 验证了"块能组合"和"AI 输出量能压缩 10 倍"。v0.13.0 要解决的是：
**让"AI 降级为块选择器"从 demo 级验证变成用户可感知的产品体验。**

具体目标：
1. 块总量从 52 扩到 100+，覆盖 6 个领域（新增 财务、历法）
2. 选块从关键词匹配升级到语义嵌入，口语化需求命中率 ≥ 80%
3. 粘合从模板合成升级到类型对齐，自动链式传参覆盖 ≥ 60% 的两步组合
4. 实现首个 L2 块（聚合 3+ 个 L1 块），验证多级聚合工程可行性
5. 评估并可能实现"导入声明反哺 lexer 白名单"，释放块命名自由度

## 三、里程碑

### M1 · 语言层准备（W1–W4）

**轨道 A**
- W1-W2：**「导入声明反哺 lexer 白名单」—— 已决策：v0.13.0 就做**（用户裁决 2026-08-09：「早啃骨头有利」）
  - ✅ **已落地（ADR-24）**：方案 A —— 复用 `frontend.py` 的 2-pass 架构。Pass1
    解析出顶层 `导入` 节点 → `module_loader.try_resolve` 静默解析目标 `.jk` →
    `pkg/blocks.py::extract_exports` 提取导出名（**不执行模块体**）→ 两道过滤
    （在源码里出现过 **且** 单独喂 lexer 非单 IDENT）→ 注入 lexer 白名单 →
    Pass2 重新分词并**重新解析**
  - 与起草时的差异（见 ADR-24 §11）：① 触发条件不是"有 Import 就 Pass2"，而是
    "过滤后白名单非空才 Pass2"；② 白名单路径**不做**收敛判定，否则功能被抵消；
    ③ ADR 编号 22 → **24**（22/23a/23b 已被 v0.7.0 占用）
  - 方案 B（未启用，保留为兜底）：文档化约束 + 推荐命名词库扩容
  - benchmark 结论：无导入文件 +0.0%，含导入文件 +20.7%（未达原定 <5%，理由与
    后续优化空间见 ADR-24 §7）
- W3：块元数据新增 `导出` 字段（把导出名写进 `块.json`），让白名单注入无需读 `.jk` 源码，进一步降低第一遍成本
- W4：`resolve()` 按频度缓存 + 索引预加载到内存（W1 已顺带落地三张进程级缓存，此项缩减为「评估去掉 `os.stat` 指纹校验」）



**轨道 D**
- W3：块版本化规范——`块.json` 新增 `兼容` 字段，`jk 块 校验` 检查同名块跨版本兼容性声明
- W4：`docs/贡献指南.md` —— 命名词库速查表、CI 校验清单、PR 模板

### M2 · 块库扩容（W4–W8）

**轨道 B**（新增 2 领域 + 既有 4 领域补充）
- 新领域「财务」（W4-W6）：发票校验、税率计算、社保基数、公积金、银行账号归属、对账
- 新领域「历法」（W4-W6）：节气计算、黄历宜忌、农历节日、工作日判定、倒计时
- 既有领域补充（W6-W8）：每领域 3-5 个新原子块，填补 v0.12.0 dogfooding 暴露的缺口
- L2 块（W7-W8）：至少 3 个，每个聚合 3+ 个 L1 块，验证多级聚合

目标：52 → 100+ 块

### M3 · AI 桥接进阶（W6–W12）

**轨道 C**
- W6-W7：块索引嵌入化——用 `text2vec-base-chinese` 或同级 embedding 模型，对每个块的 `描述+示例` 做向量化，存为 `stdlib/blocks/向量索引.bin`
- W8-W9：语义选块器——输入自然语言需求 → embedding → cosine 相似度 top-K，替代关键词匹配
  - 对比测试：20 条口语化需求，关键词 vs 语义嵌入的 top-3 命中率
  - 目标：命中率从 ~40%（v0.12.0 关键词）提升到 ≥80%
- W10-W11：类型对齐粘合器
  - 块的 `输入/输出` 字段构成类型图
  - 给定选块方案，自动推断 `赵果1 → 赵果2` 的传参链（当前步的输出类型 match 下一步的输入类型则自动链接）
  - 目标：两步组合中 ≥60% 可自动链式，无需人工填参
- W12：端到端 10 个 demo + 压缩比报告 + v0.13.0 发布说明

### M4 · 收官（W10–W12）

**轨道 A + D**
- W10：lexer 命名放松落地（W1 已提前完成，见 ADR-24；此项缩减为回归复核）
- W11：全量测试 + 索引重生成 + CI 门禁扩展（G12：块 embedding 索引一致性）
- W12：CHANGELOG v0.13.0 + 版本发布

## 四、新增风险

| 风险 | 严重度 | 应对 |
|------|--------|------|
| embedding 模型引入新依赖（torch/onnx），破坏极快"零运行时依赖"底线 | 高 | 把 embedding 放在 `tools/` 而非 `src/`；索引生成时依赖，运行时只读向量文件 |
| "导入反哺白名单"的 2-pass 方案可能影响 lexer 性能 | 中 | ✅ 已量测（ADR-24 §7）：无导入 +0.0%，含导入 +20.7%。原定阈值 <5% 未达，但过滤后现实脚本白名单为空、用户零感知，判定接受 |
| 财务/历法领域块需要大量规则数据（税率表、农历算法表） | 中 | 复用极快已有的 `历法.py` + `校验.py`；税率表以 JSON 数据文件随块分发 |
| 类型对齐在"多输出"块上失效（返回列表而非单一类型值） | 中 | 约定一级块若返回列表则 `输出.类型=列表`，glue 退化为手动；L2 块内部自己处理解包 |
| 100+ 块的命名冲突（两个领域的原子块叫同一个名字） | 低 | 导出名全局唯一（`jk 块 校验` 扩展检查 `索引.json` 内导出名无重复） |

## 五、成功度量

1. **块总量** ≥ 100（6 领域 + 首批 L2）
2. **语义选块命中率** ≥ 80%（20 条口语化需求基准）
3. **自动链式** ≥ 60%（两步组合无需人工填参的比例）
4. **首个 L2 块端到端跑通**
5. **零回归**（全量测试绿色）
6. **无新运行时依赖**（embedding 在工具侧，不进 `src/`）

达成 5/6 视为成功；达成 6/6 视为超预期。
