# 极快 JiKuai v0.14.0 + v0.15.0 六个月路线设计

- 起草：2026-08-10
- 周期：24 周（六个月），分前三（v0.14.0）/ 后三（v0.15.0）依次执行
- 前置：v0.13.0（M2 块库 102 块 + M3 神经检索 + G12 门禁 + `jk 块 选`）
- 关联：ADR-15（块生态）、ADR-24（导入反哺白名单）、ADR-25（M3 语义选块）

---

## 一、总目标

v0.13.0 验证了「AI 降级为块选择器」在**单通道（CLI）**可行。六个月要做两件事：

1. **补内核**：把类型系统细化到能支撑「自动链式传参」而不产生语义荒谬的链——这是 v0.13.0 定了指标（自动链式 ≥60%）却没做的真正难点。
2. **铺三通道**：CLI / LSP / Web 三条 UX 路径共享同一「三段式设计语言」`[需求]→[候选]→[产出]`，先在 CLI 上收敛设计语言，再复制到 LSP、Web。

分段依据：**先深后广**。前三个月把内核（类型系统 + 粘合器 + L2 块）和参考通道（CLI/REPL）做透；后三个月把定型的设计语言复制到 LSP、Web，并开放第三方块生态。

## 二、两个探查结论（改变了成本估算）

### 结论 A：LSP 已能跑，不是 stub

`lsp/jikuai_lsp/` 独立包已实现 `initialize`/`didOpen`/`didChange`/`didClose`/`publishDiagnostics`/`completion`/`hover`，诊断走真实 `SessionHost.compile_and_diagnose` + UTF-16 列投影。

缺口：无 `definitionProvider`；incremental sync 代码完备但契约硬编码 Full；**`completion`/`hover` 零测试覆盖**；`lsp/README.md` 严重过期（还写「M4 stub」）。

→ LSP 轨道从「从零做 MVP」降级为「补测试 + 加两个 provider + 打包」，省下的预算转投类型系统。

### 结论 B：类型对齐的拦路虎是「列表」类型太粗

102 块实测类型词表：
- 输入：数 98 / 字符串 46 / 列表 18 / 字典 6 / 函数 2 / 任意 2
- 输出：列表 40 / 字符串 34 / 数 20 / 布尔 6 / 字典 1

40 个块输出「列表」，但绝大多数是**异质元组**（`批量统计`→`[总和,均值,最小,最大]`、`税单`→`[月收入,个税,税后,大写]`）；只有 18 个块吃「列表」，且要的是**同质数值列表**。

朴素 `列表→列表` 匹配会把 `批量统计 → 升序` 判为可链——类型通过、语义荒谬。**不细化类型系统，v0.13.0 的「自动链式 ≥60%」只会产出一堆能编译的胡话链。** 所以类型系统细化必须先于粘合器，且是前三个月的重头。

## 三、前三个月 · v0.14.0「类型系统 + 粘合 + CLI/REPL 定型」

### M1（月1）类型系统细化 —— 解锁自动链式的前置
- ADR-26 类型词表规范：`块.json` 的 `输入/输出` 增 `元素类型`（同质容器）与 `元数`（异质元组）；定义子类型关系（`列表<数>` <: `列表`）
- 102 块类型标注回填 + G14 门禁（类型词表白名单 + 元组元数与实际返回值一致）
- 类型对齐粘合器落地 `glue.py`：类型图 + 自动链式 + 不兼容时给可读理由（不静默跳过）
- 验收：两步组合自动链式 ≥60%，且人工抽检 20 条链无语义荒谬（比百分比更重要）

### M2（月2）L2 块 + 元数据补强
- 3 个 L2 块（各聚合 3+ L1）：候选 `工资条`（税单+金额报表+周岁）、`月结单`（分期+复利+保留分+金额雅写）、`用户档案`（姓名拆分+身份证+地址剖解+周岁）
- `块.json` 加 `导出` 字段（白名单注入不必读 `.jk`，压 ADR-24 含导入 +20.7% 开销）+ `兼容` 字段（v0.13.0 轨道 D 欠账）
- G13 导出名全局唯一门禁（短名碰撞风险：`转义编码→转义`、`环境值→环境`）

### M3（月3）CLI/REPL 设计语言定型 + 发布
- 三段式 CLI：`jk 块 选`（候选）→ `jk 块 组`（代码）→ `jk 块 跑`（执行）——即后续 LSP/Web 复制的设计语言
- REPL `需求 xxx` 元命令（复用 `repl_session._feed_idle` + `parse_help` 扩展点 + tab 补全种子）
- `tools/ai-bridge/embed_query.py` sidecar，让 CLI/REPL 真正走神经路径（当前向量索引只有 bench 消费）
- 10 个端到端 demo + 压缩比报告 + v0.14.0 发布

## 四、后三个月 · v0.15.0「LSP 深化 + Web + 生态」

### M4（月4）LSP 补齐
- `completion`/`hover` 补测试（当前零覆盖）+ `lsp/README.md` 纠偏
- `definitionProvider`（导入行 F12 跳块目录）+ 开 incremental sync（改 `capabilities.py`+`server.py` 契约）
- `workspace/executeCommand: 极快.选块` 接 `retrieval`
- VS Code 扩展打包 `.vsix`

### M5（月5）Web UI
- 本地只读服务，**用标准库 `http.server` 不引 Flask/FastAPI**（零依赖是品牌主张，此 UI 复杂度标准库够用）
- 三段式单页：需求框 → 候选卡片 → 代码+运行结果，代码高亮 + 错误回显
- 三通道统一 JSON 协议（CLI `--json` / LSP `executeCommand` 返回 / Web API 同 schema）

### M6（月6）生态 + 收官
- `jk 块 新建 <领域> <块名>` 脚手架（生成三件套 + 预检形参名，消灭词法原子性坑）+ 贡献指南
- ADR-27 第三方块注册表规范（`极快_包/blocks/` 布局、命名空间、索引合并策略）
- 全量回归 + 索引/向量索引重生成 + 门禁扩展
- v0.15.0 发布 + 六个月复盘

## 五、三个关键判断（设计约束）

1. **类型系统先于粘合器**。跳过 M1 直接做 glue 会得到「60% 自动链式但一半胡话」，比不做更糟——污染 demo 可信度。
2. **LSP 省下的预算转投类型系统**。LSP 已能跑，只需半月补齐；多出的时间应对类型标注回填这种脏活。
3. **Web 层不引框架**。宣称零运行时依赖的语言，官方 UI 不该 `pip install flask`——产品一致性，非技术洁癖。
