# 极快 JiKuai 路线图 · v0.19.0 + v0.20.0（半年）

> 起草：2026-08-11（v0.18.0 发布当日）
> 周期：W61-W84（约 6 个月，两个版本各 12 周）
> 前置：v0.18.0（L3 扩到 7、G16 协议门禁、集成反馈落地）
> 关联：`docs/BACKLOG.md`、`docs/包管理.md`、`docs/ADR-27-第三方块注册表.md`、`src/jikuai/pkg/registry.py`
> 主题：**把「能装包」变成「有包可装、块也能装、装得可信」——包生态从空转到运转**

---

## 一、目标

半年一句话：**包生态基建齐了，但空转——本季度让它转起来，下季度让它可信地跨机器转。**

起草本路线图时做了一次能力盘点，纠正了两个长期误判（BACKLOG 落后代码七个版本）：

- **「中央注册表是 MVP 占位」是错的**。本地注册表在 v0.11.0 M11-1 就完整实现：`registry.publish/lookup/search/list/unpublish` 全可跑，`sources._fetch_registry` 早已接 `registry.lookup()`，`test_v0_11_0_registry.py` 37 条端到端全绿。
- **「`jk 包 发布` 未落地」也是错的**。`jk 包 发布 [--确认] [--分类] [--允许覆盖]` 早已实现，默认演练。

真正的缺口是三件**没做**的事 + 一件**尴尬**的事：

1. **块 ↔ 包 桥接断裂**：块靠 `JIKUAI_PKG_ROOTS` 手配环境变量发现，包装到 `极快_包/`，两套体系互不相通。ADR-27 §（末）承认「未来让安装器把块放到约定目录并追加环境变量」——这个桥接**没做**。
2. **生态内容为零**：注册表是空的，`examples/` 下无任何真实第三方包/块，测试全靠 `tmp_path` 造。基建齐了没人用。
3. **HTTP 分发 + 签名 + 鉴权**：`registry.py` docstring 自己写着「HTTP 分发留到接入 token 鉴权 + 包签名之后」。纯本地注册表跨不了机器。
4. **文档比代码落后七个版本**：`docs/包管理.md` §尚未实现、`BACKLOG.md` §3 都还在说注册表/发布没做。

### 版本切分决策

- **v0.19.0 = 块包一体 + 生态冷启动**（本地闭环）：先让「块能通过包管理装」+「有真实的包/块可装用」。
- **v0.20.0 = HTTP 分发 + 可信跨机**：再做远程注册表 + 包签名 + token 鉴权。

**为什么这个顺序**：HTTP 分发是「签名 + 鉴权 + 传输」三件套，做完也没内容可分发（注册表空的）。先做「块包能装 + 有内容」，HTTP 才有车可跑。反过来先建 HTTP 等于修一条没车的高速路。这条判断是本半年的主轴，若中途要调整先改这里。

---

## 二、探查结论（改变了估算的事实）

- **注册表/发布/安装三通道已能跑** → v0.19.0 不重做基建，只补桥接与内容，工作量比想象小；省下的周次投给「生态冷启动」（造真实内容 + 文档纠偏）。
- **块与包是两套体系**（`blocks.py` 自述「块不会被安装进 `极快_包/`」）→ 桥接不是小改，要立 ADR-32 定清「块包」格式与安装落点，避免把两套模型强行捏一起。
- **文档漂移不是孤例**：G16 只覆盖了「协议文档 ↔ Web 路由」，没覆盖「包管理文档 ↔ CLI 子命令」。本季度顺手把这类一致性门禁思路延伸（候选 G17）。
- **HTTP 分发的真前置是安全**：token 鉴权 + 包签名不做，远程注册表就是「谁都能推任意包」的攻击面。v0.20.0 必须签名先行、传输在后。

## 三、里程碑

### v0.19.0（W61-W72 · M16-M18）：块包一体 + 生态冷启动

**M16 · 文档纠偏 + 块包桥接设计（W61-W64）**
- 纠正 BACKLOG §3 / `包管理.md` §尚未实现 与代码的七版本漂移
- 清 v0.18.0 W57 遗留的两个文档债（`LSP-使用.md` 补 `npm install`、`package.json` 补 `repository`）
- 候选门禁 G17：包管理文档 ↔ `jk 包` 子命令一致性（沿用 G16 的双向 diff 思路）
- ADR-32：定义「块包」格式（一个包可携带块）+ 安装器把块落到约定目录并接线 `JIKUAI_PKG_ROOTS`

**M17 · 块包桥接实现 + 生态冷启动（W65-W69）**
- installer 侧实现块包安装：`jk 包 装` 后第三方块能被 `scan_blocks` / 检索发现
- 造 3-5 个**真实可发布的第三方块包** fixture，放 `examples/`
- 端到端走通 `发布 → 装 → 检索 → 组码 → 跑`，作为回归钉板

**M18 · 收尾发布（W70-W72）**
- 全量回归 + 双平台 CI + 文档收敛
- v0.19.0 发布
- 缓冲周

### v0.20.0（W73-W84 · M19-M21）：HTTP 分发 + 可信跨机（骨架，详细 WBS 临近再写）

**M19 · 包签名（W73-W76）**
- ADR-33：包签名方案（sha256 已有，加非对称签名 + 公钥分发）
- `jk 包 发布` 产出签名；`jk 包 装` 校验签名，不可信包拒装

**M20 · token 鉴权 + HTTP 注册表（W77-W80）**
- ADR-34：远程注册表 HTTP 协议 + token 鉴权
- `注册表` 源支持 `https://` 根；本地注册表作为镜像/缓存层

**M21 · 收尾发布（W81-W84）**
- 端到端跨机分发验证 + 全量回归 + v0.20.0 发布 + 缓冲

## 四、风险

- **块包格式设计过度**（M16）：块与包强行统一会做出四不像。**应对**：ADR-32 先定「最小桥接」——包只是块的运输壳，块元数据格式不动，安装器只负责落地 + 接线环境变量。
- **生态冷启动造的内容是玩具**（M17）：为凑数造的第三方块没人真用。**应对**：从 quye 等真实集成方的实际需求反推要造哪些块，而不是拍脑袋。
- **HTTP 分发被安全前置拖死**（v0.20.0）：签名 + 鉴权做不完就没法上 HTTP。**应对**：v0.20.0 M19 只做签名（本地可验证），M20 才碰传输；若签名溢出，HTTP 顺延 v0.21.0，不硬塞。
- **文档纠偏引出更多漂移**（M16）：查一处漂移可能带出一片。**应对**：G17 门禁一次性把「文档 ↔ CLI」锁死，之后靠门禁不靠人。

## 五、成功度量（达成 ≥4/5 视为半年成功）

1. **块包桥接闭环**：`jk 包 装` 一个带块的第三方包后，该块能被 `jk 块 选` 检索到并 `组`/`跑`（v0.19.0）。
2. **生态有真实内容**：`examples/` 下 ≥3 个真实可发布第三方块包，端到端 `发布→装→用` 有回归测试钉板（v0.19.0）。
3. **文档零漂移**：BACKLOG / 包管理.md 与代码一致；G17（或等效门禁）上线锁死「文档 ↔ CLI 子命令」（v0.19.0）。
4. **包可信**：`jk 包 装` 校验签名，篡改包被拒；签名方案有 ADR + 测试（v0.20.0）。
5. **跨机分发**：`注册表` 源支持 `https://` 根，端到端从远程注册表装包成功（v0.20.0）。
