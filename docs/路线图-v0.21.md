# 极快 JiKuai 路线图 · v0.21.0（一个季度）

> 起草：2026-08-13（v0.20.0 发布次日）
> 周期：W85-W96（约 3 个月，12 周）
> 前置：v0.20.0（M19 包签名 + M20 HTTP 远程注册表**读侧**；回归 2177 passed / 34 skipped；G10-G18 全绿）
> 关联：`docs/BACKLOG.md` §3、`docs/ADR-33-包签名.md`、`docs/ADR-34-远程HTTP注册表.md` §2.6/§7、`docs/安全边界.md`
> 主题：**把包生态从「只能读」开到「可信地写」——安全审计前置，远程发布随后**

## 一、外部建议的核对结论（先纠偏，再排期）

本路线图的输入之一是一份外部能力提升建议（四维度：核心语言能力 / 生态工具链 / 体验 / 工程质量）。
逐条核对代码与 BACKLOG 后，**其中多数条目已落地或与既有设计边界冲突**。不照单执行，
理由逐条留档如下 —— 沿用 v0.19.0 W61 的纪律：**认定错误要写清，不要静默绕过**。

### 1.2 与既有设计边界冲突，本季度**不做**（要做须另立 ADR 推翻）

- **LLVM 原生后端 + ARM64 交叉编译**。项目已有 AOT 原生编译路径（`tools/aot`，ADR-19）。
  当前 AOT 的瓶颈**不是后端选型，而是子集太窄** —— 成员访问 / 异常 / Lambda / 列表字典 / 类 / 管道
  全部在子集外（BACKLOG §2，均为刻意的「不引入运行时依赖」取舍）。换 LLVM 后端解决不了这些，
  它们缺的是**运行时对象模型、栈展开、堆分配容器**，与后端无关。
  且 llvmlite 是重量级第三方依赖，会击穿「零第三方依赖」品牌主张（同 W31 拒绝 Web 引框架的理由）。
  **裁决**：本季度不做。真要提性能，正确顺序是先扩 AOT 子集（需另立 ADR 逐项推翻设计边界）。
- **可选静态类型推导**。BACKLOG §6 已标「低 / 待定」。这是**语言语义层的大改**，
  且与「极简语法」核心体验直接冲突（类型标注写法必然增加书写负担）。
  当前更迫切的类型缺口不在语言级，而在**块槽位类型**（ADR-26 类型词表 + ADR-30 槽绑定），
  且 v0.17.0 W42 已实测**证伪**「扩类型词表能提升粘合率」这条先验。
  **裁决**：本季度不做实现。若要推进，前置是一份「类型标注不破坏无空格书写」的可行性 ADR。
- **异步任务调度 / 图形基础能力标准库**。零需求证据，且两者都需要引入运行时子系统
  （事件循环 / GUI 后端）。同 L4 块的裁决逻辑：**没有「现有能力表达不了、必须它」的真实场景就不开**。
  **裁决**：不做。

### 1.3 命中真缺口，纳入本季度

| 建议条目 | 对应缺口 | 落点 |
|---|---|---|
| 包管理「完善全链路包发布」 | **远程发布（POST）未做**。`HttpBackend` 写操作抛 `UnsupportedOperation`，ADR-34 §2.6 已预留接口、§7 定了触发条件 | M23 |

## 二、目标

一句话：**v0.20.0 让包能被可信地「读下来」，v0.21.0 让包能被可信地「推上去」。**

为什么这是本季度的正确主轴：v0.19.0-v0.20.0 半年的主轴是「包生态从空转到运转」，
现在链路缺最后一环 —— **写端**。没有远程发布，第三方作者要发包必须拿到注册表机器的文件系统写权限，
这在任何多人协作场景下都不成立，生态就只能停在「官方自己往里塞」的阶段。

但写端是**攻击面的量级跃迁**：读端最坏是读到坏包（M19 签名已兜住），
写端最坏是**任意人往注册表推任意内容、覆盖他人包、撑爆磁盘**。
所以顺序必须是**审计先行**，与 v0.20.0「签名先行、传输在后」同源。

## 三、里程碑

### M22 · 安全审计前置（W85-W88）

开写端之前，把现有三条链路一次性审干净并留档。**这是 M23 的准入条件，不是可选项。**

- **W85 审计三链路**，逐条给「可利用性 / 现状 / 裁决」：
  1. **路径解析**：`module_loader.py` 模块解析、`blocks.py` `extra_roots()` + `.块根.json`、
     `installer.py` 落盘路径、`registry.py` 的 `key_rel`/`package_rel`/`archive_rel`
  2. **依赖解压**：`sources.py` `_safe_extract_targz`、git/本地/注册表三种来源的落盘
  3. **动态代码执行**：`pybridge.py` `DENY_LIST`、`evaluator` 的 exec hook、`module_loader` 的 `.py` 侧载
- **W86 修复**审计中判定为真缺陷的条目；判定为设计边界的写进 BACKLOG 并在源文件留摘要
- **W87 门禁 G19**：把审计中「可机检」的不变量固化成门禁（沿用 G16/G17 的双向 diff 思路），
  避免下一版又靠人肉复查
- **W88 审计报告定案** `docs/安全审计-v0.21.md`，进 BACKLOG 相关条目

**验收**：审计报告覆盖三链路全部入口点，每条有裁决；真缺陷零遗留；G19 有 ≥3 类反例证明门禁真能抓。

### M23 · 远程发布（W89-W93 · ADR-35）

- **W89 ADR-35**：远程发布协议。必须定清 ADR-34 §2.6 留白的五件事 ——
  `POST /publish` 报文格式、**写路径鉴权与授权**（token 能推哪些包名，不能只做「有 token 即可写」）、
  **覆盖策略**（默认拒覆盖已发布版本，与本地 `--允许覆盖` 对齐）、**配额**（包体积 / 频率）、
  **审计日志**（谁在何时推了什么）
- **W90-W91 服务端**：标准库 `http.server` 实现（同 `tools/web/` 的零依赖纪律），
  落在 `tools/registry-server/`（**不随主包发行** —— 它是运维组件不是语言组件）
- **W92 客户端**：`HttpBackend` 写操作实装；`jk 包 发布` 支持 `https://` 目标；
  发布前强制签名（未签名包拒推，比读侧的「过渡告警」更严 —— 写端没有存量兼容负担）
- **W93 端到端**：`发布 → 装 → 验签` 跨进程回归；G18 环境变量文档同步扩展

**验收**：端到端从客户端推包到远程注册表并在另一目录装回验签成功；越权推包被拒且给中文理由；
覆盖已发布版本被拒；未签名包被拒。

### M24 · 质量量化与收尾（W94-W96）

- **W94 覆盖率量化**：接 `coverage.py` 出**首个覆盖率基线数字**，按模块列出低覆盖区。
  **不预设 95% 目标** —— 先看基线，再定本版目标（拍数字容易催生为覆盖率而写的空测试）
- **W95 macOS CI** 补齐四平台；示例补 1-2 个**远程发布链路**的真实场景（不为凑数造玩具，沿用 W67 纪律）
- **W96 发布**：全量回归 + G10-G19 全绿 + CHANGELOG + 版本号 bump（只动 `_version.py`）+ 缓冲

**验收**：四平台 CI 绿；覆盖率基线有数字且低覆盖区有排期；v0.21.0 发布。

## 四、风险

- **审计变成无底洞**（M22）：三链路全审可能带出一片。**应对**：审计只对「外部可控输入能到达的路径」
  定级修复；纯内部调用路径记录不修。W87 用门禁固化，不靠下一版再人肉复查。
- **远程发布设计过度**（M23）：容易滑向「做一个完整的包仓库产品」。**应对**：ADR-35 明确
  **只做单节点、单管理员、文件系统存储**；不做集群、不做 Web 管理界面、不做用户注册流程。
  多租户诉求出现再另立 ADR。
- **服务端引入依赖**（M23）：会有「用 FastAPI 快得多」的诱惑。**应对**：零依赖是硬约束，
  与 W31 拒绝 Web 引框架同源。`http.server` 足以支撑单节点静态托管 + 一个 POST 端点。
- **写端鉴权做成半吊子**（M23）：「有 token 就能写任意包」是最容易掉的坑，等于没有授权。
  **应对**：ADR-35 必须定 token ↔ 包名归属的绑定关系，W93 必须有越权推包的反例测试。
- **覆盖率数字倒逼空测试**（M24）：**应对**：不预设目标数，先出基线；低覆盖区按「是否外部可达」排序。

## 五、成功度量（达成 ≥4/5 视为季度成功）

1. **审计留档**：`docs/安全审计-v0.21.md` 覆盖路径解析 / 解压 / 动态执行三链路全部入口，每条有裁决（M22）。
2. **审计可持续**：G19 门禁上线并有 ≥3 类反例；审计发现的真缺陷零遗留（M22）。
3. **远程发布闭环**：端到端「客户端推包 → 远程注册表 → 另一目录装回 → 验签通过」（M23）。
4. **写端授权真实**：越权推包 / 覆盖已发布版本 / 未签名包，三类均被拒且有反例测试（M23）。
5. **质量可量化**：首个覆盖率基线数字入库；macOS 补齐后四平台 CI 全绿（M24）。

## 六、本季度刻意不做的（逐条 + 理由）

- **LLVM 原生后端 / ARM64 交叉编译** —— 见 §1.2。AOT 瓶颈在子集宽度不在后端；引 llvmlite 破零依赖。
- **可选静态类型推导** —— 见 §1.2。语义层大改 + 与极简语法冲突；前置是可行性 ADR。
- **异步 / 图形标准库** —— 见 §1.2。零需求证据 + 需引入运行时子系统。
- **L4+ 块** —— ADR-28 §3.3 已定不开。
- **LSP `codeAction`** —— ADR-31 已明确关闭，四轮零社区诉求。
- **注册表多租户 / Web 管理界面 / 集群** —— M23 只做单节点单管理员，见 §四。
