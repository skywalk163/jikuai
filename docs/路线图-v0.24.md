## 一、这一版为什么是「修发布，不加功能」

PyPI 上的 `jikuai` 0.4.1 是个**坏包**：wheel 里零个 stdlib 文件，装完 `导入 数学`
直接退出码 1。而本机 `pip install -e .` 一切正常，所以三个版本谁都没发现——editable
装法用 `__file__` 相对回溯能摸到仓库根的 `stdlib/`，非 editable 装完根本没有那个目录。

这是 BACKLOG §10 记了三个版本的「打包死循环」：每次想发都卡在 stdlib 进不去 wheel，
而 ADR-16 §3.4 的 data-files 方案**本身不成立**（`data_files` 装到 `sys.prefix`，与
代码从 `site-packages/jikuai/` 上溯的定位对不上，这才是它一直没落地的真实原因）。

所以 v0.24.0 = **一条主轴（把 stdlib 搬进包、修定位、上门禁、真机验收）+ 三包版号
对齐 + 发布**。刻意不加任何语言/块功能：发布通路自己不通，加什么都发不出去。

---

## 二、目标

一句话：**让 `pip install jikuai` 在干净 venv、非 editable wheel 下真的能用——
stdlib 随包发行、定位入口唯一、有构建后门禁挡住「editable 假绿」，三包同步发 PyPI
0.24.0，yank 掉线上坏版。**

验收总纲（细分见各里程碑）：

1. `stdlib/` 物理进 `src/jikuai/stdlib/`，随 wheel/sdist 发行；定位收敛到唯一入口
   `jikuai.resources`，散落的 6 处 `__file__` 回溯全部改道。
2. 有一条**真构建 wheel 再解包断言内容**的门禁（G20），能抓住漏发资源、测试产物
   随包、块背衬文件缺失。
3. 有一条**干净 venv 真机验收**，是唯一能抓住「editable 假绿」的一步。
4. 三个发行包（jikuai / jikuai-lsp / jikuai-dap）版号对齐 0.24.0，且都从单一真源取。
5. 回归全绿，方案立 ADR-39、BACKLOG §10 结账。

## 三、里程碑

W 编号接 v0.23.0 的 W112。

### M30 · stdlib 进包 + 单一定位入口（W113-W115 · ADR-39）

#### W113 · 定位唯一入口

- 新增 `src/jikuai/resources.py`：唯一定位口（`stdlib_dir()` / `blocks_dir()` /
  `stdlib_path()`）+ `JIKUAI_STDLIB` 覆盖口。只依赖标准库、无全局可变状态。
- 拒绝 `importlib.resources`：消费方（模块加载器、块 CLI）需要**真实文件系统路径**，
  不是文件对象或 traversable（ADR-39 §3）。

#### W114 · 搬 stdlib 进包 + 打包清单单一真源

- `git mv` 把 `stdlib/` 搬进 `src/jikuai/stdlib/`。
- `MANIFEST.in` 成为「什么随包发」的**单一真源**（`include_package_data` 默认 true，
  package-data 白名单反而不是实际过滤器）。
- 清掉随包发出的测试产物（实测 9 个 `临时_测试*.txt` 曾被打进 wheel）。

#### W115 · 定位点收敛 + 自测去污染

- 6 处各写各的 `__file__` 相对回溯全部改道 `resources`。
- 块自测 chdir 到 tmp 根治源码树污染，顺带修 4 处硬编码旧布局的自测。

### M31 · 门禁 + 真机验收（W116-W117）

#### W116 · G20 wheel 内容门禁

- `scripts/check_wheel_contents.py`：**真构建 wheel 再解包**断言——具名资源在、
  无 `.pyc`/`__pycache__` 泄漏、无 `临时_测试*` 随包、块 json 数在 [112,500]、
  **块背衬 `.py` 精确 14 个**（漏了 `圆分` 等旗舰块运行期才炸，原验收线全绿——这是
  本门禁的核心理由）。
- 刻意**不进静态门禁主流程**（要跑 build，慢两个数量级），由
  `check_stdlib_contract.py` 末尾提示单独跑。

#### W117 · 干净 venv 真机验收

- `scripts/verify_wheel_e2e.ps1`：全新 venv、`--no-deps` 装本地 wheel，跑通
  hello / 分词（`个人所得税` 整词切出，证明词典真随包）/ 选块 / 包管理，并断言
  stdlib 落在 site-packages 而非回落源码树、`JIKUAI_STDLIB` 覆盖生效。
- 这是**唯一能抓住「editable 假绿」的一步**。

### M32 · 三包对齐 + 发布（W118-W120）

#### W118 · 三包版号对齐 0.24.0

  `_version.py` 单一真源 + `pyproject` dynamic version，钉依赖下界 `jikuai>=0.24.0`。
- **G15 版本投影从 4 处扩到 6 处**（加 lsp/dap 的 `_version.py`），并补漂移测试。

#### W119 · 文档结账 + 向量索引字节序修复

  README 安装段与项目结构树改到包内布局。

## 四、风险与边界

- **「editable 假绿」是本版头号坑**，也是它存在的理由。任何只在 `pip install -e .`
  下验证的 stdlib 改动都可能是假绿——W117 干净 venv 验收是唯一护栏，不能省。
- **`include_package_data` 让 package-data 白名单形同虚设**：真正的过滤器是
  `MANIFEST.in` + git 跟踪状态，白名单只是补充。误以为白名单在过滤会漏发或多发
  （9 个测试产物随包就是这么发出去的）。G20 是这条的兜底。
- **`py3-none-any` wheel 装到大端平台**：本版查证发现 `向量索引.bin` 的载荷是原生
  字节序，与显式小端的文件头不自洽——在 s390x 等大端机上会静默算错（见 §六偏离 3）。
  发 `any` wheel 就等于承诺跨平台，这类隐患必须清。
- **W120 不可逆**：yank 之后老版本装不上，发错版号无法覆盖。须人工在 TestPyPI 预演
  通过后再动正式 PyPI。

## 六、M30-M32 实施结果（2026-08-15）

### 落地数字

- stdlib 从仓库根 `git mv` 进 `src/jikuai/stdlib/`，随 wheel/sdist 发行。定位入口
  收敛到唯一的 `jikuai.resources`，此前散落 6 处的 `__file__` 相对回溯全部改道。
- G20 门禁：真构建 wheel 后 **430 条条目全绿**（块 json 在 [112,500]、块背衬 .py
  精确 14、无 `.pyc`/`__pycache__`/`临时_测试*` 泄漏）。清掉 9 个曾随包的测试产物。
- 干净 venv 真机验收（W117）通过：`分词("个人所得税起征点")` 切出整词
  `['个人所得税','起','征','点']`（证明 58713 条词典真随包）、stdlib 落在
  site-packages 而非源码树、`JIKUAI_STDLIB` 覆盖生效。
- 三包版号对齐 0.24.0，均从 `_version.py` 单一真源取；G15 版本投影 4 → 6 处，
  加 lsp/dap 漂移测试。
- 全量回归 **2595 passed / 88 skipped**（88 条 skip 是需 C 编译器的 AOT 编译-运行
  比对，本机无编译器）。契约门禁 G10-G19 全绿。

### 与计划的偏离（三处）

1. **G20 测试用仓库 import 惯例，不用 `from scripts.xxx import`**。计划里写的
   `from scripts.check_wheel_contents import ...` 会 `ModuleNotFoundError`（`scripts`
   不是包）。改用仓库既有惯例 `sys.path.insert(0, _SCRIPTS); import ... as G20`。
2. **G20 提示行必须避开 `--json` 模式**。在 `check_stdlib_contract.py` 末尾无条件
   打印 G20 提示会污染 `--json` 输出（`test_契约脚本_json_输出可解析` 报 "Extra
   data"）。用 `if not as_json:` 守住。
3. **顺手修了一个查证时撞见的仓库级缺陷：`向量索引.bin` 字节序不自洽**（本轮外发现、
   本轮修）。文件头一直是显式小端（`struct('<...')`），而向量载荷写侧用 numpy
   `.tobytes()`、读侧用 `array.array('h').frombytes()`——都是**原生字节序**。仓库里
   的 bin 生成于 x86（小端），发 `py3-none-any` wheel 装到大端平台会把 int16 逐字节
   翻转，**不抛异常、只是余弦打分全错、静默返回错误检索结果**。修法：格式口径定为
   「全小端」，读侧在 `sys.byteorder == 'big'` 时补 `array.byteswap()`；写侧用
   `astype('<i2').tobytes()` 显式小端——在小端机器上是纯 no-op，产出字节与改前逐字节
   一致，不触碰 G12 哈希门禁、不需重跑 embeddings。补了三条测试：小端解析、
   monkeypatch 强制大端分支证明 `byteswap` 真被调用（防「守卫绿≠守卫在守」）、
   真实 bin 仍可加载。

### 挂账（不在本轮做）

- **W120 发布本身**：TestPyPI 预演 → 正式 PyPI 发三包 → yank 0.4.1 及更早。不可逆，
  须持 token 的人执行。跨平台验证（大端机器实读 `向量索引.bin`）也在这一步——本机
  只能靠 monkeypatch 证明分支逻辑，真机读要等有大端环境时补。
- **spec/plan 存放位置**：本版 spec/plan 落在 `docs/superpowers/`，与仓库既有的
  `docs/路线图-vX.md` + ADR 惯例并行。要不要统一收口，留作流程问题，本轮不动。
