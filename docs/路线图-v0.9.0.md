## 一、总目标（What & Why）

在保持"极中国"设计基因与现有测试基座（1209 用例零回归）的前提下，用 3 个月完成 M9 遗留的 4 大缺口 + 1 大新增能力：

| 缺口 | 现状 | 目标 |
|---|---|---|
| **CI 原生编译校验** | 8 条端到端 AOT 用例 skip | 全部启用，每次 push 校验 |
| **AOT 子集** | 覆盖控制流；缺 for/函数/return | 覆盖日常语法，脱离 Python 独立跑 |
| **OOP 进阶** | 缺 super、抽象类/接口 | 补上，零关键字增量 |
| **中国特色内置** | 只有身份证/农历等校验 | 补中文正则字面量 + 成语断言 |
| **包管理器** | 只能手动 `导入` 本地文件 | v1 可 `极快 包 install/publish` |

## 三、借鉴 duanpub 的具体设计选型

调研结论（已由子智能体读过 `C:\dumatework\duanpub` + `C:\dumatework\duan\src\`）：

**照抄的**：
1. **双层 JSON 索引**：主索引存路由（`包名 → 分片文件`）+ 分类分片存详情。客户端首次拉几十 KB，按需分片，`etag + checksum` 支持缓存。
2. **强目录约定**：`极快_包/<name>/{源.jk, 包.json, 测试.jk, 示例.jk}`，替代 per-package 脚本。
3. **ZIP 优先于 git clone**：`ZipDownloader` 免 git 依赖、更快；`git clone` 仅 fallback。
4. **发布前 dry-run + 清单校验**：`极快 包 publish --dry-run` 默认打开。

**明确不抄的**：
1. **HTTP registry v2**：duan 的 `registry_server.py` **POST/DELETE 零鉴权**（严重安全隐患），v1 阶段不建 registry 服务，等 v2 补 token。
2. **`外部` 类型声明但实现缺失**：duanpub 里 `包管理增强/源.duan` 只 8 行外部声明，实现体不存在，测试断言函数无定义 —— 我们不复制这种"声明与实现分离"模式。
3. **硬编码路径**：`run_all_tests.ps1` 里 `c:\traework\duanpub\` 是旧路径，我们的脚本要一律用相对路径或环境变量。

**必备安全线**（写进设计契约）：
- 包名禁止 `..`、路径分隔符（沿用 `module_loader.py` 现有校验）
- 清单 `dependencies` 字段必须带版本约束（区别于 duan 的扁平数组）
- Git URL 装包时校验 HTTPS + 固定 commit hash

## 六、风险与降级

| 风险 | 概率 | 降级方案 |
|---|---|---|
| Windows CI 装 gcc 慢 | 中 | 用 `mingw-w64` 预装镜像；或先只在 Linux CI 跑 AOT |
| super 与词法作用域（ADR-22）冲突 | 中 | 保留静态 `父类.方法`；显式禁 `父类` 逃出方法体 |
| 中文正则字面量与 `／` 除号冲突 | 高 | 用 `〔正则〕` 或 `正则'...'` 备选语法 |
| 包管理器 Git URL 域名解析被墙 | 高 | 优先支持 GitCode 镜像；可配置 `极快.toml` 默认源 |
