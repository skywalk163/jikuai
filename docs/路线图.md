# 极快语言 3 个月迭代路线图

周期：2026-08-07 ~ 2026-11-07
起点：v0.1.0（24 项测试全通过，树遍历解释器，基础语法可用）
终点：v0.4.0（中国国情标准库完备、工具链可用、性能达标、可对外发布）

---

## 现状盘点（v0.1.0）

已完成：
- 无空格贪心分词 + 百家姓标识符 + 中文数字字面量
- 元数驱动解析、逗号管道、副词高阶（皆/只/归）
- 变量/条件/循环/函数/类/异常/成员访问
- 人民币类型、大写金额、汉字数字
- REPL + CLI + 24 项测试

明确短板：
1. 中国国情库只有 3 个动词，远未成体系（无农历、无证件校验）
2. 错误信息无行号、无源码上下文，排错困难
3. `导入` 是空壳，标准库无法拆分文件
4. 人民币用 float，有精度隐患（金融场景不可接受）
5. REPL 不支持多行输入，无法在交互中定义函数/类
6. 树遍历解释器，性能未测量、未优化
7. 无编辑器支持、无格式化工具

## 优先级取舍说明

先做国情库而非性能，理由：极快的差异化在「中国」不在「快」——农历、身份证、大写金额是别的中文语言普遍缺失的空白，而性能优化在语言语义尚未稳定时做容易白干。性能放第 3 月，等语义冻结后一次性做字节码，避免重复劳动。

Decimal 改造放第 1 月而非更晚，理由：这是数据表示层的改动，越晚改动影响面越大，且金融精度问题属于正确性缺陷，不是优化项。

## 技术债登记

本节登记已知缺陷与其排期，供后续版本跟踪。登记优于伪装通过：显性豁免比让失败示例"看起来能跑"更负责。

### T-01 lexer 姓氏标识符与动词后缀切分冲突 —— v0.3.0-beta 已修复
- **标题**：贪心分词把含动词字的标识符切碎
- **根因简述**：`_read_surname_ident` / `_read_general_ident` 在遇到动词字（如 `乘`）时无条件断开，导致 `赵阶乘` 被切成 `IDENT(赵阶) + VERB(乘)`；预扫描 `_prescan_definitions` 只登记 `定义 X`，不覆盖 `函数 X` / `方法 X`，无法保护函数名。
- **影响示例**：`examples/functions.jk`（递归阶乘 `赵阶乘` 无法正确解析）
- **排期**：v0.3.0-beta **已修复**
- **修复方式（ADR-01）**：扩展 `_prescan_definitions()`，除 `定义 X` 外同时扫描 `函数 X` / `方法 X` / `类 X`，把名字纳入 `user_defs` 白名单，使 `_try_user_def` 在 `_read_surname_ident` 之前整体命中。贪心切分逻辑本身未改动，`定义` 路径零回归。
- **验证**：`examples/functions.jk` 退出码 0，`赵阶乘(5) → 120`；AC-32 系列 5 条测试守护。

### T-02 子类未定义构造器时未回溯继承链 —— v0.3.0-beta 已修复
- **标题**：子类缺省构造器不调用父类构造器
- **根因简述**：`_eval_NewInstance` 仅执行 `klass.ctor_body`；当子类未声明 `构造` 时 `ctor_body` 为空，不会沿 `parent` 链回溯调用父类构造器，实例属性（如 `名字`/`年龄`）从未初始化。
- **影响示例**：`examples/oop.jk`（`狗` 继承 `动物` 但未定义构造器，访问 `狗.名字` 报"无属性/方法"）
- **排期**：v0.3.0-beta **已修复**
- **修复方式（ADR-02）**：`ClassDef` 新增 `ctor_defined` 标记（`构造` 关键字出现即为真，含空体）；新增 `Evaluator._resolve_ctor()` 沿 `parent` 链回溯定位构造器；`ClassDef` 求值时静态扫描 `自身.X = ...` 得出 `declared_fields` 并沿父链合并，使"声明过但未初始化"的字段返回空(nil)、完全未声明的属性仍然报错。显式空构造器**不**回溯父构造器。
- **验证**：`examples/oop.jk` 退出码 0，`狗.名字 → "旺财"`、`狗.年龄 → 3`；AC-33/34/35 系列 8 条测试守护。

## v0.3.1 排期项（已于 v0.3.1 全部关闭）

### D-04 方法名撞内建动词导致解析失败 —— v0.3.1 已修复（ADR-06）
- **标题**：以内建动词命名的方法/属性在调用点被切碎
- **现象**：`方法 取值：` 定义可以通过（`方法 X` 已进白名单），但**调用点**在另一次独立分词中失去上下文，`赵对象.取值` 被切成 `IDENT(赵对象) . VERB(取值)`，报 `对象 X 无属性/方法`。
- **根因**：与 T-01 同族 —— `_prescan_definitions` 建立的 `user_defs` 白名单只在**同一次 tokenize 的源文本内**有效，且 `_try_longest_keyword`（VERB 匹配）在 `_read_han` 中优先于 `_try_user_def`。REPL 逐行分词、跨行调用时白名单不跨输入保留。
- **受影响写法**：
  - 方法/属性名**整体等于**某内建动词：`方法 取值`、`方法 长度`、`方法 排序`、`方法 反转`、`方法 求和` 等
  - 方法/属性名**内嵌**内建动词字：`方法 王加一`（含 `加`）、`方法 李乘积`（含 `乘`）、`方法 赵取值表`（含 `取值`）
  - 在 REPL 中跨行调用上述成员时必然复现；在单文件中若定义与调用同在一个文件，`方法 X` 白名单可命中，风险较低
- **规避方式**：
  1. 方法/字段命名避开 `VERB_ARITY` 中的动词字，优先用双字非动词词（如 `王显示`、`王递增`、`王计数`）
  2. 已有代码可改名，或把定义与调用置于同一源文件（同一次 tokenize）
  3. 属性访问改走显式赋值的实例字段（`自身.值`），字段名同样避开动词字
- **为何不在 v0.3.0-beta 修**：需要把 `user_defs` 提升为跨输入的会话级符号表，并调整 `_read_han` 中 VERB 与 user_defs 的优先级 —— 属于 lexer 切分逻辑改动，与本轮"锁定 T-01/T-02 已通过态"的回退锚点保护冲突。

### D-05 顶层 `返回` / `跳出` 显示 `内部错误：0` —— v0.3.1 已修复（ADR-08）
- **标题**：控制流信号逃逸到顶层时诊断缺失
- **现象**：在函数/循环体外直接输入 `返回 0。` 或 `跳出。`，REPL 打印 `内部错误：0`（`跳出` 打印 `内部错误：`），而非可读的中文诊断。
- **根因**：`ReturnSignal` / `BreakSignal` / `ContinueSignal` 是控制流用的 Python 异常，不继承 `JiKuaiError`。函数调用/循环体会捕获它们；顶层没有捕获者，落到 REPL 的兜底 `except Exception` 分支，打印异常对象的 `str()`（`ReturnSignal(0)` 的 `str` 就是 `0`）。
- **性质说明**：这是**诊断缺失**，不是解释器损坏。解释器状态未被破坏，会话可继续正常使用；语义上"函数外 `返回`"本身就是无意义写法。
- **规避方式**：只在 `函数`/`方法` 体内使用 `返回`，只在 `当`/`遍历`/`重复` 体内使用 `跳出`/`跳过`。
- **v0.3.1 修复方向**：在 `Evaluator.eval` 顶层与 REPL 求值处捕获三个信号类，转换为携带 `ErrorInfo` 的 `JiKuaiError`（类别 `SYNTAX` 或 `RUNTIME`），文案如"`返回` 只能用在函数或方法体内"。
- **实际修复方式（ADR-08）**：拦截点定为 **`Evaluator.eval()` 最外层 + REPL 顶层**，三条固定中文文案：`「返回」只能在函数或方法体内使用。` / `「跳出」只能在循环体内使用。` / `「跳过」只能在循环体内使用。`（类别 `SYNTAX`）。R-C 约束下 `_eval_FuncCall` / `_invoke_method` / 循环内部的信号捕获保持不变。
- **验证**：AC-59 ~ AC-65 共 7 条 + REPL 侧 3 条测试守护。

## v0.3.1 新登记并同批关闭项

### D-08 带参方法无法调用 —— v0.3.1 已修复（ADR-07）
- **标题**：`_eval_MemberAccess` 无条件「访问即调用」，导致 ≥1 参方法拿不到实参
- **根因简述**：v0.3.0-beta 的 `_eval_MemberAccess` 对方法一律构造闭包并立即 `bound()` 零参调用，形参全部落 `None`；`obj.方法(实参)` 中的括号实参被施加在**返回值**上，报"不可调用的对象"。
- **修复方式（ADR-07）**：新增 `BoundMethod(instance, method_def, closure_env)` 并**按元数分流**：0 参方法保持访问即调用（M-01，兼容 `oop.jk` 的 `赵狗.叫声`），≥1 参方法返回 `BoundMethod` 交由 `_eval_FuncCall` 带参调用（M-02/M-03）；`obj.成员(...)` 走 `auto_invoke=False` 使 `赵狗.叫声()` 等价 `赵狗.叫声`（M-04）。DP-3：`BoundMethod` 不可赋值/传参/返回，统一报 `类型错误：方法不能作为值使用，请直接调用：X.Y(参数)`。
- **验证**：AC-49 ~ AC-58 共 10 条测试守护；`examples/oop.jk` 输出零回归。

### D-09 `自身.X` 字段名未进白名单 —— v0.3.1 已修复（ADR-06 · R-D）
- **标题**：`_prescan_definitions` 只覆盖 `定义/函数/方法/类 X`，漏掉字段声明
- **根因简述**：语言无字段声明语法，字段只在 `自身.X = ...` 处出现；预扫描未收集，导致 `自身.次数` / `自身.当前` / `自身.返回值` 这类含关键字字的字段名在访问点被切碎（`次`=KW_TIMES、`当`=KW_WHILE、`返回`=KW_RETURN）。
- **修复方式**：`_prescan_definitions` 扩容，新增 `_prescan_self_fields()`，在 `_class_regions()` 定位的 **`类` 块作用域内**收集 `自身.X =` 形式的字段名（R-D：类外不纳入；只有紧随 `=` 的成员名算字段赋值）。配合 ADR-06「白名单最优先」在 `_read_han` 入口整体命中。
- **附带修正**：预扫描前对源码做注释/字符串掩码（`_mask_source`），避免 `-- 定义函数` 这类注释把关键字登记进白名单（在旧优先级下无害，在白名单最优先下会把关键字降级为 IDENT）。
- **验证**：AC-39 / AC-40 / AC-41 / AC-44 共 4 条 + `get_user_defs` 契约用例守护。

## ADR-06 方案 A 副作用（v0.3.1 已知限制，同次分词全域生效）

一旦某内建动词名被登记进 `user_defs` 白名单（无论来自 `方法 X` 还是 `自身.X =`），
**该名字在同次分词的全域范围内**（包含类定义之外的顶层语句、同类的其他方法体内、
REPL 同一会话的后续输入）**都失去内建动词语义、被整体识别为 IDENT**。
这是方案 A「白名单最优先」的固有结构性代价，不局限于某个方法体或类块作用域。

**用户规避写法**：
1. **命名避开内建动词名/字**（推荐）：如 `方法 王长度` / `方法 王取值` 代替 `方法 长度` / `方法 取值`。
2. **拆分源文件 / REPL 拆分会话**：把「含动词名的类定义」与「使用同名内建动词的代码」放到不同 `.jk` 文件（不同次分词互不影响）。
3. **⚠️ 括号写法 `长度(郑列)` 无法规避**：分词阶段已将 `长度` 标为 IDENT，括号语法走 `FuncCall(Ident(...))` 路径仍然报未定义标识符，请勿依赖。

## v0.3.1 遗留 Known Issues（已于 v0.3.2 全部关闭）

### D-10（中）变参动词实参不足泄漏 Python 异常文本 —— v0.3.2 已修复
- **复现**：`定义 郑数 = 5。` + `打印 郑数 加 2。` → `类型错误：...lambda() missing 1 required positional argument: 'b'`
- **根因（RCA 报告）**：`parser._parse_argument` 读完一个 primary 就返回，不吸收右侧中缀二元动词；`打印`（变参）已吞掉 `郑数` 后，中缀 `加` 只拿到 1 个实参；`evaluator._eval_Call` 直接 `fn(*args)`，Python `TypeError` 原文透出。分词结果本身正确，非 v0.3.1 引入。
- **修复方案（A + B 双层）**：
  1. **A · parser 中缀合并**：`_parse_argument` 增加中缀二元合并循环（与 `_parse_verb_or_primary` 同源），`打印 郑数 加 2` → `打印(加(郑数, 2))`。
  2. **B · evaluator 元数守卫**：新增 `_check_verb_arity`，实参数量与 `VERB_ARITY` 声明不符时抛 `ErrorInfo(SYNTAX)` 中文诊断 `动词「X」需要 N 个参数，实际收到 M 个`；变参/副词跳过；消息不含 Python 实现细节。
- **语义变化**：`打印 X 加 Y` / `列 A B 加 C` 从抛异常变为成功执行，详见 CHANGELOG v0.3.2「语义变化」表。
- **验证**：D-10 共 9 条测试（含手写 AST 元数守卫用例、变参豁免、前缀动词原路径边界）。

### D-11（低）`python -m jikuai` 不可用 —— v0.3.2 已修复
