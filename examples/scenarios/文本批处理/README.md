# 场景：中文文本批量处理

## 用途

演示极快在**中文文本清洗与分析**场景下的标准库组合能力：一批带排版毛病的脏中文
文本，经「排版规范化 → 分词 → 词频统计 → 成语识别」四级流水线，输出清洗结果与
统计结果。

本示例满足 **AC-M6-03-02**：调用了三个 M4/M5 新增标准库模块 ——

- `排版`（M4）：`规范化文本`，中西文间距 + 标点全角化
- `分词`（M5）：`分词`，正向最大匹配切词
- `成语`（M5）：`是成语` / `成语释义`，四字成语断言与释义

## 输入

三段**固定字面量**脏文本，内嵌在 `main.jk` 中（同目录 `输入文本.txt` 是同一份文本的
纯文本副本，供人工比对，`main.jk` 并不读取它）：

1. `JiKuai是第1个中文编程语言,值得推广!`
2. `中国程序员的中文编程语言。极快版本V0.7.0于2026年发布 !`
3. `团队做事讲究胸有成竹,同事们学富五车,合作画蛇添足要避免.`

毛病类型：中西文之间无间距、句尾用半角标点、句中用半角逗号。

## 预期输出

见同目录 `expected.txt`（真实运行结果的快照，42 行）。要点：

- 排版后：`JiKuai 是第 1 个中文编程语言，值得推广！`（补间距 + 标点全角化）
- 幂等自检通过：`规范化文本` 满足 `f(f(x)) == f(x)`
- 分词结果：命中词典的长词优先（`编程语言` / `程序员` / `胸有成竹`），
  未命中的汉字单字兜底，连续字母数字整体成词（`JiKuai` / `2026`）
- 总词项数 50，去重词表 44
- 多字词词项 20 个；词频 `中文 × 2`、`编程语言 × 2`，其余各 1
- 成语识别命中 3 条：`学富五车` / `画蛇添足` / `胸有成竹`，各附释义

> 快照在 v0.23.0 随词典扩容（565 → 58713 条，ADR-38）重新生成过：
> `值得` / `推广` / `做事` / `讲究` / `胸有成竹` / `避免` 以前都被切成单字，
> 现在整体成词，多字词项从 14 涨到 20。

## 前置依赖

- Python 3.8+，仓库根目录下运行
- 运行方式：`PYTHONPATH=src python -m jikuai examples/scenarios/文本批处理/main.jk`
- 依赖 `stdlib/` 下的三个混合模块：`排版.jk`+`排版.py`、`分词.jk`+`分词.py`、
  `成语.jk`+`成语.py`。模块搜索路径由 `module_loader._search_paths()` 定位到
  仓库根的 `stdlib/`，无需设置 `JIKUAI_PATH`
- 零第三方依赖（不需要 opencc / jieba）

## 实现要点与已知限制

- **副词只识别内建动词**：`赵文集，皆规范化文本` 不成立 —— `规范化文本` 是模块函数，
  会触发 `JK-W1001` 并原值透传。本示例改用 `遍历` 逐条调用 `排版.规范化文本(...)`
- **分词词典不含四字成语**：`胸有成竹` 会被单字兜底切成 `胸/有/成/竹`，
  所以成语识别不能基于分词结果，改为在规范后的整句上做 **4 字滑动窗口** +
  `成语.是成语` 询问
- **`标识符 (` 会被解析成函数调用**：`子串 赵成 钱i (钱i加4)` 报「不可调用的对象」，
  需先把上界算进变量再传（`定义孙止=钱i加4。`）
- `排版` 的 R2b 只看紧邻的前一个字符：文本 2 里 `发布 !` 中间有空格，
  半角 `!` 不会被转成全角 `！`，这是文档声明的口径，非缺陷
- 词频统计用双层遍历计数（O(n²)），示例规模小可接受；生产代码应改用字典累加
