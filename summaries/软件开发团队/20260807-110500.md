## 2. 架构决策（架构师）

### ADR 清单

| ADR | 决策 | 备选方案 | 选择理由 |
|---|---|---|---|
| ADR-01 | AST 位置信息：Node 基类加 `line`/`col` 字段 | SourceLocation 独立包装类 | 改动最小，避免改 20+ 个 `_eval_Xxx` 签名 |
| ADR-02 | JiKuaiError 就地改造：加可选 `info` 属性（含 line/col/source_line/suggestion） | 新建 ErrorWithLocation 子类 | 避免 `except JiKuaiError` 遗漏子类 |
| ADR-03 | 列号用 code point 序号（从1），`^` 渲染层额外处理宽字符 | 显示宽度列号 | 断言稳定、与 VS Code/Vim 一致；视觉对齐与逻辑列号解耦 |
| ADR-04 | ModuleLoader 独立类，与 Evaluator 组合 | 内嵌 Evaluator 方法 | 避免 evaluator.py 膨胀至 900+ 行，可独立单测 |
| ADR-05 | REPL 使用标准库 readline / pyreadline3 | prompt_toolkit | 零外部依赖，符合"极简"定位 |
| ADR-06 | 拼写建议用纯 Python Levenshtein 实现 | rapidfuzz 库 | 候选集 <200，性能充裕，零依赖 |

### WBS 概要

T-01（errors.py 新增）→ T-02（ast_nodes.py 基类改造）→ T-03（lexer.py 位置传递）→ T-04（parser.py _loc 注入）→ T-05（evaluator.py 异常包装 + 拼写建议）→ T-06（main.py 格式化输出）→ T-07（module_loader.py 新增）→ T-08（evaluator 模块系统集成）→ T-09（main.py REPL 增强）→ T-10（stdlib/校验.jk 薄封装）→ T-11（examples 新增）→ T-12（tests 补全）

## 5. 分歧与裁决记录

### 5.1 PRD 阶段裁决（Q1 ~ Q5）

| 编号 | 议题 | 各方立场 | 裁决 | 依据 |
|---|---|---|---|---|
| Q1 | 别名导入后原名是否仍可用 | PM建议A(不可用) vs B(两者可用) | **A：原名不可用** | 与 Python `import x as y` 对齐，降低学习成本，单一入口避免心智负担 |
| Q2 | REPL 多行输入取消方式 | PM建议A(空行取消+Ctrl+C+Ctrl+D) vs B(仅Ctrl+C) | **A：空行取消+Ctrl+C不退出+Ctrl+D退出** | 空行可 stdin 注入模拟，AC-23 可测性优先；Ctrl+C/D 符合终端惯例 |
| Q3 | 标准库 `.jk` 化范围 | PM建议A(1个薄封装) vs B(全量迁移) | **A：仅做 1 个薄封装** | 本轮三块变更叠加已满，全量迁移挤压零回归窗口；验证桥接路径即可 |
| Q4 | 错误列号计数口径 | PM建议A(code point) vs B(显示宽度) | **A：code point 序号从1** | 断言稳定跨平台一致，`^` 渲染层单独处理宽字符，测试与视觉解耦 |
| Q5 | 版本号落法 | PM建议分段打版 | **采纳：M1-3→0.2.0，M2-1/M2-2→0.3.0-alpha** | 与路线图里程碑口径一致，`-alpha` 准确表达未完结 |
