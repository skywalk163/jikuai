## 2. 架构决策（架构师）

### ADR-06 Lexer 白名单优先级重排（治理项 1 · D-04 + D-09）

| 项 | 决策 |
| --- | --- |
| **方案选择** | **方案 A（白名单最优先）+ 清理旧路径**（遵守 DP-4） |
| **否决方案** | B（调用点源码无 `方法 X` 标记，prescan 无法收集）、A+B 并用（制造双路径）、C（延迟切词，侵入过大） |
| **新优先级序** | `_try_user_def_strict` → `_try_longest_keyword` → 姓氏 → 中文数字 → 一般标识符 |
| **旧路径处置** | 原 keyword 之后的 `_try_user_def` 调用点**删除**（唯一事实源，禁双路径） |
| **R-A 防线** | 完整名全长匹配 + 右边界校验（`_is_def_boundary`）+ 仅在 `_read_han` 入口触发，禁止前缀命中 |
| **R-D 防线** | `自身.X =` 扫描限定在 `_class_regions`（`类` 块作用域内），类外不扫 |
| **REPL 会话级** | 新增 `Lexer(source, external_defs=None)` + `get_user_defs()`，供 REPL 跨输入累积白名单 |
| **prescan 扩容** | `_prescan_definitions`：新增前置边界判定（前须非汉字）+ `_mask_source()`（注释/字符串屏蔽）；`_prescan_self_fields`：`自身.X =` 字段声明 |

### ADR-07 BoundMethod 成员方法调用语义（治理项 2 · D-08）

| 项 | 决策 |
| --- | --- |
| **新类型** | `BoundMethod(instance, method_def, closure_env)` + `arity` 属性 |
| **分流判据** | `_eval_MemberAccess` 按**方法定义形参元数**分流：0 参 → 访问即调用（兼容 `oop.jk`）；≥1 参 → 返回 BoundMethod |
| **调用对接** | `_eval_FuncCall` 统一走 `_invoke_method`，BoundMethod 自动解包 `self` + 实参 |
| **逃逸守护** | `_reject_bound_method` 在赋值/传参/返回三个位置拦截，抛 `类型错误` |
| **oop.jk 相容** | `狗.叫声`（0 参）保持访问即调用，零回归 |

### ADR-08 顶层控制信号拦截（治理项 3 · D-05）

| 项 | 决策 |
| --- | --- |
| **拦截点** | `Evaluator.eval()` 最外层 + REPL 顶层求值处（两处） |
| **不触碰** | `_eval_FuncCall` / `_eval_MethodCall` / 循环体内的现有信号捕获（R-C 保护） |
| **错误类别** | `SYNTAX`（结构性误用） |
| **文案** | 三条固定字符串，由 PRD AC-59/61/63 锁定 |

### 7.4 风险提示

1. **限制 1 的用户沟通（中）**：白名单全域共享意味着"一旦定义了名为 `长度` 的方法，同文件内所有 `长度` 都变成标识符而非内建动词"。这是方案 A 的固有 trade-off，错误消息可读可定位，但用户可能困惑。须在 CHANGELOG v0.3.1 的"已知行为"段落准确说明。
2. **性能未验证（低）**：`_try_user_def_strict` 对 user_defs 集合做线性扫描（sorted by len, reversed），大文件 + 大量用户定义时可能出现分词性能退化。暂无基准数据，登记 A-12 跟踪。
3. **`python -m jikuai` 不可用（低）**：不影响官方入口 `jk`，但可能影响部分验证者首次复现 G-2。README 明确标注 `jk` 为唯一官方入口。
