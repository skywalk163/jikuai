## 2. 架构决策（本轮由 debugger RCA 替代架构师环节）

### RCA-D10 变参动词实参不足泄漏 Python 异常

- **根因定位**：`parser.py::_parse_argument` 路径**缺少中缀二元动词合并**（该逻辑只存在于 `_parse_verb_or_primary` L520-525）。`打印 郑数 加 2` 被解析为 `打印` 吞噬 `郑数` 作为独立参数，`加` 当成新前缀调用只拿到 1 个操作数 → evaluator 无元数守卫 → Python `TypeError` 原文经 `_eval_node` 的 `except TypeError` 分支塞进 `ErrorInfo.message`。
- **决策**：**方案 A（parser 中缀合并）+ 方案 B（evaluator 元数守卫）双层叠加**。
  - 方案 A 让 parser 在动词参数位置也能吸收右侧中缀二元动词，符合用户直觉。
  - 方案 B 是最后一道守门线，即便 parser 变参贪心策略未来再次出现类似盲区，也不会泄漏 Python 实现细节。
- **否决方案 C**（强制括号）：认知负担高、破坏"元数驱动免括号"设计理念。

### RCA-D11 `python -m jikuai` 不可用

- **根因定位**：`pyproject.toml` 只声明 `jk` / `jikuai` console_scripts，`src/jikuai/` 下无 `__main__.py`。
- **决策**：新增 3 行 `__main__.py` 委托 `.main:main()`。
- **前置论证**：`sys.argv` 在三入口（`jk` / `python -m jikuai` / `python -m jikuai.main`）下零漂移（`main()` 只读 `sys.argv[1:]`）——已由 debugger 论证。

### RCA-D12 `_class_regions` 启发式定位与 prescan 一致性缺陷

- **根因定位**：`_class_regions` 与 `_prescan_self_fields` 用**未掩码的 `self.source`**，而 `_prescan_definitions` 已用 `_scan_src`（掩码后）——**同一预扫描系统内的一致性缺陷**。
- **debugger 实际复现成功**（v0.3.1 QA 上轮未复现）：多行字符串内含 `类 假类：\n 自身.伪字段 = 1` → `伪字段` 被误登记；`-- 类 甲：` 注释同理。
- **决策**：2 行改动切到 `_scan_src`。安全侧倾——最差情况是掩码内部结构变化导致漏登记合法字段（退化为 D-09 现象），不会误切合法名字或污染类外语义。

2. **本轮 debugger 已完成技术层 RCA**，但语义边界（例如"是否允许类外调用同类内定义的方法名"）属产品决策，不适合 debugger 单人裁决
3. **X3 违反 R-E** 已在 debugger 报告标注，PM 需在"用户体验一致性"与"架构简洁"之间做取舍
4. **潜在的用户可见变更多**：例如若采纳 X2，则 `打印 长度(郑列)`（不用 DOT）将恢复 `长度` 的内建语义，与括号写法一致——需 PM 判定这是否是期望的用户心智模型
5. **必须做穷举写法清单**：类似 v0.3.1 治理项 1 的 W-01~W-24，覆盖所有"用户名与内建动词同名"的组合，PM 环节不可省

### 7.3 风险提示

1. **语义变化的用户沟通（中）**：D-10 方案 A 让 `打印 郑数 加 2` 从"报错"变为"打印 7"。虽然无用户依赖，但发布通告应突出"如果你的脚本以前依赖此处报错来做输入校验，请显式检查"。CHANGELOG 独立小节已披露，通告应引用。
2. **`jk` console_script 未实机（低）**：O-01 已裁决登记 A-14。风险仅在极少数打包差异场景暴露，函数层字节级一致证明业务逻辑无差异。
3. **ADR-06 副作用继承（低）**：v0.3.1 已披露的"同次分词全域生效"限制在 v0.3.2 未消化。用户规避写法（重命名 / 拆分文件 / 拆分 REPL 会话）在文档中明确。
4. **防御性冗余（低）**：`_check_verb_arity` 的 `>` 分支不可达但保留，维护成本 = 3 行代码，收益 = 未来 parser 策略变更时的守护。O-02 已裁决保留。
