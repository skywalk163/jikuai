## 3. 架构决策（ADR-09 / 10 / 11 / 12）

### ADR-09 · 类作用域限定白名单（**采纳 X1**）

G5 根因决议。`DefEntry` 记录字符区间，`_try_user_def_strict` 按 `pos` 查 `ScopeMap` 判定白名单是否生效。

| 方案 | 结论 |
|---|---|
| X1（采纳） | 类作用域内白名单生效、类外内建动词语义保留 |
| X2（否决） | 废白名单改运行时消歧 → 打断元数守卫、干扰括号调用 |
| X3（否决） | 同名报错 → 破坏现有代码、违反 AC-66 |

依据：语义精确对齐 AC-66~70；保留 R-E 单入口；与 G2/G3 正交；作用域为纯静态区间可独立单测。

### ADR-10 · Python 桥独立模块 + `蟒:` 前缀

- 新增独立 `pybridge.py`；Python 模块以 `蟒:` 前缀显式导入。
- `蟒:` 采用**单字引导 + 紧邻 `:` 双条件**触发，不与百家姓标识符、内建动词冲突。
- 否决「无前缀先查 `.jk` 再查 `.py`」：模块解析歧义 + 诊断复杂化。

### ADR-11 · Python 函数必须括号调用，不进 `VERB_ARITY`

否决无括号调用：C 扩展函数签名不可探测，会破坏元数集中声明的可审计性。

### ADR-12 · 元数守卫从 evaluator 前移到 parser

使元数错误在语法期即拦截，配合 ADR-11 保持元数声明的单一权威来源。

### 类型映射表与安全约束

- 映射：`整数↔int` / `小数↔float` / `字符串↔str` / `布尔↔bool` / `空↔None` / `列表↔list` / `字典↔dict` / `人民币↔Decimal`；`BoundMethod` **禁止跨界**。
- 安全：`os.system` / `subprocess.Popen` / `eval` / `exec` 默认拒绝；`jikuai.load` 拒绝 `..` 与绝对路径逃逸；异常路径脱敏。
- **重要披露**：拒绝清单是**黑名单而非完整沙箱**，CHANGELOG 已明示，见 §8 R-03。

## 6. 分歧与裁决记录

### 6.1 DEF-01 · AC-68「同类内内建动词遮蔽」语义之争

**分歧点**
类 `甲` 中定义 `方法 长度` 后，同类另一方法体内 `长度 自身.吴项` 走 IDENT 路径报「未定义的标识符：长度」，未回落到内建动词。PRD AC-68 字面表述要求此处仍保留内建语义。

**各方立场**

| 方 | 立场 |
|---|---|
| 产品经理（PRD 原文） | 按字面：类内定义同名方法后内建语义不应丢失 |
| 工程师 | 当前语义是 ADR-09 X1 的正确结果：类作用域内该名字归属本类方法 |
| QA | 按 PRD 字面应判 FAIL；但**实质支持工程师的语义**（强让裸名回落内建会与 `自身.长度()` 二义，属 X3 级改动）；不代产品经理改写 AC，裁决权上交 |

**裁决（M1 阶段拍板）：采纳 QA 拆分建议**
1. **AC-68 口径收敛为跨作用域** —— 「某内建动词名被某类登记后，该名字**在该类作用域之外**仍保留内建动词语义」，按此判 **PASS**；
2. **新开 AC-68b** —— 同类内遮蔽时诊断文案必须可操作：「`长度` 已被本类方法遮蔽，请改名或使用 `内建:长度`」，仅改 evaluator 错误建议逻辑；
3. 要求产品经理回填 PRD 修订版。

**M3 收尾时状态**：AC-68b **已在 M1 尾段实现并测试关闭**（并入 192 passed 增量）。

**裁决依据**
- 「类内方法名在本类内可见」是作用域定义性后果，不是缺陷；反其道会产生真正的语义事故（`长度` 与 `自身.长度()` 指向不同实体）；
- 让同类内裸名回落内建属 X3 级改动，而 X3 已被 ADR-09 明确否决 —— 「架构 vs 实现：以架构约束为先」；
- 非本轮回归：legacy 模式同样失败，证明是 v0.3.2 起就存在的既有行为；
- 但用户遇到的「未定义的标识符」文案是真实体验缺口，必须以 AC-68b 作**补偿性交付**同步落地，不允许用「解释」关闭缺陷。

### 6.2 DEF-05 · AC 编号区间与用例组数不匹配

**分歧点**：AC-78 ~ AC-90 为 13 个编号，PRD 声明 15 组边界用例，无法 1:1 追溯。

**裁决**：**子编号方案** —— 新增 `AC-90a` / `AC-90b`，不做全局重编号。

**M3 收尾时状态**：AC-90a / AC-90b 已由产品经理回填、由 QA 补齐自动化并通过。

**裁决依据**
- 不能删组：15 组已 15/15 实测通过，删减等于丢弃质量证据；
- 不能扩区间：AC-91~AC-123 已分配 M2/M3，扩到 AC-92 会正面冲突并触发全局位移；
- 子编号成本最低、追溯完整、零连锁成本。
