# 三个端到端 demo

每个 demo 走完整链路：**需求文本 → select → glue → 生成的极快代码 → 实际运行输出 → token 压缩比**。

跑法（三个都能独立执行，输出即下文内容）：

```
python tools/ai-bridge/demos/demo1_数值统计.py
python tools/ai-bridge/demos/demo2_文本清洗.py
python tools/ai-bridge/demos/demo3_中文报表.py
```

每个 demo 都跑两条路径：**A = 用原子块拼装**，**B = 用一级块一步到位**。
对比 A/B 是为了让「块生态的层级设计」这件事变得可测量，而不是口号。

---

## 压缩比怎么算的（先说方法，再看数字）

```
比率 = len(生成的粘合极快源码.strip()) / len(等价 Python 实现.strip())
```

三点必须讲清，否则这个数字会被误读：

1. **用字符数，不用真 token 数。** 真 token 数依赖具体分词器，不同模型对中文的
   token 化差异很大；字符数任何人都能复算。中文字在多数 BPE 分词器里约
   1～2 token/字，英文标识符约 0.25～0.5 token/字符——所以本比率对极快
   （几乎全中文）是**偏悲观**的，真实 token 比率通常比这里报的更差一点。
   **别拿这个数当上限吹。**
2. **分母是我们手写的一份等价 Python**，不是「AI 真实会写的代码」。AI 通常
   还会附带 docstring、类型标注、边界防御，实际分母更大、比率更好看。
   我们刻意没往分母里灌水。
3. **分子不含块本身的实现。** 块的代码已经在 `stdlib/blocks/` 里、已被测试
   覆盖，属于**一次性成本**；粘合代码是**每次请求的边际成本**。这正是本方案
   省 token 的机制——省的是边际，不是总量。

## Demo 1：数值统计

需求：`对一组销售额求和并算平均`

选块结果 top-5（分数由 `select.py` 的字符重叠打分给出）：

| 名称 | 领域 | 分数 | 导出名 |
|------|------|------|--------|
| 求和 | 数据 | 11.9 | 汇总 |
| 均值 | 数据 | 3.9 | 均数 |
| 批量统计 | 数据 | 2.6 | 统览 |
| 请求组装 | 网络 | 2.3 | 备请 |
| 升序 | 数据 | 1.3 | 顺排 |

`求和` 与 `均值` 都进了前二，需求里的「求和」「平均」被正确对上了。
`请求组装` 是噪声（「求」「组」误命中），排第四不影响使用。

### A · 原子块拼装

```jikuai
-- 由 极快 AI 桥接 v0（选块 + 粘合）自动合成
-- 需求：对一组销售额求和并算平均

从 blocks.数据.求和 导入 汇总。
从 blocks.数据.均值 导入 均数。

定义赵料=列 100 200 150 300 250。

-- 步骤 1：对销售额列表求和
定义赵果1=汇总(赵料)。
-- 步骤 2：对同一列表求算术平均
定义赵果2=均数(赵料)。

打印 赵果1。
打印 赵果2。
```

实际运行输出：

```
1000
200.0
```

压缩比：`204 / 596 = 0.342`

### B · 一级块一步到位

```jikuai
-- 由 极快 AI 桥接 v0（选块 + 粘合）自动合成
-- 需求：对一组销售额求和并算平均

从 blocks.数据.批量统计 导入 统览。

定义赵料=列 100 200 150 300 250。

-- 步骤 1：一步得到 [总和, 均值, 最小, 最大]
定义赵果1=统览(赵料)。

打印 赵果1。
```

实际运行输出：

```
[1000, 200.0, 100, 300]
```

压缩比：`156 / 596 = 0.262`（比 A 还多给了最小/最大两个值）

## Demo 2：文本清洗

需求：`把多行文本去重并排序`

选块结果 top-5：

| 名称 | 领域 | 分数 | 导出名 |
|------|------|------|--------|
| 去重 | 数据 | 11.9 | 精简 |
| 文本清洗 | 数据 | 9.1 | 净化 |
| 头部组装 | 网络 | 5.2 | 造头 |
| 序出 | 数据 | 3.9 | 存档 |
| 文本雅正 | 中文 | 3.9 | 雅正 |

`去重` 与 `文本清洗` 在前二。`头部组装` 因描述里的「列表」「排列」误命中——
v0 字符匹配的典型噪声。

### A · 四步流水线

本套 demo 里**唯一真正链式传参**的例子：每一步用 `参数: ["赵果N"]` 把上一步
结果喂进去（v0 的 glue 不会自动推断这个链条，靠方案显式写）。

```jikuai
-- 由 极快 AI 桥接 v0（选块 + 粘合）自动合成
-- 需求：把多行文本去重并排序

从 blocks.数据.文本切分 导入 切片。
从 blocks.数据.去重 导入 精简。
从 blocks.数据.升序 导入 顺排。
从 blocks.数据.文本合成 导入 缝合。

定义赵料="香蕉,苹果,苹果,橙子,香蕉,梨"。
定义赵隔=","。

-- 步骤 1：按逗号切成列表
定义赵果1=切片(赵料 赵隔)。
-- 步骤 2：去重，保留首次出现顺序
定义赵果2=精简(赵果1)。
-- 步骤 3：升序排序
定义赵果3=顺排(赵果2)。
-- 步骤 4：用逗号合回字符串
定义赵果4=缝合(赵果3 赵隔)。

打印 赵果4。
```

实际运行输出：

```
梨,橙子,苹果,香蕉
```

压缩比：`316 / 711 = 0.444`

### B · 一级块一步到位

```jikuai
从 blocks.数据.文本清洗 导入 净化。

定义赵料="香蕉,苹果,苹果,橙子,香蕉,梨"。
定义赵隔=","。

-- 步骤 1：切分→去重→升序→合成，一步完成
定义赵果1=净化(赵料 赵隔)。

打印 赵果1。
```

实际运行输出（与 A 完全一致，`test_demo2_端到端` 断言了这一点）：

```
梨,橙子,苹果,香蕉
```

压缩比：`159 / 711 = 0.224`

## Demo 3：中文报表

需求：`把金额转成中文大写`

选块结果 top-5：

| 名称 | 领域 | 分数 | 导出名 |
|------|------|------|--------|
| 金额雅写 | 中文 | 14.7 | 银码 |
| 金额报表 | 中文 | 10.8 | 账单 |
| 数字中文 | 中文 | 10.2 | 汉数 |
| 农历 | 中文 | 8.9 | 阴历 |
| 属相表 | 中文 | 8.9 | 属相 |

top-5 全在 `中文` 领域，前三个正是这个需求真正需要的块。这是三个 demo 里
选块质量最高的一个——因为需求用词与块的名称/描述高度重合。

### A · 金额雅写原子块

```jikuai
从 blocks.中文.金额雅写 导入 银码。

-- 步骤 1：带角分的小额 → 大写金额
定义赵果1=银码(1234.56)。
-- 步骤 2：万级整数 → 大写金额（应带「整」）
定义赵果2=银码(88888)。

打印 赵果1。
打印 赵果2。
```

实际运行输出：

```
壹仟贰佰叁拾肆元伍角陆分
捌万捌仟捌佰捌拾捌元整
```

压缩比：`173 / 1546 = 0.112`

### B · 金额报表一级块

```jikuai
从 blocks.中文.金额报表 导入 账单。

-- 步骤 1：小额 → 三元报表
定义赵果1=账单(1234.56)。
-- 步骤 2：大额 → 三元报表
定义赵果2=账单(88888)。

打印 赵果1。
打印 赵果2。
```

实际运行输出：

```
[1234.56, '壹仟贰佰叁拾肆元伍角陆分', '一千二百三十四']
[88888, '捌万捌仟捌佰捌拾捌元整', '八万八千八百八十八']
```

压缩比：`160 / 1546 = 0.103`

第三元「一千二百三十四」不含小数——底层内建动词 `汉字数字` 先做 `int()`
截断，`大写金额` 才保留角分。这是既有语义差异，不是本 demo 引入的。

## 汇总

| Demo | 路径 | 粘合字符 | 等价 Python 字符 | 比率 |
|------|------|---------:|-----------------:|-----:|
| 1 数值统计 | A 原子块 | 204 | 596 | 0.342 |
| 1 数值统计 | B 一级块 | 156 | 596 | **0.262** |
| 2 文本清洗 | A 四步流水线 | 316 | 711 | 0.444 |
| 2 文本清洗 | B 一级块 | 159 | 711 | **0.224** |
| 3 中文报表 | A 原子块 | 173 | 1546 | 0.112 |
| 3 中文报表 | B 一级块 | 160 | 1546 | **0.103** |

两条规律，都是实测出来的、不是设计出来的：

1. **一级块永远比原子块拼装更省**（B < A，三次全中）。高层块把粘合逻辑也
   吃进了块内部，边际成本随之下降。这给块生态的「层级」标签提供了实测依据。
2. **领域规则越密集，省得越多。** 中文大写金额（0.103）远好于数值统计
   （0.262）——因为「壹贰叁…元角分整」的零省略、进位单位、角分处理是
   规则密集且边界易错的活儿，而求和只是一个循环。**块生态在「中国特色
   规则」这类高知识密度的地方价值最大，在通用算法上价值有限。**
