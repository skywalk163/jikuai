# 《块选择协议 v0》

把「用户自然语言需求」映射为「一组块的选择 + 参数」，再由粘合器合成可运行极快代码。

## 数据流

```
用户需求（字符串）
      │
      ▼
[选块]  select.py：本地关键词匹配（v0 不外接大模型）
      │
      ▼
选块方案（JSON，本文件定义结构）
      │
      ▼
[粘合]  glue.py：合成极快源码
      │
      ▼
可运行极快代码 → python -m jikuai / run_source
```

v0 用**本地关键词匹配**做「选块」这一步——先把协议跑通。真正的语义选择
（理解「求和再算平均」= 求和块 + 均值块）留 v0.13.0。

## 选块方案 JSON 结构

```json
{
  "需求": "把一批数字求和再算平均",
  "共享": [
    {"名": "赵料", "值": "列 100 200 150 300 250"}
  ],
  "步骤": [
    {"块": "求和", "领域": "数据", "导出名": "汇总", "说明": "对列表求和", "参数": ["赵料"]},
    {"块": "均值", "领域": "数据", "导出名": "均数", "说明": "算平均",   "参数": ["赵料"]}
  ],
  "打印": ["赵果1", "赵果2"]
}
```

### 字段定义

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| `需求` | 否 | string | 原始自然语言需求，仅作生成代码里的注释 |
| `共享` | 否 | array | 前置常量/输入定义，先于步骤生成 `定义<名>=<值>。` |
| `共享[].名` | 是 | string | 变量名，须**词法原子**（整体是单个 IDENT，见 ADR-15 §3.7） |
| `共享[].值` | 是 | string | 极快表达式片段，如 `列 1 2 3` 或 `"文本"` |
| `步骤` | 是 | array | 至少一个步骤 |
| `步骤[].块` | 是 | string | 块的**目录名**（索引里的 `名称`），用于 `导入` 语句 |
| `步骤[].领域` | 是 | string | 块所属领域（数据/中文/网络/工具） |
| `步骤[].导出名` | 是 | string | 块的**导出名**，用于调用；由 `extract_exports` 从 `.jk` 得到 |
| `步骤[].说明` | 否 | string | 该步骤的注释 |
| `步骤[].参数` | 否 | array | 调用实参（每项是极快表达式片段）。缺省则生成占位符 `?` 并注释「需人工填参」 |
| `打印` | 否 | array | 要打印的变量名。缺省则打印每步结果变量（`赵果1`、`赵果2`…） |

### 关于「导入用目录名、调用用导出名」

ADR-15 §3.7 规定：

```jikuai
从 blocks.数据.求和 导入 汇总。   -- 导入语句用目录名「求和」
打印 汇总(列 1 2 3 4 5)。          -- 调用用导出名「汇总」
```

所以方案里 `块`（目录名）与 `导出名` 是两个不同字段。选块器负责把二者一并填好：
`块` 来自索引 `名称`，`导出名` 由 `jikuai.pkg.blocks.extract_exports` 从对应
`.jk` 文件里提取（索引本身**不含**导出名字段）。

## 粘合器生成规则（glue.synthesize）

1. 顶部注释：`-- 由 极快 AI 桥接 ... 自动合成` + `-- 需求：...`
2. 为每个步骤生成一行 `从 blocks.<领域>.<块> 导入 <导出名>。`（去重）
3. `共享` 定义逐条生成 `定义<名>=<值>。`
4. 步骤逐个生成 `定义赵果N=<导出名>(<参数空格拼接>)。`
   - 无 `参数` → 实参写 `?`，上一行加注释「需人工填参」
   - 开了 `自动链式` 且类型图推得出 → 实参写推断出的变量链
5. `打印` 列表（或默认每步结果变量）逐条生成 `打印 <名>。`

## 协议扩展：自动链式（v0.14.0 W3-W4）

`步骤[].参数` **可以整体省略**，由 `glue.TypeGraph` 按 ADR-26 类型词表推断。

```json
{
  "需求": "去重后升序再求和",
  "共享": [{"名": "赵料", "值": "列 3 1 2 2"}],
  "步骤": [
    {"块": "去重", "领域": "数据", "导出名": "精简", "参数": ["赵料"]},
    {"块": "升序", "领域": "数据", "导出名": "顺排"},
    {"块": "求和", "领域": "数据", "导出名": "汇总"}
  ]
}
```

```
python tools/ai-bridge/glue.py 方案.json --自动链式
```

### 推断规则

- **节点** = 已产出变量：`共享` 常量（类型未知 → 视为 `任意`）+ 每步结果 `赵果N`
- **边** = 「某变量的类型可喂某步骤的第 k 个入参」，类型取自块的 `块.json`
  `输入[].类型` / `输出.类型`
- **消费顺序**：同一形参有多个可喂变量时，**最近产出优先**（所以两步链天然
  接上 `赵果i → 赵果i+1`）
- **可喂性**比纯子类型更严：
  - `T <: 任意`、`任意` 可喂任何形参（动态值/共享常量走这条）
  - `列表<T>` 喂 `列表<U>` 当且仅当 `T` 可喂 `U`（元素协变）
  - `字典<K,V>` 喂 `字典<K2,V2>` 要求键、值都可喂
  - `元组[T1..Tn]` 喂 `元组[U1..Un]` 要求元数等长且逐位可喂
  - **`元组` 不自动喂 `列表`**——固定形状返回值必须人工拆包
  - 源是 `联合` → 每个候选都要可喂；目标是 `联合` → 可喂任一候选即可

### 拒绝不静默

`TypeGraph.plan(steps, 共享)` 返回三元组 `(实参方案, 未匹配, 拒绝理由)`：

- `实参方案`：每步一份实参名列表；整步推不出则该项为 `null`
- `未匹配`：`[(步序, 入参名, 原因)]`
- `拒绝理由`：人读串。类型近似但不可喂时必须说清，例如

  ```
  赵果1 的输出是 元组[数,数,数,数]，非 列表<数>；需人工拆包后再喂步骤2「升序」的入参「列表」
  ```

`synthesize(..., 自动链式=True)` 会把这些理由写进生成源码的头部注释，
而不是硬塞一个类型不符的实参让代码在运行期炸。

### 评测与基准

- 评测集：`tools/ai-bridge/评测集-链式.json`（30 条，标注 `应链`/`应拒`/`边界`）
- 基准脚本：`python tools/ai-bridge/bench_glue.py`
- 门槛：自动链式命中率 ≥60%、语义荒谬率 =0、应拒用例 100% 给出可读理由
  （同一门槛由 `tests/test_glue_type.py::BenchThresholdTest` 钉进 pytest）

## v0 局限（务必知晓）

- **选块靠字符重叠**：同义改写（「加总」vs「求和」）可能命中不到。
- ~~**参数不自动推断**~~ → v0.14.0 已由 `--自动链式` 补上（见上节）。
- ~~**链式传参靠人工**~~ → 同上；推不出的仍显式拒绝并给理由。
- **无类型校验** → v0.14.0 已有 ADR-26 类型词表 + G14 精度门禁；
  但校验只覆盖「块之间的传参」，`共享` 常量的值仍是未标类型的极快表达式
  （视为 `任意`），写错要到运行期才报。
