# 极快 Web UI —— 本地开发通道（v0.15.0 W17/W18，v0.16.0 W31 可写化）

三段式设计语言 `[需求]→[候选]→[方案]→[源码]→[结果]` 在浏览器里的落地，
与 `jk 块 选/组/跑` 完全同构，只是换了传输层。纯标准库实现（`http.server`），
**零新增 pip 依赖**。v0.16.0 W31 起支持方案持久化与历史（仍零依赖）。

---

## ⚠ 安全风险声明（先读这一段）

**本服务无鉴权，仅限本机开发用途，不得暴露到 `0.0.0.0`。**

`/api/跑` 会在本机进程内执行你提交的极快代码（等价于本地 RCE）；W31 起
`/api/方案/存` 还会往你的家目录 `~/.jikuai/web-方案/` 写文件。因此：

- 默认**只监听 `127.0.0.1`**，**不要**改成 `0.0.0.0`，**不要**反向代理到公网；
- 仅供本机单人开发调试用，**不是**生产服务，也**不是**多租户服务；
- 需要给他人用的场景，请改走 CLI（`jk 块 跑`）或自建带沙箱的通道。

启动时会打印一行中文风险提示；把监听地址设成非回环地址会再追加一条警告。

## 可写化评估（W31 · 先评估后动手）

WBS 要求「先出评估结论，再动手，且结论倾向不引框架」。逐条评估如下。

| # | 可写化交互 | 原生 JS 能否胜任 | 判断 |
| - | ---------- | --------------- | ---- |
| 1 | **编辑**方案（改需求/喂数据/选块） | 已有：`<textarea>` + `<input>` + 候选卡片，v0.15.0 就在做 | ✅ 无需框架 |
| 2 | **保存**当前方案 | 一个按钮 + 一次 `fetch(POST)`，序列化用 `组装方案()` 现成函数 | ✅ 无需框架 |
| 3 | **列历史** | `fetch(GET)` → 数组 → `createElement` 重建侧栏。上限 200 条，整体重建的开销可忽略 | ✅ 无需框架 |
| 4 | **删历史** | 每条一个 `×` 按钮 → `fetch(DELETE)` → 重新列 | ✅ 无需框架 |
| 5 | **从历史恢复** | `fetch(GET /<id>)` → 回填输入框 + 重建候选 + 重新 `组` | ✅ 无需框架 |

**结论：能，不引框架。** 理由：

1. **交互复杂度低**——没有一处需要「响应式数据双向绑定」「虚拟 DOM diff」
   「客户端路由」这类框架真正解决的问题。历史侧栏是**单向数据流**：
   服务端列表 → 整体重建 DOM，不做增量 diff，因此不存在需要框架来管理的
   「本地状态与远端状态不一致」难题。
2. **沿用 W18 的 13.55 KB 单页成功经验**——v0.15.0 已经用原生 JS 做出了
   语法高亮、诊断行列高亮、神经开关、快捷键等更复杂的交互，历史 CRUD 的
   复杂度远低于它们。引框架反而会打破「零依赖、无 CDN」的品牌主张。
3. **体积可控**——加完历史侧栏 + 保存按钮后单页 gzip 实测 **16.28 KB**，
   在提升后的 18 KB 上限内还有余量。而任何主流框架（React ~40 KB gzip、
   Vue ~34 KB）单是运行时就会击穿上限。

**没有任何一条交互需要框架。** 若未来要做多标签页实时同步、离线队列、
撤销/重做栈这类真正的状态管理难题，再重新评估——那不属于本轮范围。

## 起服务（三行）

```sh
cd g:\jikuai
python tools/web/server.py                       # 默认 127.0.0.1:5000
python tools/web/server.py --端口 8000            # 换端口（--port 亦可）
```

可选参数：

| 参数              | 别名       | 默认        | 说明                              |
| ----------------- | ---------- | ----------- | --------------------------------- |
| `--地址 <host>`   | `--host`   | `127.0.0.1` | 监听地址。改成非回环会打印安全警告 |
| `--端口 <port>`   | `--port`   | `5000`      | 监听端口                          |

起好后浏览器打开 `http://127.0.0.1:5000/`。

## 九个端点

所有响应都是 `Content-Type: application/json; charset=utf-8`，
`ensure_ascii=False`（中文直出）。字段一律取自 `jikuai.service.schema`
三通道统一协议（唯一真源，见 [`docs/协议-三通道.md`](../../docs/协议-三通道.md)），
本通道**不自造字段**。

错误分层：

- **调用方的错**（坏 JSON、字段不合法、块不存在）→ `4xx` + `{"错误": "中文原因"}`
- **执行期业务失败**（源码占位符没填、解释器抛异常）→ `200` + `跑响应.执行结果` 带 `错误` 字段
  （业务失败不是传输失败）
- **服务器内部错误** → `500`，只回异常类名 + 消息，**不吐 traceback**

### 1. `GET /api/blocks`

返回 `stdlib/blocks/索引.json` 原文（`{版本, 生成时间, 块:[...]}`）。前端靠它
把候选补成方案里的 `导出名`（块条目自带 `导出` 数组）。

```sh
curl http://127.0.0.1:5000/api/blocks
```

### 2. `GET /api/能力`

能力探测。W19 前端靠它决定「神经」开关能不能点亮，**字段名固定不改**。

```json
{"神经可用": true, "索引版本": "0.15.0", "块数": 105}
```

- `神经可用`：sidecar 命令可解析（`embed_client.resolve_command`）**且**
  向量索引能加载（`retrieval.load_vector_index`）。两个判据都复用运行时现成
  逻辑，不另搞一套 `os.path.isfile`——否则会和真实检索路径的判据漂开。
- `索引版本` / `块数`：取自 `索引.json`（与 `/api/blocks` 同源）；索引读不到
  时给 `""` / `0`，**不报错**（能力探测本身不该失败）。

```sh
curl http://127.0.0.1:5000/api/能力
```

### 3. `POST /api/选`

需求文本 → 候选列表（协议 `选响应`）。

请求体：

```json
{"需求": "把一批数求和再算平均", "top": 5, "神经": false}
```

- `需求`：非空字符串（必填）
- `top`：整数 `1..50`（可选，默认 5）
- `神经`：布尔（可选，默认 `false`）。为 `true` 才起 sidecar 子进程拉查询向量

响应：

```json
{
  "需求": "把一批数求和再算平均",
  "候选": [{"名称":"求和","领域":"数据","层级":0,"描述":"…","分数":6.1234,"路径":"[启发式]"}],
  "降级说明": "神经检索不可用，降级到启发式：…"
}
```

`候选[i]` 逐字段就是 `schema` 协议候选：`{名称, 领域, 层级, 描述, 分数, 路径}`
（`分数` 保留 4 位小数、`层级` 是 int）。`降级说明` 是协议的正式可选字段，
仅在 `神经:true` 且拿不到向量时出现。

```sh
curl -X POST http://127.0.0.1:5000/api/选 \
  -H 'Content-Type: application/json' \
  -d '{"需求":"求和","top":3}'
```

### 4. `POST /api/组`

方案 → 极快源码（协议 `组响应`）。请求体两种写法都收：

```json
{"方案": {"步骤":[{"块":"求和","领域":"数据","导出名":"汇总","参数":["赵料"]}],
          "共享":[{"名":"赵料","值":"列 1 2 3"}]}}
```

或直接把方案本体当 body（`jk 块 组 -` 的 JSON 原样贴）：

```json
{"步骤":[{"块":"求和","领域":"数据","导出名":"汇总","参数":["赵料"]}],
 "共享":[{"名":"赵料","值":"列 1 2 3"}]}
```

判据是「有没有顶层 `方案` 键」。入参先过 `schema.ensure_plan`（协议校验，
**多一个未知字段就 400**），再校验领域白名单与块目录存在。

响应：`{"源码": "-- 由 极快 AI 桥接…\n…\n"}`（末尾单个 `\n`）。

```sh
curl -X POST http://127.0.0.1:5000/api/组 \
  -H 'Content-Type: application/json' \
  -d '{"方案":{"步骤":[{"块":"求和","领域":"数据","导出名":"汇总","参数":["赵料"]}],"共享":[{"名":"赵料","值":"列 1 2 3"}]}}'
```

### 5. `POST /api/跑`

方案 → 组 → 执行 → 结果。请求体同 `/api/组`。

响应是协议 `跑响应` 信封 —— 与 `jk 块 跑 --json` **逐字同构**：

```json
{
  "源码": "-- 由 极快 AI 桥接（选块 + 粘合，类型图链式）自动合成\n…\n",
  "执行结果": {"stdout": "60\n", "stderr": "", "返回值": "60", "耗时毫秒": 1.234},
  "需求": "把一批数求和"
}
```

- `源码` 必需；`执行结果` 必需；`需求` 仅当方案里写了才出现。
- `执行结果.stdout` 是**原始字符串**（不是按行切的数组）。

失败（占位符未填 / 解释器报错）时 `执行结果` 追加 `错误` 字段、`返回值` 为空、
状态仍是 `200`；若能拿到 1-based 码点行列，还会带 `诊断` 数组：

```json
{"源码": "…",
 "执行结果": {"stdout": "", "stderr": "", "返回值": "", "耗时毫秒": 0.0,
              "错误": "方案有步骤的参数未指定（源码里出现「需人工填参」）；…"}}
```

```sh
curl -X POST http://127.0.0.1:5000/api/跑 \
  -H 'Content-Type: application/json' \
  -d '{"方案":{"步骤":[{"块":"求和","领域":"数据","导出名":"汇总","参数":["赵料"]}],"共享":[{"名":"赵料","值":"列 10 20 30"}],"打印":["赵果1"]}}'
```

## 方案持久化（6 ~ 9，v0.16.0 W31）

存档落在 `~/.jikuai/web-方案/<id>.json`（与 `~/.jikuai/注册表` 同一个家目录
约定）。环境变量 `JIKUAI_WEB_PLANS_DIR` 可以覆盖存档目录——这是测试与迁移用
的逃生舱，日常不需要动。

存档项字段全部取自 `schema.SAVED_PLAN_REQUIRED`：`{id, 标题, 时间戳, 方案}`。
**存的是方案而不是源码**：源码是方案的函数，块升级后从历史恢复出来的源码
是新的，而不是一份僵化的旧快照。

### 6. `POST /api/方案/存`

请求体（`方案` 信封式，或直接把方案本体当 body）：

```json
{"方案": {"步骤":[{"块":"求和","领域":"数据","导出名":"汇总","参数":["赵料"]}],
          "共享":[{"名":"赵料","值":"列 10 20 30"}], "需求":"把一批数求和"},
 "标题": "可选，缺省时取方案的「需求」，再缺就取首步骤的块名"}
```

方案入参先过 `schema.ensure_plan` + 领域白名单 + 块目录存在校验（与
`/api/组` 同一套），坏方案不落盘。响应：

```json
{"id": "e3e6f9e0f05e42adad30c3251d713889", "标题": "把一批数求和",
 "时间戳": "2026-08-10T10:39:31+00:00"}
```

`id` **由服务端 `uuid4().hex` 生成**，不接受调用方指定——手写 id 既可能落到
白名单外，也可能覆盖别人已存的方案。

### 7. `GET /api/方案/列`

按时间戳倒序（新在前）的元数据数组，**不含方案本体**（省流量，也免得把整批
共享量甩进列表 payload）：

```json
{"方案列表": [{"id":"e3e6f9e0…","标题":"把一批数求和","时间戳":"2026-08-10T10:39:31+00:00"}]}
```

坏 JSON / 非白名单文件名会被**跳过**并打 warning，而不是把整份历史读挂。

### 8. `GET /api/方案/<id>`

单个存档，含方案本体：`{id, 标题, 时间戳, 方案}`。id 不合白名单 → `400`；
文件不存在 → `404`。

### 9. `DELETE /api/方案/<id>`

删单个存档，回 `{"id": "…"}`。id 不合白名单 → `400`；不存在 → `404`。

```sh
curl -X POST http://127.0.0.1:5000/api/方案/存 \
  -H 'Content-Type: application/json' \
  -d '{"方案":{"需求":"把一批数求和","步骤":[{"块":"求和","领域":"数据","导出名":"汇总","参数":["赵料"]}],"共享":[{"名":"赵料","值":"列 10 20 30"}]}}'
curl http://127.0.0.1:5000/api/方案/列
curl -X DELETE http://127.0.0.1:5000/api/方案/<id>
```

## 已做的安全处理

- **只绑回环**：默认 `127.0.0.1`；改成非回环地址会额外打印一条警告。
- **静态目录穿越防护**：静态路径经 `realpath` 归一化（吃掉 `..`、**跟随符号链接**），
  再用 `commonpath` 确认仍在 `static/` 真实路径之内；拒绝绝对路径与盘符前缀。
  API 路由用 unquote 后的路径匹配，静态则只 unquote 一次以防 `%252e` 二次编码逃逸。
- **方案 id 白名单**（W31）：`ID_PATTERN = ^[0-9a-f]{8,64}$`，**严格锚定**。
  这一条正则同时挡掉 `..`、`/`、`\`、盘符前缀、百分号编码残留（unquote 之后
  才校验）、NUL 字节、超长名、以及 Windows 保留名（`CON`/`NUL` 都含非 hex 字符）。
  服务端生成的 `uuid4().hex` 是 32 位小写 hex，天然落在白名单内。
- **落盘路径双重防护**（W31）：过完正则后仍对 `join(根, id + '.json')` 做一次
  `abspath` 归一化，再确认 ① 归一化结果以 `根 + os.sep` 开头、② `dirname` 恰好
  等于根目录（即必须是根的**直接子文件**，不允许多一层）。单靠正则理论上够，
  第二道闸兜住「根目录本身经 `expanduser` 后不是自己以为的那一层」这类意外。
- **存储体积三道闸**（W31）：单档 `MAX_PLAN_BYTES = 64 KiB`（序列化后）、
  总量 `MAX_STORE_BYTES = 4 MiB`、条数 `MAX_PLAN_COUNT = 200`。三者都在**写之前**
  检查——写完再删的策略会在磁盘满时把用户已有的方案挤丢。超限回 `413`。
- **原子写**：先落同目录临时文件再 `os.replace`，避免半写状态被 `列` / `取` 读到。
- **请求体上限 1 MiB**：超限回 `413` 并分块排空已在途 body（否则 413 到不了客户端）；
  `Content-Length` 缺失/非法/为负 → `400`。
- **JSON 严格校验**：非 UTF-8、非合法 JSON、非对象 → `400` + 中文原因。
- **不泄露内部信息**：执行异常只回异常类名 + 消息，不回 traceback（栈里带服务端绝对路径）。
- **响应头**：`X-Content-Type-Options: nosniff` + `X-Frame-Options: DENY`。
- **执行串行化**：`redirect_stdout/stderr` 换的是进程级 `sys.stdout`，
  ThreadingHTTPServer 下用锁串行化 `/api/跑`，避免并发互串输出。
- **访问日志走 logging**，不污染 stdout。
- **前端 XSS**：候选描述、块名、stdout/stderr、**历史标题**一律 `textContent` 或
  显式 `esc()` 转义后再入 DOM，禁止裸 `innerHTML` 拼接；自写语法高亮先 `esc` 再包 `<span>`。
- **无外部依赖**：前端不引 React/Vue/Tailwind/Prism/hljs 及任何 CDN，语法高亮自写。

**仍然存在、且刻意不修的风险**：本服务无鉴权，任何能访问回环地址的本机进程
都能读/写/删你的方案存档，也能触发 `/api/跑`。这在「单人本机开发工具」的定位
下是可接受的——加鉴权解决不了同一台机器上的同一个用户，真要隔离得上沙箱。
**这也正是「不得暴露到 `0.0.0.0`」不是建议而是硬约束的原因。**

## `降级说明` 与 W20 收敛（v0.15.0）

`神经:true` 但 sidecar 拿不到查询向量时，服务降级到启发式检索，并在 `/api/选`
响应里附一个顶层字段 `降级说明`（字符串）——降级不是失败（返回码仍 200、
候选照给），但用户勾了神经却拿到启发式必须被告知，藏进日志等于骗人。

W20 收敛已把这条正式写进 `service.schema` 的 `SELECT_ENVELOPE_OPTIONAL`：
它是**协议**的可选字段（三通道共用），不再是本通道的私货。同批收敛还有：

- `/api/跑` 由裸 `执行结果` 提升为 `跑响应` 信封，与 `jk 块 跑 --json` 逐字同构；
- 新增 `/api/能力` 给 W19 前端点亮「神经」开关；
- `/api/组` 输入过 `schema.ensure_plan`——协议禁止通道私自加字段，多一个键就 400。

细节见 [`docs/协议-三通道.md`](../../docs/协议-三通道.md)。
