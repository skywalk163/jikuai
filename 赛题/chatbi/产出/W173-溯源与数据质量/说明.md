# W173 · 溯源面板 + 等价 SQL 导出 + 数据质量检查（v0.28.0）

三件交付物都是**纯函数式导出**：不连库、不渲染图片、不执行 SQL。

工具在 [`tools/ai-bridge/溯源.py`](../../../../tools/ai-bridge/溯源.py)，两条子命令：

```bash
python tools/ai-bridge/溯源.py 面板 <方案.json> [--json] [--出 <文件>]
python tools/ai-bridge/溯源.py SQL  <方案.json> [--json] [--出 <文件>]
```

`--出` 写 UTF-8 无 BOM 文件。存档产出物请用它而不是 shell 重定向——Windows 控制台按
GBK 转码会把 `单车电耗均值` 这类中文列名压坏，本目录里的 `.txt` 全是这么生成的。

## 一、溯源面板：四要素

`R1-溯源面板.txt`（源方案 `../W172-角色视角/R1-厂长-单车电耗趋势-方案.json`，7 步）。
每步给出 DoD 要求的四要素：

- **块名** —— 取自 `块.json` 的 `名称`（不是导出名，两者可以不同）
- **版本** —— 取自 `块.json` 的 `版本`。**必须走 `load_block_metadata`**：
  `索引.json` 的条目字段集里根本没有 `版本`，从索引拿会静默拿不到
- **口径声明** —— 块的 `描述` 原文。这是「这个数按哪个口径算的」的唯一权威来源，
  面板不做摘要、不做改写
- **生成的 `.jk` 源码行** —— `glue.synthesize` 那一行 `定义赵果N=<导出名>(<实参>)。`

`glue.synthesize` 只回一个字符串、**不回「步骤 → 行」的映射**，所以定位靠固定前缀
`定义赵果N=`（`glue.py` 里写死的模板，`定义` 与变量名之间无空格）。

## 二、等价 SQL：只作展示，一行都不执行

`R1-等价SQL对照表.txt` —— 7/7 步登记，附 `WITH` 链全文（一步一个 CTE，CTE 名 = 该步
结果变量，这就是「逐步对应」的落地方式）。

三条硬约束，改动时别磨掉：

1. **从不执行**。模块里没有 `sqlite3`、没有任何 DB-API import，也不接受连接串。
   沿用 `网络/请求组装` 的「只产出请求描述，不发起连接」先例。
2. **没登记的块如实说「未登记」，绝不猜**。一段看着像样但口径错了的 SQL 比报错糟得多。
3. **`WITH` 全文只在每一步都登记时才给**。否则为空 + 一句「哪几步没登记」——
   半截 SQL 会被误当成「能跑的那份」。

已登记 15 个块（`表载入`/`窗口`/`窗口补集`/`单车电耗现成`/`能耗汇总`/`停线汇总表`/
`缺陷汇总`/`缺陷率`/`基线偏离`/`窗间对比`/`趋势判定`/`排序`/`取前N`/`达成率权重`/
`达成率均值`），列名与聚合口径逐字照块的固定列常量抄，不是凭印象写的。

刻意不登记三个，理由写在 `溯源.py` 的 `不登记理由` 里：

- `质量体检` —— 输出是四元组、不是一张表（详见下节）
- `多窗口` —— 列数由实参形状决定，本工具不做依赖实参形状的模板
- `邻期关联` —— 窗口函数还是子查询会改变「膨胀在哪一侧」的呈现，属口径判断

**已知失真**（写在全文注释里）：CTE 里的 `ORDER BY` 在多数引擎不保证传到外层，而块是
保证行序的。要拿到与极快一致的行序，得把 `ORDER BY` 再写一遍在最外层。另外
`基线偏离`/`窗间对比` 用了 `FULL OUTER JOIN`（`对齐` 那列是三态，内连接会把「只有一侧
有」的组悄悄丢掉），SQLite / MySQL 要改写成两个 `LEFT JOIN` 的 `UNION`。

## 三、数据质量检查：复用 `质量体检`，不新增块

`DQ-fact_orders-体检-方案.json`，两步，`jk 块 跑` 实测输出：

```
[1850, {'actual_delivery_date': 57, 'delay_days': 57}, 0, {'model_id': 0, 'customer_id': 0}]
```

即 1850 行 / 两列各 57 个空值 / 主键 `order_id` 零重复 / 两条外键零孤儿，与
ADR-40 §4.3 §4.5 冻结的数字一致。

一个写方案时会踩的点：`外键检查` 的 `目标表` 要的是**已载入的表**、不是路径字符串，
而共享常量在合成源码里排在**所有步骤调用之前**，所以它不能引用 `赵果N`。这里的解法是
在共享常量里就地 `读表(…)` 载入维表——`读表` 已由步骤 1 的 `表载入` 块导入，那时已经
可用。

`DQ-等价SQL对照表.txt` 是「未登记」路径的实证：覆盖 1/2 步，`体检` 那一步给出理由而不
给 SQL，也因此不出 `WITH` 全文。**这不是缺口，是设计**——四项计数互不同构（两项还是
字典），硬塞成一条 `SELECT` 会把它伪装成一行数据。

## 四、为什么这两样是工具而不是块

它吃的是**方案 + 块元数据 + 合成源码**，三样都是合成层的东西；制造域的块只吃「行的
列表」。做成块就得让块反过来 import 编译它自己的工具链，层次是倒的；块库也会为一个
不产表的东西多一个成员，连带 G12 / G20 / G22 全要跟着动。所以块库仍是 145 个块、
制造域仍是 33 个，本项一个门禁数字都没碰。
