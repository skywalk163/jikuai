# W178 · 运营日报样例（赛题交付物第 ⑤ 项）

赛题说明书「七、交付物」第 5 条要的是「**至少 1 份自动生成的运营日报样例**」。
这一项在 v0.28.0 立项时的 WBS W178 清单里**漏列了**——W178 原文只列了 Demo /
技术方案说明 / 口径审计说明 / 数据质量报告 / 溯源样例 / 评测报表 / 演示视频，
比对 docx 原文才发现少这一项。本目录就是补上的那一份，**不是**从别处改名来的。

## 这份日报是什么

- 输入：`日报-2026-06-15-全厂-方案.json`（10 步，实参全手写）
- 合成：`jk 块 组` → `日报-2026-06-15-全厂.jk`（**零 `?` 占位**）
- 运行：`jk 块 跑 --json` → `日报-2026-06-15-全厂-结果.txt`（四段逐字照抄 stdout）

「自动生成」指的是**日报正文由确定性合成 + 执行产生，全程不过任何模型**：换一个
报表日只改共享常量 `赵报日` 一处，四段口径与链路一个字都不用动。

## 四段与口径

| 段 | 块（导出名） | 源表 · 日期列 | 口径 |
| --- | --- | --- | --- |
| 一·产量 | `产量汇总`（计产） | fact_production_actual · `production_date` | `actual_quantity` **求和** |
| 二·停线 | `停线汇总表`（计停表） | 同上（复用同一次载入 + 同一个单日窗） | 合计/均值/最长；**均值分母 = 计入记录数**，0 分钟进分母、空值排除 |
| 三·缺陷 | `缺陷汇总`（计陷） | fact_quality_defects · `defect_date` | `defect_count` **求和**（≠ 记录条数） |
| 四·能耗 | `能耗汇总`（计耗） | fact_energy_usage · `usage_date` | 电/水/气**绝对量求和** |

三张表三个日期列名互不相同（`production_date` / `defect_date` / `usage_date`），
全部显式写进参数——这类「列名看着差不多、实际不同」的地方**不能交给自动推参**，
猜错了不报错，只是筛出空表。

单日窗靠 `窗口`（截期）的**闭区间**性质实现：`起 = 止 = 赵报日`。没有为了「按日」
另造一个块。

## 这一天的实测数字（2026-06-15，八条产线）

- 产量榜首 **L002 = 162**，末位 L007 = 89。
- 停线榜首也是 **L002 = 97 分钟**（均值 48.5，最长 59）。
- 缺陷榜首还是 **L002 = 17**，是第二名（L001/L006 各 5）的三倍多。
- 电耗榜首却是 **L008 = 35066.5**，L002 = 31327.6 排第二。

**「产量最高的线同时停线最久、缺陷最多」这三榜同头是这一天的真实结构**，不是巧合被
挑出来的——它正是运营日报值得每天出的理由。而第四段榜首换了人（L008），是
ADR-40 §5.5「绝对量 vs 比率排名」那处分歧点在日报里的具体样子：**电耗绝对量高**
可能只是因为那条线开得多，要判「费不费电」得看单车电耗，那是另一个口径、另一侧块。

## 日报刻意不做的三件事

1. **不出达成率**。要联 `fact_production_plan`，且撞 ADR-40 §5.1（加权 vs 均值）。
   日报是给一群人看的同一张纸，不该替读者选那一侧。
2. **不出缺陷率**。要联产量表，且 §5.3 已判定「先算行级比率再平均」那一侧**本身是错的**
   （2026-06 实测：先汇总后相除 0.050550 vs 行级比率平均 0.032218，差 **57%**）。
   日报出绝对量，比率交给专门问一句的人。
3. **不出单车电耗**。同时撞 §5.2（现成列 vs 重算）与 §5.5（绝对量 vs 比率排名）。

三条都是同一个原则：**日报可以少说，不可以替读者做口径选择**。要那些数就单独问一句，
让 `分歧告警` 逼着显式选一侧（`jk 块 规划` 的规则 3）。

## 复现

```bash
jk 块 组 赛题/chatbi/产出/W178-运营日报/日报-2026-06-15-全厂-方案.json
jk 块 跑 赛题/chatbi/产出/W178-运营日报/日报-2026-06-15-全厂-方案.json --json
```

换日期：把方案里 `赵报日` 改成别的日子即可，其余不动。
