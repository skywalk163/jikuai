做不到的写清为什么不做**。评审要的技术方案、口径审计、评测分档报表也在文末给全。

生成日期 2026-08-21，对应 commit `58fbf44`（v0.28.0 W164-W177）。块库 **145 块**
（制造域 33 块），全链路合成 + 执行**不调用任何 LLM**。

## 一、六项交付物逐条对账

赛题原文（`赛题/chatbi/赛题说明_参赛者版.docx` 第七节）：

- **① 可运行 Demo 或在线访问链接**
  → **本机可跑的安全演示端点**：`tools/web/demo_server.py`（ADR-42，W164）。
  只收方案不收源码、Bearer 鉴权、块白名单（制造域）、subprocess 隔离执行带超时、
  数据集只读，四道闸由门禁 G24 静态 + 行为两套断言守。
  → **「在线访问链接」一栏如实空着**：本轮**不做公网部署**（不写反代 / HTTPS / 限流）。
  拿本机端点冒充在线链接，安全化就白做了——这是本轮立项拍板的反向度量（WBS §五.5）。

- **② 代码仓库 / 部署包 + README / 部署说明**
  → 仓库即本项目；`README.md`（人读总览）、`AGENTS.md`（机读调用手册）、
  `docs/协议-三通道.md`（协议正本）。三包发行元数据由 G21 守。

- **③ 技术方案说明（架构 / 数据导入 / 语义层 / 查询链路 / 模型或 Agent 设计）**
  → 见本文件 **第三节** + 三份 ADR 正本（架构见文末索引）。

- **④ ≥5 个公开问题的系统回答（截图或导出结果）**
  → `产出/Q_PUB_001..010`（**10 道**，各含 `-方案.json` / `.jk` / `-结果.txt`），
  超出「至少 5 个」一倍。逐题结果对照见 `产出/README.md` §二。

- **⑤ ≥1 份自动生成的运营日报样例**
  → `产出/W178-运营日报/`（本轮补——立项 WBS 漏列了这一项，比对 docx 原文才发现）。
  一份四段（产量 / 停线 / 缺陷 / 能耗）全厂日报，`jk 块 组`/`跑` 双通、零 `?` 占位。

- **⑥ ≤5 分钟演示视频**
  → **需人做，本轮不产**（要人操作录屏）。产出物与复现命令都已就绪，录制即可。

**加分项**（docx 第四节可选）也都落了：数据质量检查（`产出/W173-溯源与数据质量/`）、
角色视角（`产出/W172-角色视角/`）、趋势判断（`制造/趋势判定` 块 + W172 R1）。

## 三、技术方案说明（架构一页纸）

**一句话**：极快是一个**确定性代码合成层**——从 145 块的库里选几个块，用模板 +
类型图推导拼出粘合代码并执行，整条链路不调用 LLM。Chat BI 场景里，读到问句的 agent
（人或模型）只做「选块 + 填参数」，输出 token 从 O(代码行数) 降到 O(块数)。

- **数据导入**：`表载入`（读表）块直接吃赛题 CSV，`_推断` 按列做类型推断，`_校验表头`
  比对表头。数据集九张表（3 维 + 6 事实）不进 wheel/sdist（ADR-40 §7）。
- **语义层**：`制造/语义层.json`，42 条业务词 → `{表, 字段, 口径说明, 时间锚点}`。
  它**不是块**（无 `块.json`、不进块索引），只在 `jk 块 规划` 组装上下文包时被读。
- **查询链路**：`jk 块 规划`（离线出上下文包，候选带 `输入槽`/`输出类型`）→ agent 回填
  `{需求, 方案, 模型}` → `jk 块 组`（合成 `.jk` 源码）→ `jk 块 跑`（执行出结果）。
  回填被 `planner.py` 五条硬规则挡（参数齐全 / 块名逐字取自包 / 分歧点显式选一侧 /
  信封形状合法 / 严格模式类型闸）。
- **Agent 设计**：检索层**永不拒答**（无分数阈值，永远返回 top-K）；判断权交给读候选的
  agent；规划器层有一个**词表覆盖**拒答判据，拦「整类能力不在库里」，拦不住「口径差一档」。
  口径差一档由 `分歧告警` 逼显式选一侧。详见 ADR-41 与 AGENTS.md 第四节。
- **正本**：数据模型 + 口径 = ADR-40；规划器 / NL 层 = ADR-41；演示端点安全 = ADR-42。

## 四、口径审计说明（五处分歧点，正本 ADR-40 §5）

制造域有五处「两种口径都算得出、但结果不同、必须显式选一侧」的分歧点。系统**不替读者选**，
而是在 `jk 块 规划` 出 `分歧告警`、在块 `描述` 里互相点名，选错一侧代码照跑、结果是错的。

- **§5.1 平均达成率**：`达成率权重`（达权，产量加权）vs `达成率均值`（达均，行级等权）。
  本数据集上两者差**仅万分之几**（L003 白班 0.969950 vs 0.970209），拿它讲口径分歧很弱。
- **§5.2 单车电耗**：`单车电耗现成`（车耗现，用现成列）vs `单车电耗重算`（车耗算，联产量表重算）。
  本数据集逐行等值（数据生成时口径一致），重算块的价值在「换真实数据会分叉、届时块已在」。
- **§5.3 缺陷率**：`缺陷率` 单块（先汇总后相除）+ 描述显式否决另一侧 + 姊妹块 `缺陷汇总`。
  **另一侧「先算行级比率再平均」本身是错的**——两表粒度不同（缺陷 2992 行 vs 产量 2896 行）。
  实测 2026-06：先汇总后相除 **0.050550** vs 行级比率平均 **0.032218**，**差 57%**。
  **这处 57% 是五处里口径分歧最有说服力的一个**，讲审计就用它。
- **§5.4 时序对比参照系**：`窗间对比`（窗比，跟平级窗口比，出绝对量差值）vs
  `基线偏离`（基偏，跟自身长期基线比，出升幅比率）。互换不报错只给错数（拿上一窗当基线会把
  一次性波动当常态）。Q_PUB_004「哪条产线异常升高」的正确答案是 `基线偏离` → **L002 +25.89%**。
- **§5.5 绝对量 vs 比率排名**：`能耗汇总`（计耗，绝对量）vs `单车电耗现成`（车耗现，比率）。
  「哪条线电耗最高」和「哪条线单车电耗最高」不是一个问题——L006 平时就是耗电大户、不代表费电。
  这处用「与」形触发词组（排名/取最值语境才成立），实测 15 份录像误报 0 份。

**运营日报（交付物 ⑤）正是这套口径纪律的现场演示**：它四段只出绝对量（产量/停线/缺陷/能耗
求和），**刻意不出达成率、缺陷率、单车电耗**——这三样各撞 §5.1 / §5.3 / §5.2+§5.5，
日报不替一屋子读者做口径选择，要那些数就单独问一句、让分歧告警逼着选一侧。

## 五、评测数字分档报表（2026-08-21 现跑，块库 145）

**两套纪律**：正例分**调优 / 留出**两集（只有留出也涨才算真涨）；负例分**远离 / 近边缘**
两档（只报远离档等于自欺）。留出集只当裁判，绝不看其 miss 明细调参。

### 5.1 检索层（`bench_chatbi.py`，top=5）— 永不拒答，判断权在读候选的 agent

- 正例·调优 15 条：块覆盖率 19.6% / Recall@1 20.0% / Recall@3 53.3% / MRR 0.3744
- 正例·留出 5 条：块覆盖率 19.2% / Recall@1 60.0% / Recall@3 80.0% / MRR 0.7000
- 负例·远离 10 条：拒答率 **0.0%**（无阈值设计）/ 制造块占位率 20.0%
- 负例·近边缘 8 条：拒答率 **0.0%** / 兄弟块诱骗率 **62.5%**

### 5.2 规划器层（`bench_planner.py`，K=8）— 上下文包能否装下正确方案 + 词表拒答

- 正例·调优 15 条：期望块覆盖 84.7% / 完整命中 53.3% / **白名单可承载 60.0%**
- 正例·留出 5 条：期望块覆盖 79.0% / 完整命中 60.0% / **白名单可承载 60.0%**
- 负例·远离 10 条：规划器层拒答 **50.0%**（拒下 5）← 同档检索层 0.0%
- 负例·近边缘 8 条：规划器层拒答 **0.0%** / 兄弟块诱骗率 **75.0%** ← 同档检索层 62.5%
- 录像回放 18 份：判定一致率 **100.0%** / 通过 14（组跑全通 14）/ 拒下 4 / 组失败 0

> 近边缘诱骗率规划器层（75.0%）**高于**检索层（62.5%）：W174 语义层直取旁路为让白名单
> 装下正确方案（承载 0.0%→60.0%）多注入了骨架块，其中 `停线汇总` 多骗到一条。这是那次
> 改动写在明面上的代价（ADR-41 §9），不是笔误。

### 5.3 自动拒答可行性（`bench_retrieval_reject.py`）— 为什么检索层不设阈值

四轮实测已证伪所有基于分数的自动拒答方案。远离档最优信号「绝对分」AUC 调优 0.881 /
**留出仅 0.773**；近边缘档最优信号「突出度」AUC 调优 0.676 / **留出仅 0.532**（≈随机）。
交叉检验（阈值选自远离·调优，套到近边缘·留出）多数信号**净收益为负或近零**。
结论：能拒掉多数无覆盖需求的阈值会同时误杀大量真命中，所以检索层**不设阈值、不替 agent 把关**。
